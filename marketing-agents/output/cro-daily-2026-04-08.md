## Page CRO Review — `/dashboard` (web/src/app/dashboard/page.tsx)

### Critical (P0)

1. **Sign-up upsell disappears after search results load.** The logged-out banner ("Track prices and get alerts when they drop!") only appears *above* the search form. Once a user searches and scrolls through results, the upsell is gone — precisely when intent is highest. A user who just found a $200 Taylor Swift ticket and wants to track it has zero in-context signup nudge below the results.
   - **Fix:** Add a contextual signup CTA card after the 3rd EventCard in results for logged-out users. Copy: "Like what you see? **Create a free account** to track prices and get alerts when they drop." Button: "Sign Up Free →"
   - **Expected lift:** 15–30% increase in `/dashboard` → registration conversion (industry pattern: inline contextual CTAs at point-of-intent outperform banners by 2–4×).

2. **No target price input on watchlist add.** `EventCard.tsx` adds to watchlist without a `target_price`. The entire price alert system (`price_alerts` table, the cron job comparison, the drip emails about "your target price") depends on this value. Users add events, never set a target, and **never receive alerts**. The core product loop is broken.
   - **Fix:** When a logged-in user clicks the watchlist button, show a quick inline modal: "What price would you like to pay? $[input]" with "Track at any price" as a secondary option. Pre-fill with 10% below current lowest price.
   - **Impact:** This isn't a conversion optimization — it's a feature gap that silently breaks the alert funnel.

3. **Default city hardcoded to "Orlando"** (same issue flagged on `/compare` 04-07). Every non-Orlando user's first interaction is deleting text and retyping. That's friction at the first touch.
   - **Fix:** Empty input with placeholder "Enter your city" + optional geolocation detect. Or remember last searched city in `localStorage`.

### Medium (P1)

4. **Empty state copy is generic.** "Find your next event" conveys no value. Replace with: "Search & compare prices across Ticketmaster, SeatGeek, and 60+ sites — free." This establishes the multi-source comparison value prop immediately.

5. **Watchlist button (👁️) has no visible label.** Users don't know what the eye icon does. On mobile, the `title="Sign up to track prices"` tooltip is invisible (no hover). After adding, it shows "✓" with no confirmation text.
   - **Fix:** Add "Track" label next to the icon, or replace with a bookmark/bell icon which has stronger "save/alert" mental model. Show a brief toast: "Added to your watchlist! Set a target price to get alerts."

6. **Search button is not full-width on mobile.** The button sits in its own row, right-aligned via `flex justify-end`. On small screens users must scroll past 4 form fields to find a narrow button. Make it `w-full` below `sm` breakpoint.

7. **No "Clear filters" button.** Once a user searches with date constraints and gets no results, the only way to broaden the search is manually clearing each field. Add a "Reset" link next to the Search button.

### Low (P2)

8. **Error state shows raw API text.** "Search failed. Please try again." is the fallback, but if the API returns a specific message it's shown verbatim. Wrap in user-friendly copy.

9. **Blog tip cards below results** are a nice retention touch but have no CTA beyond article links. Add "Get tips like these in your inbox →" linking to newsletter signup.

### Recommended A/B test #2
- **Hypothesis:** Adding an inline signup CTA card after the 3rd search result for logged-out users will lift registration rate from `/dashboard` by ≥25%.
- **Variant A (control):** Current — top banner only.
- **Variant B:** Top banner + inline CTA card after 3rd result.
- **Primary metric:** Registration completions from `/dashboard` sessions.
- **Duration:** 2 weeks at current traffic.

## Form CRO — User Registration (web/src/app/register/page.tsx)

### Current State
- 3 fields: Email, Password, Confirm Password
- CTA: "Create account"
- Subtext: "Start tracking ticket prices today"
- Footer: "Already have an account? Sign in"

### Issues Found

**P0 — No value reinforcement on the page.**
The registration page is a bare white card with form fields and nothing else. The user clicked "Sign Up" from a page full of events and value props — then landed on a blank form. Momentum dies.
- **Fix:** Add a left-side panel (desktop) or top section (mobile) with 3 benefit bullets:
  - "Track any event across 60+ ticket sites"
  - "Get instant alerts when prices drop"
  - "Free forever — no credit card needed"
- Include a small social proof line: "Join 50,000+ smart ticket buyers" (matches homepage stat).

**P1 — No password visibility toggle.**
Users typing into `type="password"` with no show/hide control are prone to typos, especially on mobile. This causes failed registrations and form re-submission.
- **Fix:** Add a 👁️ toggle on both password fields.

**P1 — No inline validation.**
All validation happens on submit. User types a 5-character password, fills confirm, submits, gets an error, has to re-enter both fields.
- **Fix:** Show inline "Password must be 8+ characters" as user types. Show "Passwords match ✓" when confirm field matches.

**P1 — "Already registered" error not differentiated.**
If a user submits with an existing email, `err.message` shows as a red error. But "already registered" isn't an error — it's a redirect opportunity.
- **Fix:** Detect "already registered" in the error response and show: "Looks like you already have an account! [Sign in instead →](/login)"

**P2 — No social login option.**
3 fields (email + password + confirm) is above-average friction for a free tool. A "Continue with Google" button would capture users who won't create another email/password combo.
- **Priority:** P2 because it requires OAuth setup, but the conversion lift (typically 20–40% for free products) justifies the investment.

**P2 — No terms/privacy links.**
Missing "By registering, you agree to our Terms of Service and Privacy Policy" near submit button. Not a conversion blocker per se, but its absence can erode trust for privacy-conscious users. Also a legal baseline.
