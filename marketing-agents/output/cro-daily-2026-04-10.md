## Page CRO Review — `/venues/[slug]` (Venue Pages)

Venue pages are **the #1 SEO entry point** — users searching "MSG ticket prices" or "Crypto.com Arena events" land here. These pages must convert cold organic traffic, yet they have the weakest conversion architecture of any page on the site.

### Critical (P0)

1. **No newsletter/alert signup anywhere on venue pages.** The homepage has `<NewsletterSignup>` in two places. Venue pages — where first-time organic visitors land — have zero. A user who isn't ready to create an account has no low-commitment way to stay connected.
   - **Fix:** Add `<NewsletterSignup source="venue-[slug]" variant="card" />` below the event list. Customize heading: "Get price alerts for [venue name] events." This captures email from users who aren't ready to register but want to stay in the loop.
   - **Expected lift:** 5–10% email capture rate on venue pages (industry benchmark for contextual, relevant signup prompts on content pages).

2. **"Track Price" buttons drop all context when routing to `/register`.** A user sees "Magic vs Celtics — $45" and clicks "Track Price." They land on a bare registration form that says "Create your account." The event name, price, and venue are all gone. Momentum dies.
   - **Fix:** Pass event context via query params: `/register?event=magic-vs-celtics&venue=kia-center&price=45`. On the registration page, show: "You're about to track **Magic vs Celtics** at Kia Center (from $45). Create your free account to get alerts when the price drops."
   - **Impact:** This bridges the intent gap between "I want this specific deal" and "fill out this generic form." Expected 20–40% lift on venue→register conversion.

3. **No social proof on venue pages.** Homepage shows "50K+ events tracked, $127 avg savings, 24 cities" plus 3 testimonials. Venue pages — the pages that need to earn trust from cold traffic — show none. First-time visitors from Google have zero reason to trust this site.
   - **Fix:** Add a compact social proof bar below the hero: "Tracking prices across 60+ ticket sites • Avg savings: $127 • Free forever." Reuse the existing `StatsBar` pattern from the homepage.

### Medium (P1)

4. **Sidebar CTA copy is generic.** "Start Free" tells the user nothing about what they'll get. On a venue page for MSG, the CTA should feel venue-specific.
   - **Fix:** Dynamic CTA copy: "Get Price Alerts for Madison Square Garden" with subtext "We'll notify you when prices drop for events here."
   - File: `web/src/app/venues/[slug]/page.tsx` lines 261–274.

5. **No `PriceTrendIndicator` on event rows.** The component exists in `web/src/components/PriceTrendIndicator.tsx` but venue pages don't use it. Showing "↓ 12% this week" next to a price creates urgency and demonstrates the product's value (live price tracking) without requiring signup.
   - **Fix:** Add `<PriceTrendIndicator>` to each event row where trend data is available.

6. **Empty event state is a dead end.** When a venue has no upcoming events, users see plain text: "Sign up to get notified when events are announced." This is a high-intent segment (they searched for a specific venue) served the weakest possible CTA.
   - **Fix:** Replace with a prominent card: "No upcoming events at [Venue] yet. **Get notified first when events go on sale.**" + email input field (no account needed). Button: "Notify Me". This captures leads without requiring full registration.

7. **Seating tier section shows multipliers (`~3x base`) instead of dollar estimates.** Without an anchor price, "3x base" is meaningless. The `VenuePriceDisplay` component exists but isn't used here.
   - **Fix:** If any event has price data, anchor tier estimates to real prices: "Upper Level: $45–$80 • Lower Level: $120–$200." If no events exist, show "Prices typically range from $X–$Y" based on historical data.

8. **Mobile: sidebar CTAs are buried below event list.** On mobile, the sidebar collapses below the main content. A user scrolling through 15 events never sees "Start Free" or the seating guide.
   - **Fix:** Add a sticky bottom bar on mobile for logged-out users: "[Track Prices — Free] [Sign Up]". Appears after scrolling past the first 3 events.

### Low (P2)

9. **Breadcrumb city link has a `.replace(' ', '-')` bug** (line 135). Only replaces the first space in multi-word city names. Won't break current data (no two-space cities in the dataset) but is a latent bug.

10. **No "Share this venue" or social links.** Venue pages are shareable content — users send arena guides to friends planning group outings. A share button creates viral distribution at zero cost.

### Recommended A/B Test #3
- **Hypothesis:** Venue-specific CTA copy ("Get Price Alerts for [Venue]") will outperform generic copy ("Start Free") by ≥30% click-through rate.
- **Variant A (control):** "Start Free" button with "Track Ticket Prices" headline.
- **Variant B:** "Get Price Alerts for [Venue Name]" button with "Never miss a deal at [Venue]" headline.
- **Primary metric:** CTA click-through rate on venue pages.
- **Duration:** 2 weeks at current traffic.

## Form CRO — Newsletter Signup, Footer Variant (web/src/components/NewsletterSignup.tsx)

### Current State
- 1 field: Email
- CTA: `'...'` (three dots during loading), "Subscribe" otherwise
- Placement: Footer only (+ card variant on homepage)
- Source tracking: ✅ passes `source` prop to API

### Issues Found

**P1 — Loading state shows `'...'` instead of clear feedback.**
The `footer` variant uses `'...'` as the loading indicator while `card` and `inline` variants say `"Subscribing..."`. Three dots are ambiguous — is it loading? Broken? The inconsistency between variants suggests this was an oversight.
- **Fix:** Change `'...'` to `"Subscribing..."` across all variants, or better: show a spinner icon.
- File: `web/src/components/NewsletterSignup.tsx`, footer variant submit button text.

**P1 — No post-subscribe upsell to create an account.**
After submitting, the form shows a success message and stops. A user who just gave their email is the warmest lead on the site — they've already shown trust. The next logical step is: "Want even more control? **Create a free account** to track specific events and set price alerts."
- **Fix:** Replace the static success message with a two-step acknowledgment:
  1. "You're in! Check your inbox for a welcome email."
  2. Below it: "Want to track specific events? [Create Free Account →](/register)" — framed as an upgrade, not a demand.
- **Expected lift:** 10–15% of newsletter subscribers convert to registered accounts (industry benchmark for warm-lead upsell).

**P1 — Newsletter signup is absent from 90% of pages.**
It only appears on the homepage (2 placements) and the footer. Venue pages, city pages, event detail pages, the World Cup landing page, and blog posts have zero newsletter touchpoints. These are all high-intent pages where a "get alerts for this [venue/event/topic]" prompt would capture leads.
- **Fix:** Add `<NewsletterSignup>` to venue pages, city pages, and blog posts with contextual `source` props for attribution.

**P2 — Error messages may surface raw API text.**
The component shows `data.error` directly. If the API returns a technical string (e.g., database error text), the user sees it.
- **Fix:** Wrap in user-friendly fallback: `data.error || "Something went wrong. Please try again."` For the specific "already subscribed" case, show: "You're already subscribed! [Check your account →](/login)."

**P2 — No email format validation before submit.**
Relies entirely on `type="email"` browser validation. Some mobile browsers are lenient with this. Adding a simple regex check before submit would catch obvious typos (missing `@`, `.com` → `.con`).
