## Page CRO Review — Blog Conversion Path (`/blog` + `/blog/[slug]`)

The blog exists as a content-to-conversion engine: attract organic search traffic, build trust, then funnel readers into newsletter subscribers or registered users. Today's audit reveals the blog-to-newsletter funnel is **completely broken** due to routing errors, and the blog-to-registration path has significant friction.

### Critical (P0) — Broken Conversion Funnels

1. **Blog page "Subscribe Now" button routes to homepage, not newsletter signup.**
   - **File:** `web/src/app/blog/page.tsx` ~line 169
   - **Problem:** The bottom-of-page CTA uses `<Link href="/">Subscribe Now</Link>`. A reader who finishes browsing blog posts and clicks "Subscribe Now" gets dumped on the homepage with no signup prompt. They must then scroll past the hero, how-it-works, features, testimonials, and stats sections to find the newsletter form near the bottom.
   - **Impact:** This is the primary newsletter conversion point for blog readers — it's 100% broken. Every blog visitor who wanted to subscribe bounced.
   - **Fix:** Replace the `<Link>` with the actual `<NewsletterSignup source="blog" variant="card" />` component. This renders an email input directly on the page — zero navigation required.

2. **Blog post sidebar "Subscribe" button also routes to homepage.**
   - **File:** `web/src/app/blog/[slug]/page.tsx` ~line 195
   - **Problem:** The sidebar "Get More Tips" box uses `<Link href="/">Subscribe</Link>`. Same broken routing as the blog index page.
   - **Impact:** In-article conversion from engaged readers (the highest-intent blog audience) is broken.
   - **Fix:** Replace with `<NewsletterSignup source="blog-post" variant="inline" />`. The inline variant fits the sidebar width naturally.

3. **Blog newsletter CTAs don't pass `source` tracking.**
   - Even once fixed, the current implementation uses plain links — no `source` parameter reaches the newsletter API. Without source attribution, we can't measure blog-specific conversion rates.
   - **Fix:** Using the `<NewsletterSignup>` component (which accepts a `source` prop) solves this automatically.

### High (P1) — Missing Conversion Elements

4. **No newsletter signup on individual blog posts (in-content).**
   - Blog posts are 800–2000 words. The only conversion options are: (a) broken sidebar subscribe link, (b) bottom "Create Free Account" CTA. There's no mid-article or end-of-article newsletter capture.
   - **Fix:** Add `<NewsletterSignup source="blog-post-[slug]" variant="card" />` after the article content, before the "Ready to Find Cheap Tickets?" box. This captures readers at peak engagement (just finished reading).

5. **Blog CTA competes with itself: newsletter vs. registration.**
   - Blog post pages have two CTAs: "Create Free Account" (after article) and "Subscribe" (sidebar). These serve different conversion goals but don't explain the difference. A user choosing between them may choose neither.
   - **Fix:** Sequence them. After article: newsletter signup ("Get weekly tips like this"). Below that: registration CTA ("Ready to track prices? Create a free account"). This creates a low-commitment → high-commitment funnel.

6. **No social proof on blog pages.**
   - Blog pages show zero credibility signals. No subscriber count, no user count, no platform stats. First-time organic visitors from Google have no reason to trust the newsletter.
   - **Fix:** Add micro-copy to the newsletter CTA: "Join 50K+ fans who save on tickets" (or actual subscriber count if we grow past the current 3).

7. **Blog featured posts section doesn't highlight recency.**
   - The 3 featured posts span Jan 1 – Apr 7, 2026. The most recent post (World Cup pricing article, Apr 7) is shown alongside 3-month-old posts. Fresh content signals an active, trustworthy site.
   - **Fix:** Add a "New" badge on posts published within the last 14 days.

### Medium (P2) — UX Friction

8. **Blog page has no search or filter.**
   - 10+ blog posts with no way to find relevant content. Users interested in NBA tickets must scroll past concert guides and World Cup articles.
   - **Fix:** Add category filter tabs (Guides, Tips, Sports, Concerts) above the post grid.

9. **Blog post read time is shown but not in a time-to-value context.**
   - "8 min read" is informational but doesn't create urgency or value framing.
   - **Fix:** Rephrase to "8 min read — could save you $200" (or similar value anchor from article content).

10. **Blog post sidebar "Quick Links" go to generic pages.**
    - Links to "Search Events", "Compare Prices", "Create Account" — none are contextual to the article being read.
    - **Fix:** Replace with article-specific CTAs. For the NBA tickets post: "Search NBA Tickets" → `/dashboard?keyword=nba`. For the concert post: "Compare Concert Prices" → `/dashboard?keyword=concerts`.

## Form CRO — User Registration (`/register`)

### Current State
3-field form: Email, Password, Confirm Password. Clean card layout, center-aligned.

### Form Scorecard

| Criterion                  | Score | Notes                                    |
|---------------------------|-------|------------------------------------------|
| Field count               | ⚠️ 3  | Email + Password + Confirm — confirm adds friction |
| CTA copy                  | ❌    | "Create Account" — generic, not action-oriented |
| Value reinforcement       | ⚠️    | "Start tracking ticket prices today" — weak value prop |
| Error handling            | ✅    | Clear error display, loading state on button |
| Inline validation         | ❌    | No real-time field validation — errors only on submit |
| Password visibility       | ❌    | No show/hide toggle — increases error rate |
| Social proof              | ❌    | Zero — no user count, no testimonials, no trust signals |
| Mobile UX                 | ✅    | Centered card, responsive width |
| Post-signup flow          | ⚠️    | Redirects to dashboard — no onboarding, no newsletter offer |
| Source attribution        | ❌    | No `?source=` param handling for utm tracking |

### Recommendations

1. **Remove "Confirm Password" field.**
   - Industry best practice (Baymard Institute): confirm password fields increase form abandonment by 10–15% without meaningfully reducing password errors. Modern registration uses a single password field with a visibility toggle.
   - **Fix:** Remove `confirmPassword` field. Add a show/hide password toggle icon.

2. **Change CTA from "Create Account" to benefit-oriented copy.**
   - Options: "Start Saving on Tickets", "Track Prices Free", "Get Price Alerts"
   - The CTA should answer "what do I get?" not "what am I doing?"

3. **Add value reinforcement below the form.**
   - Current subtext "Start tracking ticket prices today" is generic.
   - **Fix:** Add 3 bullet points:
     - "Compare prices across Ticketmaster, SeatGeek & StubHub"
     - "Get alerts when ticket prices drop"
     - "Free forever — no credit card required"

4. **Add social proof.**
   - **Fix:** Add "Join 51 fans already tracking prices" below the form title (update dynamically from admin stats).

5. **Handle `?source=` and `?email=` query parameters.**
   - When users arrive from World Cup pages or newsletter, pre-fill the email field and show contextual copy: "Almost there — create your account to track World Cup ticket prices."
   - This connects the registration form to upstream conversion flows.
