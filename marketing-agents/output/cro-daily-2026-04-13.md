These are 2-line fixes. Every day they stay broken, every blog visitor who wants to subscribe hits a dead end.

### New Observation: Blog Post End-of-Article CTA Mismatch

The blog post CTA box ("Ready to Find Cheap Tickets?") pushes registration (`/register`), but the typical blog reader journey is:
- Google search → blog article → *trust building* → low-commitment action (newsletter) → return visit → registration

Pushing registration at the end of a first-visit blog read skips the trust-building step. The newsletter signup should come first, with registration as a secondary CTA below it.

**Recommended article-end CTA sequence:**
1. `<NewsletterSignup source="blog-post" variant="card" />` — "Get weekly tips like this"
2. Existing registration CTA — "Ready to track prices? Create a free account"

## Form CRO — Watchlist Add (EventCard Component)

**File:** `web/src/components/EventCard.tsx`

The watchlist add is not a traditional form — it's a single button click (`handleAddToWatchlist`). This is the core conversion action for engaged users: they found an event and want to track it.

### Current Flow

1. User clicks eye icon button on EventCard
2. **If logged in:** Immediately adds to watchlist with event name, date, venue, city. No target price. No confirmation UI beyond `✓`.
3. **If not logged in:** Shows overlay prompt → "Sign Up Free" link to `/register` or "Maybe Later" dismiss.

### Form Scorecard

| Criterion                    | Score | Notes                                                |
|-----------------------------|-------|------------------------------------------------------|
| Friction level              | ✅    | One-click add for logged-in users — excellent         |
| Target price capture        | ❌    | **Critical miss.** No target price field. This breaks the entire price alert system. |
| Button affordance           | ❌    | Eye icon (👁️) is ambiguous — could mean "view" or "preview." Not clearly "track" or "watchlist" |
| Button label (accessibility)| ❌    | No visible text label — icon-only button with title attribute only |
| Success feedback            | ⚠️    | Checkmark (✓) appears but no message explaining what happened or next steps |
| Post-add upsell             | ❌    | No prompt to set a target price, no "we'll alert you when prices drop" confirmation |
| Logged-out experience       | ⚠️    | Overlay is decent but "Sign Up Free" goes to generic `/register` — no event context preserved |
| Error handling              | ✅    | Error message shown below button                      |
| Mobile UX                   | ⚠️    | Button is small (icon-only), may be hard to tap on mobile |

### Recommendations (Priority Order)

#### P0: Add target price capture

This is the single most impactful CRO fix on the platform. The price alert system (`activeAlerts: 0`, `triggeredAlerts: 0`) is completely unused because no user ever gets asked for a target price.

**Current:** Click → add to watchlist (no target price) → done
**Proposed:** Click → mini-modal with pre-filled event info + target price input → "Track & Alert Me" button

The modal should:
- Pre-fill event name, date, venue (read-only context)
- Show current price range if available (e.g., "$89 – $340")
- Have a single input: "Alert me when price drops below $___" with a suggested default (e.g., 20% below current min)
- CTA: "Track This Event" (not "Submit")
- Secondary link: "Skip — just track without a price alert"

This single change activates the entire price alert funnel that currently generates zero engagement.

#### P1: Fix button affordance

Replace the eye icon with a more recognizable action:
- **Icon:** Bell (🔔) or bookmark — universally recognized as "track" or "save"
- **Label:** On desktop, show "Track" text next to icon. On mobile, icon-only is acceptable if it's a bell.
- Current: `👁️` → Proposed: `🔔 Track` (desktop) / `🔔` (mobile)

#### P1: Add success confirmation with next step

After adding to watchlist, replace the checkmark with a brief confirmation:
```
✓ Tracking [Event Name]
Set a price alert → [link to watchlist page or inline target price input]
```

This creates a secondary conversion moment — the user just committed to tracking, so asking for a target price when motivation is highest has the best conversion rate.

#### P2: Preserve event context for logged-out users

When a logged-out user clicks Track → signs up, the event context is lost. After registration, they land on an empty dashboard and must re-search.

**Fix:** Change the "Sign Up Free" link from `/register` to `/register?event=${event.id}&redirect=/dashboard&action=watchlist`. After registration, auto-add the event and redirect to watchlist.

#### P2: Increase mobile tap target

The track button is `px-4 py-2` — approximately 32px tall. Apple's Human Interface Guidelines recommend 44px minimum tap target.

**Fix:** Increase to `px-4 py-3` or use `min-h-[44px]` for the button.
