## Thursday Focus: Event Detail Page (`/event/[id]`) — First Review

This is the highest-intent page on the site: a user has either (a) come from their watchlist to check a tracked event, or (b) been linked via an external source (SEO, email drip, social). The page renders buy-now/wait/hold recommendations, a 30-day price chart, and a history table — everything needed to make a purchase decision. It is also auth-gated, has no way to buy, and has no way out except "Back to Watchlist."

### P0 — Hard login redirect kills inbound SEO/email traffic
**File:** `web/src/app/event/[id]/page.tsx:67-71`
```tsx
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```
Same pattern as Compare. If Agent 4 (SEO) or Agent 2 (Email) ever link directly to `/event/[id]` — e.g., a "prices dropped on this event" email or a shared deal link — the recipient gets a silent redirect to a login page with no context. The entire cold-traffic funnel for this page is broken.

**Fix:** Show the recommendation card, price chart, and history to anonymous users, but gate the price-alert setup and tracking behind a soft overlay: "Create a free account to track this event and get price drop alerts."
**Effort:** 2–3 hours | **Impact:** Unlocks event detail as a shareable/linkable asset. Estimated +20–35% signup conversion from any campaign that routes through event detail.

### P0 — No purchase CTA on the "Good Time to Buy" recommendation
**File:** `web/src/components/BuyRecommendation.tsx:53-115`
The component tells users "Good Time to Buy" with high confidence and then... does nothing. No link to Ticketmaster, no link to SeatGeek, no "Compare Prices Now" button. The entire page is an analytical recommendation with no action path. A user who sees "buy now" has to leave the page, go back to the dashboard, re-search the event, and click buy from a different card.

**Fix:** Add a CTA row below the reason text with the relevant source links (pass `ticketmasterUrl` and `seatgeekUrl` props through from `loadEventData`). When action is `buy_now`, surface both as primary buttons. When action is `wait` or `hold`, surface as secondary links plus a "Set/update target price" primary.
**Effort:** 2 hours (requires backend change to return purchase URLs from the recommendation endpoint, or a separate fetch) | **Impact:** Estimated +25–40% click-through to affiliate links from this page — the current CTR is effectively 0 because no CTA exists.

**Fix:** Add a "Compare all sources for this event →" link above the price chart that deep-links to `/compare` prefilled with the event name.

## Form Friction Check: Watchlist Add Flow

**Today's form:** Watchlist add button inside `EventCard.tsx` (lines 159-171)

### Critical recommendation: Inline target-price capture

The current flow is:
1. Click 👁️ on card (adds to watchlist with no target)
2. Nothing happens — user doesn't know the alert rules
3. Later, user must navigate to... (nowhere, actually — target price is not editable anywhere in the current UI)

This means the headline feature — "alerts when your target is hit" — has a dead entry path. Users who add an event to watchlist never set a target, so the `isAtTarget` badge on the watchlist page never fires for them.

**Proposed flow:**
1. Click "Track" → button expands into a small inline widget: `[Target price $___] [Track]`
2. Default the input to `priceRanges.min * 0.85` (15% below current) as a suggestion
3. "Track" submits both the watchlist add + the target in one call
4. Success state: "Tracking! We'll email you when it drops below $X"

This ties the add to the alert, which ties the alert to the email, which ties the email to the return visit. Currently that whole chain is broken on add #1.

**Effort:** 2–3 hours | **Impact:** Estimated 3–5x increase in price-alert trigger rate; directly feeds return visits and email engagement.
