## Saturday Focus: `/world-cup-2026` (Main Landing Page)

The main WC landing page received a meaningful update this week: `WorldCupSchedule.tsx` was extracted into a client component that supports *by-date* and *by-round* filtering. That's real functional progress on one of the most strategically important pages on the site. But the page as a whole still has structural conversion problems that are amplified by the fact that **FIFA tickets don't go on sale until late 2025 and the tournament is 14 months away**. This is not a "buy now" page — it is a "be first to know" page, and it is architected as if it were the former.

### P0 — The entire top-of-page CTA path leads to an empty search result

The hero offers two CTAs:
1. **"Search World Cup Tickets"** → `/dashboard?keyword=world+cup+2026`
2. **"View Match Schedule"** → `#schedule` anchor

And the secondary CTA block at page bottom (lines 397–410) offers:
1. **"Create Free Account"** → `/register` (no context)
2. **"Search Tickets Now"** → `/dashboard?keyword=world+cup`

`WorldCupSchedule.tsx:158` per-match CTA:
- **"Find Tickets"** → `/dashboard?keyword=world+cup+{city}`

**The problem:** FIFA itself hasn't started official ticket sales. The Ticketmaster/SeatGeek APIs will return zero or low-relevance results for "world cup 2026" keyword searches today, in April 2026 — because actual match ticket inventory is still being allocated from the FIFA portal (the page itself admits this in Tip #1 at line 358–362). Users who click "Search World Cup Tickets" will hit the dashboard, see an empty results grid or unrelated matches ("World Cup of Darts," etc.), and bounce.

**Fix:** Replace the primary hero CTA with an email-capture form instead of a search link. The page copy at line 177 already says *"Set your target price and we'll notify you when tickets drop"* — lean into that. Specifically:

```tsx
// Replace the two hero buttons with:
<NewsletterSignup source="wc-2026-hero" variant="inline" />
// Copy: "Get notified when World Cup tickets drop — and when prices change."
// Subtext: "Free. One email per match you follow. No account required."
```

Keep "View Match Schedule" as a secondary anchor link. Remove "Search World Cup Tickets" from the hero entirely — it is currently the most prominent CTA on the page and it actively disappoints traffic.

**Effort:** 45 min. **Impact:** Replaces a 0%-converting CTA with a 5–12% capture form on what is likely the highest-intent organic traffic on the site. This is the single highest-leverage change in today's report.

### P0 — Per-match "Find Tickets" buttons currently deliver nothing

`WorldCupSchedule.tsx:157–162` — every row in the schedule links to `/dashboard?keyword=world+cup+{city}`. Same problem as P0 #1, but at scale: 104 matches × multiple clicks = a steady stream of dead-end traffic. Worse, the TBD placeholders in the knockout rounds (line 144: "TBD vs TBD") send users hunting for tickets to matches whose teams haven't been determined.

**Fix:** Replace the `Find Tickets` button with a per-match **"Notify me"** button that opens a lightweight email-capture modal:
> "We'll email you when tickets for **{team1} vs {team2}** at **{venue}** go on sale and when the price changes."

POST to `/api/newsletter/subscribe` with `source=wc-2026-match-{matchNumber}` and persist the match ID so we can target later.

**Effort:** 3–4 hrs (modal + API source plumbing). **Impact:** Converts 104 dead-end click targets into 104 email-capture funnels. Each knockout match especially (lines 129–133 — Semi-Final, Final, etc.) is *itself* a premium email-capture event.

### P0 — No newsletter capture anywhere on the page

Same structural gap as venue pages (Day 8 open). A page that generates organic SEO traffic for "World Cup 2026 tickets" has three CTAs, all pointing to either a dead-end dashboard search or a context-free `/register`. There is zero low-commitment conversion path.

**Fix:** Add `<NewsletterSignup source="wc-2026" variant="card" />` in **two** locations:
1. After the "Why Compare Prices" block, before "Featured Teams" (around line 189).
2. Replacing or augmenting the bottom CTA section (line 389) with the card variant.

Copy tuned to the context:
- Heading: "Be first to know when World Cup tickets go on sale"
- Subhead: "Official FIFA sales start late 2025. Resale prices move daily. One email when things change — no account needed."

**Effort:** 20 min. **Impact:** Estimated 8–15% email capture on page. This is cold SEO traffic — email is the right commitment level.

### P0 — Schedule truncation hides 72 of 104 matches

`WorldCupSchedule.tsx:115` — `filteredMatches.slice(0, 20)`. In "By Round" view with "Group Stage" selected (72 matches), users see 20 and a footnote telling them to switch to date view. In "All Rounds," they see 20 of 104.

This is both a UX problem (the page tells users it has 104 matches, then shows 20 with no pagination) and a conversion problem: the truncated rows include the most high-intent, premium matches (Semi-Finals and the Final). If a user specifically wants to find the Final and we hide it behind a "switch to date view" instruction, the funnel is broken before it starts.

**Fix:**
- Option A (low effort): Pin the Final, both Semi-Finals, and all Quarter-Finals to the top of any filtered view, then show 20. The premium matches are visible regardless of filter.
- Option B (better): Implement "Load more" pagination. Render 20 initially, `{filteredMatches.length - 20} more matches →`. Infinite scroll optional.
- Option C (best, with P0 #2): Each match row is a "Notify me" capture surface, so truncation also becomes a capture-funnel truncation. Option B becomes mandatory.

**Effort:** 1 hr (A), 2 hrs (B). **Impact:** Unblocks intent for the single most searched matches on the page (Final, Semis).

### P1 — "Featured Teams" block is static decoration

`page.tsx:191–212`. 32 team cards (by inference from worldcup.ts), each with a flag and group letter, *no interaction*. A user who is a USA fan, Brazil fan, or Argentina fan cannot do anything with this block. The data is already structured; the opportunity is obvious.

**Fix:** Make each team card a "Follow {team}" CTA that triggers a lightweight capture: email input + "We'll notify you about {team}'s matches." POST to `/api/newsletter/subscribe` with `source=wc-2026-team-{team-slug}` (and if the user is logged in, also call `/api/favorites` with `{favorite_type: 'team', favorite_name: team.name}` — the table exists per CLAUDE.md).

**Effort:** 2 hrs. **Impact:** 32 segmented conversion surfaces. Team-specific capture is the most targetable email list we can build — USA fans, Mexico fans, etc. are discrete marketing segments with very different intent profiles.

### P1 — Secondary "CTA Section" is redundant and generic

Lines 389–412. Two buttons ("Create Free Account" / "Search Tickets Now") with copy that could appear on any page of the site. If we implement P0 #1 and P0 #3, this block is redundant and should be removed or replaced with the card newsletter form + a single contextual "Create your free WC tracker" link.

**Effort:** 15 min. **Impact:** Reduces decision fatigue at bottom of page.

### P1 — No trust/social proof

Same as venue pages (Day 8 open). A page that asks users to enter their email or create an account has no indicators that the brand is legitimate. Add a one-line proof bar below the stats block (around line 155):

> "Tracking 60+ ticket sources • Used by 12,000+ fans (replace with real count) • Free forever"

Numbers must be honest — if we don't have real counts, ship copy that's still honest ("New: 104 matches, all 16 stadiums covered").

**Effort:** 20 min. **Impact:** Trust precedes conversion.

### P2 — "Register with FIFA" tip link is missing

`page.tsx:359–362` tells users to register on FIFA.com but doesn't link there. An outbound link to `https://www.fifa.com/` (with `rel="noopener noreferrer"` and `target="_blank"`) turns a passive instruction into an action. This is not a direct conversion for us but it's a trust signal — we're telling users the honest path to official tickets, which reinforces the "we're on your side" positioning.

**Fix:** Wrap "FIFA.com" in the tip copy as a real `<a>` link.
**Effort:** 2 min.

### P2 — Schema.org `AggregateOffer` hardcodes lowPrice: $50

`page.tsx:74`. The offer schema declares `"lowPrice": "50"` for the entire tournament. When actual WC ticket prices surface (likely $150–$400+ minimum), this schema becomes a lie that Google will penalize. Either remove `AggregateOffer` entirely (legitimate — we aren't selling) or wire it to real data later.

**Fix (short-term):** Remove the offers block from the schema. The `SportsEvent` schema without offers is cleaner and more honest.

**Effort:** 5 min. **Impact:** Avoids future SEO penalty when the lie becomes provable.

## Form Friction Check: **Price Alert Setup** — the form doesn't exist

**This is today's critical finding.** The schedule said to review the "Price alert setup" form. There is no such form.

### Evidence

- **Database**: `watchlist.target_price` column exists (confirmed in CLAUDE.md).
- **API**: `POST /api/watchlist` accepts `targetPrice` as a number (`web/src/lib/api.ts:169`).
- **Display**: `web/src/app/watchlist/page.tsx:222` renders `item.target_price` if present.
- **Recommendation engine**: `/api/prices/recommendation` checks `currentPrice <= targetPrice` (CLAUDE.md — "Target hit" → "buy_now").
- **Marketing copy**: Every page advertises "price alerts." Homepage, venue pages, WC page (4 places on that one page alone), blog posts, drip emails #2 and #3, all social posts, all ads.

### The hole

- **`EventCard.tsx:43–49`** — the only "add to watchlist" surface in the app. It calls `api.addToWatchlist({ eventId, eventName, eventDate, venue, city })`. **`targetPrice` is never passed.**
- **`watchlist/page.tsx`** — displays `target_price` but has no input to set or edit it. There is no pencil icon, no modal, no `PATCH` endpoint wired up on the frontend.
- **`event/[id]/page.tsx`** — shows `BuyRecommendation` with `recommendation.stats.targetPrice`, but no form to set or change that target.
- **No `/price-alert/new` page exists.** No modal component. No inline form. Nothing.

### Consequence

Every marketing campaign Agent 1 (content), Agent 2 (email), Agent 4 (SEO), and Agent 5 (ads) is running uses "set a target price and we'll alert you when it drops" as a core value prop. A user who registers, adds an event to their watchlist, and expects to receive a price drop alert **never gets one**, because:
1. They have no way to set a target price.
2. The cron job correctly checks `currentPrice <= targetPrice` — but with `target_price = NULL`, that branch never fires.
3. The only remaining trigger is the *default fallback* ("hold") — no email is sent for a hold.

**This is the single biggest unfulfilled promise on the site.** Users are registering in good faith, expecting a core feature, and the feature is architecturally absent.

### Fix — minimum viable form

Two surfaces need it, in priority order:

**1. Watchlist row: inline target-price editor.**
In `web/src/app/watchlist/page.tsx`, replace the static `Target: $X` display (line 222) with an inline-editable field:

```tsx
<div className="flex items-center gap-2 text-sm text-gray-600">
  <span>Target:</span>
  {editingTargetId === item.id ? (
    <>
      <input
        type="number"
        inputMode="decimal"
        defaultValue={item.target_price ?? ''}
        placeholder="Your target price"
        className="w-24 px-2 py-1 border rounded text-gray-900"
        onKeyDown={(e) => { if (e.key === 'Enter') saveTarget(item.id, e.currentTarget.value); }}
        onBlur={(e) => saveTarget(item.id, e.target.value)}
        autoFocus
      />
      <button onClick={() => setEditingTargetId(null)} className="text-xs text-gray-500">Cancel</button>
    </>
  ) : (
    <button onClick={() => setEditingTargetId(item.id)} className="font-semibold text-green-600 hover:underline">
      {item.target_price ? `$${item.target_price}` : 'Set target →'}
    </button>
  )}
</div>
```

Backend: add `PATCH /api/watchlist/:id` that accepts `{ targetPrice }` and updates the row. If this endpoint already exists, wire the UI; if not, it's a 15-minute addition to `index.js`.

**2. Add-to-watchlist flow: inline capture at the moment of intent.**
In `EventCard.tsx`, when the user clicks the 👁️ button, instead of silently calling the API, flip the button region into a mini-form:

```tsx
<input
  type="number"
  inputMode="decimal"
  placeholder={`Alert me under $${event.priceRanges?.min ?? 50}`}
  className="w-full px-3 py-2 border rounded"
/>
<button onClick={submitWithTarget}>Set alert</button>
<button onClick={submitWithoutTarget} className="text-xs text-gray-500">Just track, no target</button>
```

If the event has `priceRanges.min`, pre-fill the placeholder to `min * 0.9` as a sensible default. Default target = "10% below current min" is a well-studied anchor that converts significantly better than an empty field.

**Effort (both surfaces):** 4–6 hrs including backend `PATCH` route. **Impact:** Unblocks the single most-marketed feature on the site. Every drip email, every ad, every blog post that says "set a target price" becomes honest.
