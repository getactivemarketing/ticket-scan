## Sunday Focus: Newsletter / Blog Conversion Path

**Files inspected:**
- `web/src/app/blog/page.tsx` (181 lines — server component, blog index)
- `web/src/app/blog/[slug]/page.tsx` (240 lines — server component, blog post template, 21 posts × this template)
- `web/src/data/blog.ts` (21 posts, 5 featured)
- `web/src/components/NewsletterSignup.tsx` (157 lines — `card` variant 113–155)
- `web/src/components/Footer.tsx` (118 lines — confirmed no NewsletterSignup)
- `web/src/app/page.tsx:285,314` (the only two NewsletterSignup mounts on the entire site)

### The premise

The blog is, in pure cold-traffic SEO terms, the **second-largest top-of-funnel surface** on the site — 21 indexed posts, each ranking for a long-tail query, each pulling search traffic with **content intent** (not transactional intent). A user who lands on `/blog/world-cup-2026-final-ticket-10990-dynamic-pricing` is, by definition, *not* yet ready to register an account, set up a price alert, or compare prices on a specific match. They are reading. The right ask for a content-intent reader is **email**, not signup.

The blog conversion path today asks for the wrong thing in the wrong way. Every blog conversion CTA is one of:
- A **link to the homepage** to subscribe (`/blog` index "Subscribe Now" → `/`, sidebar "Subscribe" → `/`).
- A **link to the registration page** (`/blog/[slug]` bottom CTA → `/register`).

There is no inline email form on any of the 22 blog surfaces. A user who finishes reading a 4-minute blog post about FIFA's $10,990 final ticket — i.e., the high-intent moment where they've just been educated, primed for trust, and given a reason to come back — is sent **off the page they're on** to a different page to fill in a form. Bounce rates on link-out CTAs are catastrophically worse than on inline forms; industry norms put inline-form conversion at 4–8× link-out conversion for content-intent traffic.

The exit problem compounds: the link sends the user to the homepage, where the homepage's primary product is *search*, not *newsletter signup*. A user who clicks "Subscribe" on a blog post and lands on `/` has to re-orient themselves to the homepage layout, find the newsletter card (lines 285–305 of `app/page.tsx`, well below the fold), scroll to it, and complete a form there. Most won't.

There are **two positives** worth naming:
1. **Blog post template `generateMetadata`** ✓ (`[slug]/page.tsx:16–48`) — proper SEO setup, OG/Twitter cards, article-type structured data with author + dates + image.
2. **Article-grade JSON-LD** (`[slug]/page.tsx:85–117`) — `Article` + `BreadcrumbList` `@graph`. Truthful, useful, no aspirational claims.

These positives mean the blog is *being indexed and ranked.* The acquisition surface is operational. The conversion machinery is what's broken.

Below are six new findings on the blog/newsletter path, plus one regression-class restatement of the still-unresolved homepage card form audit.

A user reading a Taylor Swift / concert tips article should see venue links for the relevant tour. The blog post template already has access to `post.tags` and `post.category`. The links could be derived from a simple tag-to-route map.

**Fix (45 min):** Make Quick Links contextual to the article. Sketch:

```tsx
// In data/blog.ts or a new helper:
function getContextualLinks(post: BlogPost): { label: string; href: string }[] {
  const links: { label: string; href: string }[] = [];

  if (post.tags.some(t => t.toLowerCase().includes('world cup'))) {
    links.push(
      { label: 'World Cup 2026 Hub', href: '/world-cup-2026' },
      { label: 'MetLife Stadium Guide', href: '/world-cup-2026/metlife-stadium' },
    );
  }
  // tag-to-venue mapping (e.g., 'msg', 'lakers', 'ucla') → /venues/...
  // tag-to-city mapping (e.g., 'orlando', 'nyc') → /tickets/[slug]
  // tag-to-category (e.g., 'concerts', 'sports') → /tickets/[slug]

  // Fallback (only if no contextual links matched):

    links.push(
      { label: 'Compare Ticket Prices', href: '/compare' },
      { label: 'Search Events', href: '/dashboard' },

  // Always include: register link (last)
  links.push({ label: 'Track Prices Free', href: `/register?source=blog-quicklinks-${post.slug}&returnTo=/blog/${post.slug}` });

  return links;
}
```

Render those links in the sidebar instead of the hardcoded three.

**Effort:** 45 min (helper + tag mapping + render). **Impact:** Converts a generic-link surface into a contextual-link surface. Per-link CTR ~2–4× when topical. Surfaces deeper SEO real estate (venue + WC pages) to readers who arrived via blog SEO — internal-link equity that Agent 4 has been requesting for weeks.
