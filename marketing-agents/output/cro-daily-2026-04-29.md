## Wednesday Focus: Dashboard / Search (`/dashboard`)

**File inspected:** `web/src/app/dashboard/page.tsx` (215 lines, client component, `'use client'`).

### The premise

`/dashboard` is the platform's **single-source search surface** — the place a user lands when they click "Find Events" / "Search" / the Navbar primary CTA / the homepage hero "Find your event" button (when `HomeHeroButtons` is mounted, which it isn't yet — see Mon's audit). Compared to `/compare`, the dashboard is the **lower-intent surface**: users browse, they don't commit. Compared to event-detail, the dashboard is the **higher-volume surface**: every search either ends here (zero-result), continues here (results page), or fans out to Buy Tickets / Watchlist add / Compare.

This makes the dashboard the funnel's **fan-out hub**. Every CRO investment here multiplies across every downstream surface — and every CRO failure here forecloses every downstream conversion.

Today's audit reveals: the dashboard is **functional engineering wrapped in a flat unconverting shell.** The search works. The result rendering works. The EventCard renders correctly. But:

- The default city is hard-coded to **Orlando**, which silently penalizes 99% of US traffic (every cold visitor outside Florida sees Orlando results until they manually clear and retype their own city).
- The **zero-result state** is a polite text apology — no reset, no "popular events," no "search nearby cities," no email capture, no fallback CTA.
- The page **looks identical to a logged-in user vs. an anonymous user** below the sign-up banner — no recent searches, no "events you're tracking," no continued-session affordances.
- The "Sign Up Free" banner above search is **decoupled from the user's actual search intent**: it pitches "save events to your watchlist" as if the user has none in mind, while the user is *literally typing the event they want to track* one row below.
- Every external "Buy Tickets" link on every EventCard fires **zero analytics events** (same finding as yesterday's compare-buy click P0, now applies on the volume-leader surface too).
- The signup link on the banner has **no `?from=dashboard&returnTo=/dashboard` param** — a user who clicks Sign Up Free, registers, and lands back on the homepage loses every search input they just typed.

Below: 4 carry-over findings (Day 8) and **8 new P0/P1/P2 findings** identified in today's review.

### P0 (Day 8 — unchanged) — No URL state encoding. Searches are not shareable; refresh discards inputs.

`dashboard/page.tsx:27–34` (`city`, `keyword`, `startDate`, `endDate`, `events`, `searched` — all `useState`, none mirrored to URL).

A user runs a search, finds an interesting event, copies the URL → recipient lands on `https://www.ticketscan.io/dashboard` and sees Orlando default state. Same finding pattern as yesterday's compare-page URL-state finding (Day 0 → Day 1) and the homepage findings (Day 2). On `/dashboard`, the impact is amplified because **search results are inherently shareable** — the platform's whole organic-share moment ("look at this Magic game") leaks here.

**Fix (1–2 hrs, bundle with `/compare` URL-state work):**

```tsx
// On mount, hydrate from URL params:
const searchParams = useSearchParams();
const [city, setCity] = useState(searchParams.get('city') || '');
const [keyword, setKeyword] = useState(searchParams.get('keyword') || '');
const [startDate, setStartDate] = useState(searchParams.get('start') || '');
const [endDate, setEndDate] = useState(searchParams.get('end') || '');

// On submit, push to URL (no scroll):
router.push(
  `/dashboard?${new URLSearchParams({ city, keyword, start: startDate, end: endDate }).toString()}`,
  { scroll: false }
);

// Auto-fire search if hydrated from URL:
useEffect(() => {
  if (searchParams.get('city') || searchParams.get('keyword')) {
    handleSearch(new Event('submit') as unknown as React.FormEvent);
  }
}, []); // mount-only
```

**Effort:** 1–2 hrs (1 hr if `/compare` URL-state ships first and pattern is reused). **Impact:** Searches become shareable + back-button-recoverable + ad-creative-deep-linkable. Estimated +3–8% on cold-visit-from-share-link conversion.

### P1 (new) — `<input id="city">` and `<input id="keyword">` lack `autoComplete` attributes. Mobile users get no autofill assistance.

`dashboard/page.tsx:87–94` (city) and `100–107` (keyword):


`type="search"` on the keyword field also enables the Enter-to-submit affordance and the in-input clear-X button on most browsers.

#### 3. No background-click dismiss

**Effort:** 5 min. **Impact:** Standard modal UX. Marginal.

**Effort:** 5 min. **Impact:** Visibility into the conversion rate at the platform's highest-intent intercept. Compounds with all other dataLayer pushes.

#### 5. Sign Up Free link has no `?returnTo=/dashboard&intent=watchlist&event_id=...` param

`EventCard.tsx:90`:

**Effort:** 5 min for the link change; ~30 min for the post-register auto-add (part of the Day-8 register cluster). **Impact:** Closes the "click track → register → forget what they wanted to track" gap.

"Maybe Later" is the standard low-friction dismiss copy, but it concedes the registration goal. A more value-aware dismissal acknowledges that the user wants to continue browsing without forcing register-or-leave.

**Fix (1 min):** `'Keep browsing'` or `'Not now'` (less concessive than "Maybe Later," more honest than "Cancel").

**Effort:** 1 min. **Impact:** Marginal copy quality. Low priority in the cluster.
