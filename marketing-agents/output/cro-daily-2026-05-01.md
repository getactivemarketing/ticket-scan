**What's actually present:** There is no standalone watchlist-add *modal*. The closest surfaces in the codebase are:

So the "form" doesn't exist. The audit becomes: **what would the form look like, and what's the cheapest path to it?**

### Findings on the watchlist-add surface (6 new today)

#### P0 (NEW) — `addToWatchlist` accepts `targetPrice?: number` but no UI ever sets it; **100% of watchlist rows enter with `target_price = NULL`**

`api.ts:169` declares `targetPrice?: number`. `EventCard.tsx:43–49` calls it with **only** `{ eventId, eventName, eventDate, venue, city }`. There is no other caller of `addToWatchlist` in the codebase (grep-confirmed). Therefore every row in the `watchlist` table has `target_price = NULL`.

The downstream consequences are visible in code:
- The price-tracking cron (`index.js`, every 4 hours per CLAUDE.md) compares `currentPrice <= targetPrice` to decide whether to send a price-drop alert. With `target_price = NULL`, the comparison is always falsy and **no price-drop alerts are ever sent.**
- `BuyRecommendation.tsx:120–124` only renders "Your target price: $X" when `stats.targetPrice` is truthy. With `target_price = NULL`, the recommendation panel always renders without this anchor.
- `watchlist/page.tsx:106–107` filters "target hit" items by `parseFloat(item.current_min_price) <= parseFloat(item.target_price)`. With `target_price = NULL`, the filter is always false and the "target hit" view is empty.

The platform's **single advertised differentiator** ("we email you when prices hit your target") is broken because no UI ever captures the target. **Day 13 unresolved** for the parent finding (no target-price UI exists anywhere) — and today's API-level inspection promotes it from "missing feature" to "schema field with no input wired to it."

**Cheapest path to a fix (1.5 hrs total):**

1. **Add a 1-input modal** triggered by the `👁️` button when the user is logged in (~45 min). UI:

```
Track Knicks vs Celtics — Apr 28
Notify me when tickets drop to:  $[ 80 ]
                                  Lowest in last 30 days: $97
[ Track this event ]   [ Skip — track without alert ]
```

The default value: the 30-day low (or `currentPrice * 0.85` if no history). Two CTAs so the user can opt out of the alert and just track.

2. **Pass `targetPrice` through `addToWatchlist`** (~5 min — the type already exists).

3. **Backend confirms the column accepts the value** (per CLAUDE.md schema, the `watchlist` table already has `target_price` — assumed wired; verify with a quick `INSERT` test).

4. **`dataLayer.push({ event: 'watchlist_added', event_id, has_target_price: !!targetPrice, target_price, source })`** on success (~5 min). Plus the inverse `watchlist_skip_target` if the user uses the secondary CTA.

5. **Apply the same modal to all add-to-watchlist surfaces** once it exists: `/dashboard` EventCard, `/compare` "Track" CTA (when soft-gated), `/event/[id]` "Set target" CTA (P0 from yesterday), `/venues/[slug]` future inline + Track button (P0 from today's Option 1 refactor).

**Total effort:** 1.5 hrs. **Impact:** Activates the platform's core differentiator for the first time. Without this, every other CRO ship on the roadmap still produces watchlist rows that can never trigger the price-drop email — meaning the entire alert/drip product remains structurally invisible to users.

#### P0 (NEW) — `EventCard.tsx:159–170` is an emoji-only button (`👁️`) with no visible label

Day 13 carry-over, re-affirmed today by re-reading the component. The eye emoji is the only visible affordance. The `title` attribute (line 162) provides a tooltip ("Track this event") on desktop hover only. **Mobile users see an unlabeled button.** Touchscreens don't surface `title` tooltips.

**Fix (10 min):** Replace `{added ? '✓' : adding ? '...' : '👁️'}` with `<span className="hidden sm:inline">👁️</span> <span className="sm:hidden">+ Track</span>` — emoji on desktop (where it's visually recognized as a "watch" icon), explicit text on mobile. Or better, drop the emoji entirely and use "+ Track" / "✓ Tracking" / "Adding..." for all viewports.

#### P0 (NEW) — Sign-up prompt overlay (`EventCard.tsx:80–104`) loses event context the moment the user clicks "Sign Up Free"

The overlay shows the user "Track This Event" — but the `<Link href="/register">` (line 90) does not include `?returnTo=` or any event identifier. So when the user lands on `/register` and completes the form, they:
1. See a 3-field generic signup form (no message-match to the event they just intended to track).
2. After submission, are redirected to the post-register default landing — **not back to the event card they were tracking.** The intent is destroyed.

**Fix (15 min):** Update the overlay's `<Link>` to include `returnTo`, `eventId`, `eventName`, and `source` (composes with the `RegisterCTA` component proposed above for the venue page):

```tsx
<RegisterCTA
  source="event-card-overlay"
  eventContext={{ id: event.id, name: event.name, date: event.date, venue: event.venue, city: event.city }}
  intent="watchlist"
  variant="primary"
>
  Sign Up Free
</RegisterCTA>
```

Plus: the register page must (a) honor `returnTo`, (b) auto-add the event to watchlist on first login when `intent=watchlist` and `eventId` are present, and (c) render a contextual headline ("Almost there — we'll start tracking **Knicks vs Celtics** for you").

**Effort:** 15 min for the overlay link + the work already specified in the register form audit (Day 10) for `returnTo` honoring + intent handling.

#### P1 (NEW) — Anonymous "Maybe Later" button is a dead-end with no email capture

`EventCard.tsx:95–101`: clicking "Maybe Later" closes the overlay. No newsletter inline-capture. No "want a weekly summary of price drops?" alternative. No nothing — just hides the modal.

This is the highest-intent dead-end on the dashboard surface. The user clicked the watch button (high intent), declined registration, and the platform has nothing to offer. Even just an inline 1-line newsletter capture ("Get the weekly price-drop digest — no signup required") would convert some fraction of these users.

**Fix (20 min):** Replace "Maybe Later" with a small inline `<NewsletterSignup variant="inline" source={\`event-card-decline:${event.id}\`} />`. If the user submits, fire `dataLayer.push({ event: 'newsletter_subscribed', source, decline_reason: 'event-card-watchlist-decline' })`. If the user clicks the close icon (`×`), the overlay closes — same dead-end as today, but at least one path now converts.

#### P1 (NEW) — Add-success state has no follow-up; user is stuck staring at a `✓`

`EventCard.tsx:50` sets `setAdded(true)` and the button becomes a `✓` permanently. No "Set target price" follow-up modal, no "View your watchlist →" link, no "Tracking 1 event — track another?" cross-sell. The single most successful interaction on the page (a logged-in user actually adding to watchlist) terminates without driving the user to any next step.

**Fix (25 min):** On `setAdded(true)`, render an inline mini-CTA below the card buttons:

```tsx
{added && (
  <div className="mt-3 flex items-center justify-between gap-3 text-sm bg-green-50 border border-green-200 rounded-lg p-3">
    <span className="text-green-800">Tracking — we'll email when prices change.</span>
    <Link href={`/event/${event.id}`} className="text-green-700 hover:text-green-900 font-medium whitespace-nowrap">
      Set target →
    </Link>
  </div>
)}
```

Once the target-price modal (P0 above) ships, this can become a direct trigger of that modal instead of a navigation to `/event/[id]`.

**Impact:** Converts the success state from a terminal `✓` into a funnel into the price-alert feature.

#### P2 (NEW) — Error state (`EventCard.tsx:172`) is text-only with no retry affordance

`{error && <p className="text-red-500 text-sm mt-2">{error}</p>}` displays the error message but provides no way to retry without re-clicking the (now disabled) button. For network errors specifically (the most common case), a "Retry" link would close the loop.

**Fix (10 min):** When `error` is set, also reset `adding` and `added` to false, and render the message as `<button onClick={handleAddToWatchlist}>{error} — Retry</button>`.
