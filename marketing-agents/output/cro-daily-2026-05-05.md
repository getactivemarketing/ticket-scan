#### P0 (NEW today) — The compare page's own internal CTAs perpetuate the same omission: when an unauthenticated user is bounced to `/login`, the redirect does not include a `?returnTo=/compare?city=…&keyword=…&start=…&end=…`. `compare/page.tsx:87–90`:

```tsx

  router.push('/login');
  return null;
}
```

The redirect drops every search input the user typed (or the absence of input on a fresh load). When they finally register and log in, `/login` `router.push('/dashboard')` (per the existing login flow) lands them on the dashboard — **a different page from the one they were trying to reach.** A user who arrived via the homepage hero "Compare Prices →" CTA, hit the gate, registered, and landed on the dashboard now has to manually navigate back to `/compare` and retype.

This is a **silent funnel leak** at the only step where TicketScan currently has any registration capture. The user who completed the highest-friction action on the platform (creating an account) lands on the wrong page.

**Fix (10 min, can ship in tandem with the soft-gate work):**

```tsx
// compare/page.tsx — replace the redirect:
if (!authLoading && !user) {
  const params = new URLSearchParams();
  if (city.trim()) params.set('city', city);
  if (keyword.trim()) params.set('keyword', keyword);
  if (startDate) params.set('start', startDate);
  if (endDate) params.set('end', endDate);
  const returnPath = `/compare${params.toString() ? `?${params}` : ''}`;
  router.push(`/login?returnTo=${encodeURIComponent(returnPath)}`);
  return null;
}
```

And on the login page (out of scope today, but flagging for the dev backlog): respect `returnTo` after successful auth.

**Effort:** 10 min on `compare/page.tsx` + ~10 min on `/login` to honor `returnTo`. Estimated +30–50% activation-completion rate among gate-bounced-then-converted users (currently a near-zero cohort because the gate kills almost all of them, but the math becomes load-bearing once the soft gate ships).

## Form Rotation: Watchlist Add Modal (Day 17 — Asymmetric: only the rejection path has a modal)

`EventCard.tsx:159–170`:

```tsx
  onClick={handleAddToWatchlist}
```

The icon-only `👁️` button — emoji-only label, no visible text — is the entire UI for adding to watchlist. The user clicks; `handleAddToWatchlist` fires; the API call lands; the icon flips to `✓`. **No modal. No price target capture. No confirmation. No alert preferences.**

`EventCard.tsx:43–49`:

```tsx
await api.addToWatchlist({
  eventId: event.id,
  eventName: event.name,
  eventDate: event.date,
```

**The payload omits `targetPrice` entirely.** Per the schema (`watchlist (..., target_price, ...)` in CLAUDE.md), the column exists. The price recommendation algorithm references it (`if (currentPrice <= targetPrice) return "buy_now"`). **And yet 100% of watchlist rows have `target_price = NULL` because there is no UI to capture it.** This is Day 17 unresolved.

The downstream consequence: the price-tracking cron at `0 */4 * * *` checks 6× daily, fetches new prices, and runs the comparison `if (currentPrice <= targetPrice) ...` against `NULL` for every row. **The product's marquee feature — price-drop alerts — never fires for any user, because there is no price target to compare against.**

This is the **single most expensive product-broken state on the platform.** Every email subject line, every blog post, every WC promise, every venue page CTA, every SEO description references "price drop alerts." Zero have ever fired.

This modal — the only one in the entire watchlist-add flow — is **register-only.** The user has just expressed intent to track an event (the strongest possible commitment signal short of a purchase). The modal responds by demanding an account.

**Findings on this modal:**

1. **The Sign Up Free CTA at line 89–93 omits `?returnTo=` and `?source=`** — the user who registers from this modal lands on `/dashboard` with no association to the event they tried to track. The intent is destroyed.

2. **There is no email-only fallback.** A user not ready to register but willing to leave an email gets nothing. The 4/28 compare-page "Track this event" P0 finding asked for an anonymous-friendly target-price form; this modal is the place that form should mount.

3. **The body copy ("Create a free account to track prices and get alerts when they drop") is functionally a lie** — the alerts can never drop because the watchlist payload doesn't capture a target price. Feature-parity with public-facing copy is broken at the same point the user commits.

4. **"Maybe Later" is a dead-end button.** It dismisses the modal with no alternative path. A user who closes "Maybe Later" returns to the same page with no trace of their attempted intent — no email captured, no event saved to a session-anonymous wishlist, no follow-up.

### Combined fix: the actual Watchlist add modal that should exist

The watchlist add UX needs **one modal that covers both paths.** Today the unauthenticated path has a modal but the authenticated path doesn't; the right pattern is the inverse of today's design — show a modal *always*, capture target-price intent in *both* cases.

**Spec (1.5–2 hrs, single new component):**

`web/src/components/WatchlistAddModal.tsx`:

```tsx
'use client';

import { useState } from 'react';
import Link from 'next/link';
import api from '@/lib/api';

interface Props {
  event: { id: string; name: string; date: string; venue: string; city: string; priceRanges?: { min: number; max: number } | null };
  isLoggedIn: boolean;
  onClose: () => void;
  onAdded: () => void;
}

export default function WatchlistAddModal({ event, isLoggedIn, onClose, onAdded }: Props) {
  const suggestedTarget = event.priceRanges?.min
    ? Math.round(event.priceRanges.min * 0.85)
    : '';
  const [targetPrice, setTargetPrice] = useState<string | number>(suggestedTarget);
  const [email, setEmail] = useState('');
  const [submitting, setSubmitting] = useState(false);
  const [error, setError] = useState('');

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setSubmitting(true);
    setError('');

    try {
      if (isLoggedIn) {
        await api.addToWatchlist({
          eventId: event.id,
          eventName: event.name,
          eventDate: event.date,
          venue: event.venue,
          city: event.city,
          targetPrice: typeof targetPrice === 'string' ? parseFloat(targetPrice) || null : targetPrice,
        });
        if (typeof window !== 'undefined') {
          (window as { dataLayer?: Record<string, unknown>[] }).dataLayer ??= [];
          (window as { dataLayer: Record<string, unknown>[] }).dataLayer.push({
            event: 'watchlist_added',
            event_id: event.id,
            target_price: targetPrice,
            source: 'event-card',
          });
        }
      } else {
        await api.subscribeNewsletterWithIntent({
          email,
          source: 'watchlist-anonymous',
          eventId: event.id,
          eventName: event.name,
          targetPrice: typeof targetPrice === 'string' ? parseFloat(targetPrice) || null : targetPrice,
        });
        if (typeof window !== 'undefined') {
          (window as { dataLayer?: Record<string, unknown>[] }).dataLayer ??= [];
          (window as { dataLayer: Record<string, unknown>[] }).dataLayer.push({
            event: 'watchlist_intent_anonymous',
            event_id: event.id,
            target_price: targetPrice,
            source: 'event-card',
          });
        }
      }
      onAdded();
    } catch (err) {
      setError(err instanceof Error ? err.message : 'Failed to track');
    } finally {
      setSubmitting(false);
    }
  };

  return (
    <div role="dialog" aria-modal="true" aria-labelledby="watchlist-modal-title" className="fixed inset-0 bg-black/60 flex items-center justify-center z-50 p-4">
      <div className="bg-white rounded-2xl max-w-md w-full p-6 shadow-2xl">
        <h3 id="watchlist-modal-title" className="text-xl font-heading font-bold text-navy mb-2">
          Track {event.name}
        </h3>
        <p className="text-gray-500 text-sm mb-4">
          We'll email you when the price drops below your target.
        </p>

        <form onSubmit={handleSubmit} className="space-y-4">
          <label className="block">
            <span className="text-sm font-medium text-gray-700">Notify me when price drops to</span>
            <div className="mt-1 relative">
              <span className="absolute left-3 top-1/2 -translate-y-1/2 text-gray-400">$</span>
              <input
                type="number"
                inputMode="decimal"
                min={1}
                step="1"
                value={targetPrice}
                onChange={(e) => setTargetPrice(e.target.value)}
                placeholder={String(suggestedTarget || 'Your target')}
                className="w-full pl-7 pr-3 py-2 border border-gray-300 rounded-lg focus:ring-2 focus:ring-brand outline-none"
                required
              />
            </div>
            {suggestedTarget !== '' && (
              <span className="text-xs text-gray-400 mt-1 block">
                Suggested: {suggestedTarget} (15% below current low of ${event.priceRanges?.min})
              </span>
            )}
          </label>

          {!isLoggedIn && (
            <label className="block">
              <span className="text-sm font-medium text-gray-700">Email address</span>
              <input
                type="email"
                name="email"
                autoComplete="email"
                inputMode="email"
                value={email}
                onChange={(e) => setEmail(e.target.value)}
                placeholder="you@example.com"
                className="mt-1 w-full px-3 py-2 border border-gray-300 rounded-lg focus:ring-2 focus:ring-brand outline-none"
                required
              />
              <span className="text-xs text-gray-400 mt-1 block">
                We'll only email you for this alert. <Link href="/register" className="text-brand underline">Or create an account</Link> to track multiple events.
              </span>
            </label>
          )}

          {error && (
            <p role="alert" aria-live="assertive" className="text-red-500 text-sm">{error}</p>
          )}

          <div className="flex gap-2 pt-2">
            <button type="button" onClick={onClose} className="flex-1 py-2 px-4 rounded-lg border border-gray-300 text-gray-700 hover:bg-gray-50">
              Cancel
            </button>
            <button type="submit" disabled={submitting} className="flex-1 py-2 px-4 rounded-lg bg-brand hover:bg-brand-dark text-white font-medium disabled:opacity-50">
              {submitting ? 'Setting alert…' : 'Track event'}
            </button>
          </div>
        </form>
      </div>
    </div>
  );
}
```
