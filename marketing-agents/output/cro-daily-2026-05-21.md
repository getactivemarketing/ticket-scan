#### P0 (NEW today) — **`router.push('/login')` is called during render at `:110`, not inside a `useEffect`.**

```tsx
// Redirect if not logged in
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```

In React 19 + Next.js 16 (App Router), navigation side-effects during render are an anti-pattern. They:

1. **Fire on every re-render**: React StrictMode (dev) double-invokes; in production, any state update before the effect resolves can cause repeat pushes. The Next.js router de-dupes destination-equal pushes silently, but the call still costs cycles.
2. **Trigger React's render-phase-side-effect warning** in the development console (silent in prod, but observable in `vercel dev` logs).
3. **Make the redirect not interruptible** — there's no way for a parent component to override or delay it.
4. **Block hydration**: if the server-rendered HTML and the client-rendered first-pass disagree (server doesn't know auth state; client does after localStorage read), the navigation fires before hydration completes, which can cause flash-of-wrong-content.

**The canonical pattern is to move the redirect into a `useEffect`:**

```tsx
useEffect(() => {
  if (!authLoading && !user) {
    const returnTo = encodeURIComponent(`/event/${eventId}`);
    router.push(`/login?returnTo=${returnTo}`);
  }
}, [authLoading, user, eventId, router]);

if (!authLoading && !user) return null; // render-time guard only, no side effect
```

**This same anti-pattern exists at `compare/page.tsx:87–90`** (per yesterday's and Tuesday's audits). The compare-page audit raised C1 (the hard-gate) but did not explicitly call out the render-phase side-effect; today's audit raises it as a structural React 19 hygiene issue across **all hard-gated pages**: `/compare`, `/event/[id]`, and `/watchlist` (which has the same pattern).

**Effort:** 10 min (move all 3 occurrences into `useEffect` with `?returnTo=` preservation, single PR).

**Composes with:** E1 (soft-gate kills the redirect entirely on this page), E2 (returnTo restoration), and C1 (compare-page hard-gate). The 3 redirects are the same shape; one commit fixes all 3.
