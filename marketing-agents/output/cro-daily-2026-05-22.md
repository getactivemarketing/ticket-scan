### Why the absence matters

- **108 watchlist items have `target_price = NULL`** (per W1's structural defect at `EventCard.tsx:43–49`, Day 34). The watchlist-add path on the dashboard collects no target price at the moment of add.
- **`triggeredAlerts: 0` for Day 33.** The cron at `index.js` `0 */4 * * *` fires every 4 hours × 33 days × 108 items = ~64,100 individual price-checks. **The cron logic compares each price against `target_price` per CLAUDE.md's recommendation algorithm — when `target_price` is NULL, the comparison short-circuits and no alert ever fires.** Every one of those 64,100 price-checks has been a wasted DB+API roundtrip relative to the user-facing outcome (zero alerts in 33 days). This is the single most expensive idle-spend on the platform today.
- **11 content-parity lie surfaces** promise "we'll notify you when prices drop": the footer NewsletterSignup at `:48–50`, the venue page CTA box at `:280–282` (today's rotation surface), the dashboard tagline, every drip email (especially Day 7 "How Price Alerts Can Save You Hundreds"), every blog mention of the feature, and the World Cup 2026 landing copy. **None of these surfaces can deliver the alert** until the price-alert form exists end-to-end.

### MVP price-alert form spec (today, paper)

Two contexts where the form should live:

**Context A — Inline disclosure in the watchlist-add flow** (preferred — composes with W1's fix):

```tsx
// At watchlist-add time, after the user clicks "Track" on an EventCard:
// Render a disclosure-style inline form below the row.

<form onSubmit={handleSetAlert} className="mt-2 p-3 bg-blue-50 rounded-lg">
  <label htmlFor={`alert-${event.id}`} className="text-sm text-gray-700 mb-2 block">
    Notify me when price drops below:
  </label>
  <div className="flex gap-2">
    <input
      id={`alert-${event.id}`}
      type="number"
      inputMode="numeric"
      pattern="[0-9]*"
      min="1"
      max={event.minPrice ? event.minPrice - 1 : undefined}
      placeholder={event.minPrice ? `$${Math.floor(event.minPrice * 0.85)}` : '$50'}
      value={targetPrice}
      onChange={e => setTargetPrice(e.target.value)}
      className="flex-1 px-3 py-2 rounded-lg border border-gray-300"
      required
    />
    <button
      type="submit"
      disabled={!targetPrice || (event.minPrice && Number(targetPrice) >= event.minPrice)}
      className="bg-brand text-white px-4 py-2 rounded-lg font-medium disabled:bg-gray-300"
    >
      Set alert
    </button>
  </div>
  {targetPrice && event.minPrice && Number(targetPrice) >= event.minPrice && (
    <p className="text-xs text-red-600 mt-1">
      Target must be below the current price (${event.minPrice}).
    </p>
  )}
  <button
    type="button"
    onClick={skipAlert}
    className="text-xs text-gray-500 underline mt-2"
  >
    Just track it — set alert later
  </button>
</form>
```

### Form-quality checklist (against the FORM-CRO framework described in the task)

| Property | Spec | Why |
|---|---|---|
| Number of fields | 1 visible (`target_price`) + 2 hidden (`event_id`, `source`) | 1-field forms convert ~2× better than 3+ field forms. |
| Field labels | "Notify me when price drops below" + concrete current-price anchor in placeholder | Anchors the user against the live price; teaches the user what number to enter. |
| Submit button copy | "Set alert" (not "Submit", not "Save", not "Subscribe") | Action-oriented + outcome-explicit per the standard CRO playbook. |
| Mobile keyboard | `inputMode="numeric"` + `pattern="[0-9]*"` | Triggers the number pad on mobile, not the full QWERTY. |
| Validation | `min={1}`, `max={event.minPrice - 1}`; inline error when target >= current | Prevents the degenerate UX of "alert fires immediately at add time". |
| Loading feedback | Disable button + change copy to "Setting..." on submit | The current platform-wide pattern (`NewsletterSignup` does this except for the footer-variant `'...'` bug, NS5). |
| Success state | "We'll email you when [eventName] drops below $X. Track another event →" | Captures the high-intent post-success moment; routes back to the dashboard for compounding adds. |
| Skip affordance | "Just track it — set alert later" | Preserves the lower-friction "add to watchlist without an alert" path; targetPrice stays NULL. |
| Telemetry | `dataLayer.push({event: 'alert_set', event_id, target_price, source})` on success | Same shape as NS1's newsletter telemetry. Mandatory for any future A/B test on alert-cohort behavior. |
