## Form Rotation: Watchlist add modal (EventCard) re-audit

The "Watchlist add" path is the single largest **retention** lever on the platform. The cron job documented in CLAUDE.md runs every 4 hours, queries `watchlist`, fetches latest prices, compares to `target_price`, and sends a `price-drop` email when triggered. **The cron has run uninterrupted for 37 days × 6 firings/day × 108 watchlist rows ≈ 23,976 individual cron invocations.** Zero alerts have fired. **The reason is upstream of the cron:** `EventCard.tsx:43–49` never sends `targetPrice` in the `addToWatchlist` payload, so 100% of `watchlist` rows have `target_price = NULL`, so the comparison `currentPrice <= targetPrice` (per the price-recommendation algorithm in CLAUDE.md) is never `true`. The entire retention engine is wired correctly except for **one missing form field on the EventCard** and **one missing target-price modal anywhere on the platform**.

### File inspected today

- `web/src/components/EventCard.tsx` — **176 lines.** Full file read.
- Confirmed: `addToWatchlist` payload at `:43–49` has 5 fields (`eventId`, `eventName`, `eventDate`, `venue`, `city`); no `targetPrice`, no `notes`, no `priority`. The button at `:159–170` is a `👁️` emoji with no text label. The sign-up prompt overlay at `:80–104` covers the entire card, dims the underlying event details, and routes to `/register` with no `?returnTo=` context.
