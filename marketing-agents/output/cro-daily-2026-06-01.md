## Form Friction Check — Newsletter signup (card variant)

The homepage's **primary in-flow capture** is the card variant at `page.tsx:285` (`<NewsletterSignup source="homepage" />`). Reviewed `NewsletterSignup.tsx:114–155`.

| Check | Status | Note |
|-------|--------|------|
| Field count | ✅ 1 (email only) | Optimal — zero unnecessary friction |
| `type="email"` | ✅ | Triggers the email keyboard on mobile |
| Visible label | ⚠️ Placeholder-only | Carried by "Never Miss a Deal" heading; acceptable for 1 field |
| Submit copy | ⚠️ "Subscribe" | Generic. The **inline** variant uses **"Get Deals"** (benefit-framed) — adopt that here for consistency and lift |
| Loading state | ✅ "Subscribing..." | Clear verbose state — this is the pattern the *footer* variant should copy (it shows a cryptic "...") |
| Error feedback | ✅ | Red message rendered below the form |
| Success state | ✅ | Replaces form with confirmation panel |
| Trust microcopy | ✅ "No spam, unsubscribe anytime." | Present — the footer variant is *missing* this |
| **Conversion telemetry** | ❌ **None** | `handleSubmit` (`:15–43`) fires **no** `dataLayer.push` / analytics event on success. **Every newsletter signup is invisible to measurement.** This is why the funnel's signup row can only ever read server-side totals. |

**Form recommendations:**
1. **🔴 Add a `dataLayer.push({ event: 'newsletter_signup', source })` on success** (`NewsletterSignup.tsx:31–34`, just after `setStatus('success')`). 4 lines. This is the prerequisite for measuring *any* of the homepage fixes above — without it, even a winning change is unreadable. Pair with the GA4 read-out restore.
2. **🟢 "Subscribe" → "Get Deals"** on the card submit button (`:142`) for benefit framing + parity with the inline variant. Low effort, applies wherever the card mounts.
