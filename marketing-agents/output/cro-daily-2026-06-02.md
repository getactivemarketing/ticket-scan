## Page-Level Review — Compare page `/compare` (Tuesday rotation)

This is **the product's core value proposition page** — "compare ticket prices across sites." It is also, today, the page most likely to receive World Cup search traffic. Full re-read of `page.tsx` (665 lines) this morning. The comparison UI itself is good: honest fee disclosure (the amber "Pro Tip" at `:648–660` candidly labels section estimates as inferred, ~27%/~24%/~20% fees spelled out — exactly the data-driven-advocate brand voice), clean side-by-side layout, a real "Save $X" badge, sensible event-matching logic. The problems are all about **who is allowed to see it and what happens after they do.**

### Findings (priority order)

| # | Pri | Finding | Fix | Effort |
|---|-----|---------|-----|--------|
| **C1** | 🔴 P0 | **Hard-gate: anonymous users are redirected to `/login` before seeing anything** (`:87–90`, `if (!authLoading && !user) { router.push('/login') }`). The single most valuable, lowest-commitment action a first-time visitor can take — *compare two prices* — is locked behind email+password. A WC searcher who clicks a "Compare prices" link lands on a login wall, not a comparison. This is the highest-leverage open ship on the entire frontend. | **Ungate the page.** Let anyone compare. Gate only the *persistent* actions (watchlist/alert) at the point they're used — the Kayak/Booking pattern. Delete the redirect; render results for all. | 10 min |
| **C2** | 🔴 P0 | **No "track / set alert" CTA anywhere in the results.** A user compares, sees "Save $40," and the only next actions are two external **"Buy on Ticketmaster/SeatGeek →"** links (`:440–447`, `:489–496`). The highest-intent moment on the site — user just saw a saving — has **no path into watchlist or price-alert.** The funnel's most valuable step is missing on its most valuable page. | Add a "🔔 Track this price" button to each matched-event card that opens the watchlist-add (with target-price input, see Form Check). Converts compare-intent into a retained, alert-eligible user. | 45 min (depends on Form #1) |
| **C3** | 🟡 P1 | **Empty-state and "Pro Tip" advertise sources the compare never queries.** The empty state (`:637–642`) shows chips for **StubHub, Vivid Seats, "+60 more"**, and the Pro Tip names StubHub ~24% fees — but `handleSearch` only fetches `ticketmaster` + `seatgeek` (`:208–209`). The SeatGeek-aggregates-60-sites framing (`:635`) is defensible, but naming StubHub/Vivid as if independently compared overstates coverage. | Reframe to what's true: "We compare Ticketmaster vs. SeatGeek (which aggregates StubHub, Vivid Seats & 60+ resale sites)." Drop the standalone StubHub fee line or label it as part of SeatGeek's pool. | 10 min |
| **C4** | 🟢 P2 | **Hardcoded default city `'Orlando'`** (`:74`). Every visitor — including WC traffic looking for host cities (NY/NJ, LA, Dallas, KC…) — starts with Orlando pre-filled and must clear it. Minor friction, wrong default for the season. | Default to empty (placeholder already says "e.g., Orlando, Miami"), or geo/UTM-seed the city. | 5 min |
| **C5** | 🟢 P2 | **Icon-only matched-card density is fine on desktop but the two external buy buttons compete with no visual primary.** Both "Buy on X →" render at equal weight; the cheaper (`bestSource`) side is only differentiated by a green background + "BEST" pill. | Make the BEST side's button visually dominant (solid brand, larger) and de-emphasize the costlier one — guide the eye to the saving. | 15 min |

**5 findings (2 P0, 1 P1, 2 P2).** C1 is a 10-minute deletion that unlocks the core product for 100% of cold traffic; C2 turns the resulting compare sessions into retained users. **C1 + C2 are the compare-page version of the two ships my own weekly memo named as highest-leverage** — they remain unshipped, so I'm restating them concisely here on the day the page is in rotation, *not* re-escalating with new urgency theater. ## Form Friction Check — Watchlist-add (`EventCard.tsx`)

The task's "Watchlist add modal" **is not a modal.** It is a single icon button (`:159–170`, renders `👁️` / `...` / `✓`) plus a full-card sign-up overlay for logged-out users (`:80–104`). Reviewed both paths.

| Check | Status | Note |
|-------|--------|------|
| Logged-out path | ✅ Soft | Shows a "Track This Event → Sign Up Free / Maybe Later" overlay (`:80–104`) instead of a hard redirect. Good — this is the pattern `/compare` should adopt (C1). |
| Field count (logged-in) | ⚠️ **0 fields** | One tap adds the event with **no target price, no confirmation** (`:43–49`). Zero friction, but also zero value capture. |
| **Target-price input** | ❌ **Absent** | `addToWatchlist` omits `targetPrice` entirely — `api.ts` accepts it, the `watchlist` table has the column, the cron checks it. **Without this input, no alert can ever fire** (`triggeredAlerts: 0`). The product's headline feature ("get alerts when prices drop") has no UI to arm it. |
| Button clarity | ⚠️ Icon-only | `👁️` with a `title` tooltip. Unlabeled; on mobile (no hover) the tooltip never shows. Meaning is guessable at best. |
| Loading state | ⚠️ `...` | Cryptic vs. the newsletter form's verbose "Subscribing…". |
| Success feedback | ✅ `✓` + green | Clear that *something* happened, though no "what next." |
| Error feedback | ✅ | Red message below the card (`:172`). |
| Conversion telemetry | ❌ None | No event fired on add — same measurement gap as everywhere. |

**Form recommendations:**
1. **🔴 Add a target-price input to the watchlist-add flow.** This is the second of the two highest-leverage ships. Convert the one-tap into a tiny inline popover/modal: prefill the current min price, let the user set "alert me below $___," send `targetPrice` in the `addToWatchlist` payload (`:43–49`). **This is the single change that turns the dormant price-alert engine on.** ~45 min.
2. **🟢 Label the button** — `👁️ Track` instead of bare `👁️`, so the action reads on mobile where the tooltip is invisible. 5 min.
3. **🟢 Verbose loading copy** — `...` → "Adding…" for parity with the newsletter form. 2 min.
