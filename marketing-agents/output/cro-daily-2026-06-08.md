## Form Friction Check — User Registration (Monday rotation)

`register/page.tsx` is clean and works (email + password + confirm → `/dashboard`). Friction notes:

| Check | Status | Note |
|-------|--------|------|
| Field count | ⚠️ | **3 fields.** The **confirm-password** field (`:95–108`) is avoidable friction — the modern pattern is a single password field with a show/hide toggle. |
| `autocomplete` attributes | ❌ | None set. Email should be `autoComplete="email"`, password `autoComplete="new-password"` — without them, browser/password-manager autofill is degraded (a real mobile drop-off cause). |
| Mobile keyboard | ✅ | `type="email"` triggers the email keyboard. |
| Inline validation | ⚠️ | Password length (8) and match are only checked **on submit** (`:22–30`); no real-time hint. A user can fill everything, submit, then get bounced. |
| Show-password toggle | ❌ | None. Two masked password fields with no reveal = higher typo/abandon rate on mobile. |
| Button copy | ✅ | "Create account" / "Creating account…" — action-oriented, good loading state. |
| **Newsletter opt-in** | ❌ | **No opt-in checkbox.** Registrants are the *highest-intent* audience and are never asked to subscribe — a direct contributor to subscribers stuck at 3 while users hit 109. This is item (3) from [[newsletter-conversion-rootcause]], still open. |

**Form recommendations (priority):**
1. 🟠 **Add a checked-by-default newsletter opt-in** ("Email me price-drop deals", POST to `/api/newsletter/subscribe` on register). Closes the last gap in [[newsletter-conversion-rootcause]] and taps the highest-intent users. ~15 min.
2. 🟡 **Add `autoComplete` attributes** (`email`, `new-password`) — cheapest autofill win. ~2 min.
3. 🟡 **Drop confirm-password for a show/hide toggle** — removes a field, reduces typo abandons. ~15 min.
4. 🟢 **Inline password-length hint** under the field instead of submit-time error. ~10 min.
