## Page-Level Review — Compare (`/compare`)

### 🔴 P0 — The compare tool is hard-gated behind login (value-after-gate inversion)
**Evidence:** `web/src/app/compare/page.tsx:86-90` redirects any non-authenticated visitor straight to `/login` before rendering anything.

```tsx
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```

Why this is the #1 conversion problem on this page:
- **The page is built and indexed as a public tool.** `compare/layout.tsx` ships a canonical URL, OpenGraph/Twitter cards, and `WebApplication` JSON-LD with `offers.price: "0"` and a public `featureList`. We are telling Google this is a free, usable web app.
- **Logged-out visitors genuinely reach it.** `Footer.tsx:72` and `blog/[slug]/page.tsx:219` link to `/compare` with no auth guard, and organic searchers land from Google. Every one of them hits the `/login` wall before seeing a single price.
- This is the classic "ask for the signup before delivering any value" inversion. The compare tool *is* the value proposition ("Find the best deals across multiple ticket sites") — gating it pre-value maximizes bounce and wastes the SEO/JSON-LD investment.

**Recommendation (build ONE thing):** Let anonymous users run the compare search and see results. Move the gate to the *downstream* high-intent actions that actually need an account — **watchlist add / price alert**. Implementation is small: delete the redirect at `page.tsx:86-90`; the search + match flow (`handleSearch`, `matchEvents`) already has no auth dependency. Optionally cap anonymous usage (e.g. results visible, "Save this comparison / get price-drop alerts → Sign up" CTA injected after the first search) to convert intent at the moment value is proven.

> Priority: P0, high confidence, low effort. This is a shipping task, not an analysis task. Hand to dev backlog.

### 🟡 P1 — No conversion CTA inside the results state
Even for logged-in users, the results view (`page.tsx:336-627`) ends at "Buy on Ticketmaster/SeatGeek →" outbound links. The strongest moment of intent — a user just saw a "Save $X" callout (`page.tsx:405-409`) — has no "Track this event / Alert me if it drops" CTA. We send the warm user off-site instead of into watchlist/alerts (the retention loop). Add a "Set a price alert for this event" button on each matched card. (Routes to the known-unarmed alerts feature — see standing watchlist/alerts findings — so pair with arming target_price capture.)

### 🟢 P2 — Empty-state is strong; keep it
The pre-search empty state (`page.tsx:630-645`) clearly communicates sources (Ticketmaster, SeatGeek, StubHub, Vivid Seats, "+60 more") and the fee-transparency "Pro Tip" banner is good trust-building, data-driven copy. No change needed.

## Form Friction Check — Compare search form (`page.tsx:261-325`)

| Check | Status | Note |
|-------|--------|------|
| Field count | ✅ Good | 4 optional fields (city, keyword, from/to date). Not overwhelming. |
| Labels | ✅ Clear | Each input has a real `<label htmlFor>` with example placeholders ("e.g., Magic, Taylor Swift"). |
| Submit button copy | ✅ Action-oriented | "Compare Prices" (not "Submit") with "Searching…" loading state. Matches best practice. |
| Loading feedback | ✅ Present | Button disables + spinner state on results. |
| Date inputs | ✅ Sensible | `min={today}` / `min={startDate}` prevent invalid past/inverted ranges. |
| Mobile keyboard | 🟡 Minor | `city` and `keyword` are plain `type="text"` — fine, but `autoComplete`/`enterKeyHint="search"` would smooth mobile submit. |
| Friction | 🟡 Minor | `city` defaults to `'Orlando'` (`useState('Orlando')`). Good for demoing, but a Miami/NYC user must clear it first. Consider geolocation default or a clearable chip. |

**Form verdict:** The compare form itself is well-built — *the friction is not the form, it's the login wall in front of it* (see P0). Fixing the auth gate unlocks this otherwise-solid form for the traffic that already arrives.
