## Page Review — Compare page (`/compare`)

**Verified live today:**
- ✅ `https://www.ticketscan.io/compare` returns HTTP 200 (static shell, ~32 KB) — the page is server-rendered/indexable, but the redirect is **client-side**, so real anonymous users get bounced after hydration. Crawlers see a shell; humans see `/login`.
- ⚠️ `/compare` is linked from **Navbar desktop (`Navbar.tsx:62`), Navbar mobile (`Navbar.tsx:144`), and Footer (`Footer.tsx:72`)**. It is a **primary-nav destination**, promoted site-wide.

**P0 (top compare-page finding, standing) — The login wall on a primary-nav page.**
`compare/page.tsx:87-90`:
```tsx
// Redirect if not logged in
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```
Every anonymous visitor who clicks "Compare" in the nav/footer — or lands on the SEO-indexed URL — is redirected to `/login` **before seeing a single price**. The page's entire value (Ticketmaster vs SeatGeek side-by-side, fee-inclusive pricing, savings badges, section estimates) is hidden behind account creation. This is the single biggest conversion leak on the page: we advertise price comparison in the global nav, then gate it.

→ **Recommendation (ship task, not analysis):** Delete the `lines 87-90` redirect and let anonymous users run the search + see results. Gate only the *save* actions (watchlist add / price alert), where login is genuinely required — show an inline "Create a free account to track this price" prompt on those buttons instead of blocking the whole page. The search/compare flow already calls a public API (`api.compareEvents`) and renders fully without any user object, so un-gating is a deletion, not a rebuild. This is the highest-leverage compare-page change and has been specced repeatedly — bottleneck is merge + deploy, not design. *(Re-confirmed live in source today; consistent with standing "compare-page-login-gated" finding — not a new flag.)*

**P2 — Hardcoded `city = 'Orlando'` default (`compare/page.tsx:74`).**
The search form pre-fills City with "Orlando" for everyone. Fine as a demo seed, but a Miami/NYC visitor must clear it first. Low friction, low priority — note only.

## Form Review — Compare search form (`compare/page.tsx:261-325`)

The form itself is clean; the dominant "friction" is that anon users never reach it (see P0).

- **Field count: 4** (City, Event/Artist/Team, From Date, To Date), all effectively optional. ✅ Reasonable for a search.
- **Submit copy: "Compare Prices"** ✅ — action-oriented, exactly right (not "Submit").
- **Loading state** ✅ — button shows "Searching..." and is disabled.
- **Labels** ✅ — clear, associated via `htmlFor`/`id`.
- **Date inputs** ✅ — `min={today}` / `min={startDate}` prevent invalid ranges.
- ⚠️ **No `autoComplete`/`inputMode` on City or Keyword** — minor; add `autoComplete="off"` or a `<datalist>` of popular cities to speed entry. One-liner.
- ⚠️ **Empty keyword + default city** returns a broad city dump; consider requiring either a keyword or a date range to keep first results relevant. Low priority.

Net: the form is not the problem — **the wall in front of it is.** Form-CRO and page-CRO both resolve to the same P0.
