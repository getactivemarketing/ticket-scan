## Form Friction Check — Watchlist Add (EventCard)

The primary "track this event" / add-to-watchlist control is the heart icon in `EventCard.tsx` (the button used across search and compare results).

**Finding (ties to known P0): the add payload carries no target price.**
`EventCard.tsx:43-49` sends only `eventId, eventName, eventDate, venue, city` — **no `targetPrice`**. There is no price-target input anywhere in this add flow. Consequence: every watchlist add lands with a null target, so the price-alert engine has nothing to arm against — explaining `activeAlerts = 0` despite ~149 watchlist items. The product copy promises alerts; the form can't capture the one field that makes them fire.

**Fix (small, front-end, high value):** add an optional "Alert me below $___" numeric input to the add flow (inline expand on the EventCard, or a one-field confirm modal). Email-keyboard not relevant; use `inputMode="decimal"`. Button copy: "Set price alert" (action-oriented) rather than a bare heart toggle once a target is entered. This is the cheapest way to convert dormant watchlist items into a working alert funnel.
