## Page Review — Dashboard / Search (`/dashboard`)
Source read: `web/src/app/dashboard/page.tsx`. Strengths: anonymous sign-up banner is above the fold (line 60-75), search form is clean, 4 well-labeled fields, good empty/no-results states.

**Recommendations (priority order):**

1. **[P1 — Activation] Add one-click quick-search chips to the empty state.** Right now the initial view (`!searched`, line 178) shows "Find your next event" + blog tips but **requires the user to type before anything happens**. Add 4-6 tappable chips that pre-fill and fire the search — e.g. `World Cup 2026`, `Taylor Swift`, `NBA`, `Concerts near me`. This is the single biggest first-action lever on the page: it converts passive browsers into searchers with zero typing. Mobile users especially benefit (no keyboard needed).

2. **[P2 — Friction] Reconsider the hardcoded `city = 'Orlando'` default (line 27).** A visitor anywhere else who hits "Search Events" gets Orlando results, which reads as broken/irrelevant. Either blank it with a strong placeholder (already present: "e.g., Orlando, Miami") or geo/IP prefill. Low effort, removes a confusing first impression.

3. **[P3 — Trust] Add a one-line social-proof stat to the search header.** We now have a real, honest number: **130 members tracking 159 events.** A subtle line under the H1 ("Join 130 fans tracking ticket prices") adds credibility at the point of search intent. Use real counts only — pull from `/api/admin/stats`, don't hardcode a stale figure.

## Form Check — User Registration (`/register`)
Source read: `web/src/app/register/page.tsx`. 3 fields: email, password, confirm password. Email field correctly uses `type="email"` (triggers email keyboard). Button copy "Create account" is clear. Validation is client-side and reasonable.

**Recommendations (priority order):**

1. **[P1] Add a newsletter opt-in checkbox** (checked or unchecked per legal preference). This is the cheapest fix for the 3-subscriber anomaly above — **all 130 registrations currently bypass the newsletter list entirely.** One checkbox + a call to the existing `/api/newsletter/subscribe` on submit captures intent at the highest-engagement moment. Directly addresses the long-standing "/register opt-in TODO."

2. **[P2] Drop the "Confirm password" field; add a show/hide toggle instead.** Confirm-password is measurable friction (3rd field, double typing) and modern best practice replaces it with a visibility toggle. Removing one of three fields is a meaningful reduction on a short form.

3. **[P3] Add `autoComplete` attributes + inline password hint.** Set `autoComplete="email"` and `autoComplete="new-password"` for mobile autofill, and surface the "min 8 characters" rule *before* submit (currently only appears as a post-submit error, line 27-30). Smooths first-attempt success.
