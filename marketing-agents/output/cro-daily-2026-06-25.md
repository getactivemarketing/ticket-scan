## Page-Level Review: Event Detail Page (`/event/[id]`)

**Focus: Thursday = Event detail page**

Reviewed `web/src/app/event/[id]/page.tsx` against current source.

### Finding 1 — Hard auth-wall with zero preview (P0, carries over from P0-3)

**Location:** `page.tsx:109-112`
```tsx
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```

Anonymous visitors are silently redirected to `/login` with no preview of the content they were trying to reach. The page contains the most compelling product proof — price chart, buy/wait/hold recommendation, tier pricing — but no visitor who isn't already logged in ever sees any of it.

**Problem compounded:** The "Back to Watchlist" link (`page.tsx:188-196`) is the only navigation on the page, meaning the intended flow is `watchlist → event detail`, not `search result → event detail`. EventCard has no link to this page at all.

**Fix:** Allow anon visitors to see a preview (trend + recommendation headline + blurred chart) with a soft gate: "Sign up free to unlock full price history." Pair with linking EventCard event name to `/event/[eventId]`.

**Priority:** P0 — this page is the core product proof and currently invisible to all new users.

### Finding 2 — "Back to Watchlist" is the only exit path

The page offers one navigation option: back to `/watchlist`. For a logged-in user who reached this page from a direct URL share, there is no way to browse or search without using the browser back button or the Navbar.

**Fix:** Add a secondary "Search events" link alongside "Back to Watchlist."

**Priority:** Low — minor UX polish, not a conversion blocker.

### Finding 3 — Empty state copy undersells urgency

**Location:** `page.tsx:342-353`

When price history is empty (which is every event right now — confirmed: price_history table has 0 rows), users see:
> "Price tracking just started — We check prices every 4 hours. Check back soon."

This is fine for a waiting state but misses a retention hook. There is no prompt to set a price alert, no email reminder offer, and no CTA to compare prices on another platform in the meantime.

**Fix:** Add a micro-CTA in the empty state: "Want an email when we have data? [Set alert price →]" — this is also the natural trigger for the P0-2 fix (target price input).

**Priority:** Medium — cheap copy change, directly relevant to email/alert retention.

## Form Friction Review: Price Alert Setup

Reviewing how users currently set a price alert (or can't).

**Current state (verified from `EventCard.tsx:43-49`):**
- The "Track" button (👁️) adds to watchlist with no target price
- `api.addToWatchlist()` at `api.ts:169` accepts `targetPrice?: number` but EventCard never passes it
- Result: 149 watchlist items, 0 active alerts

**Form audit — the form that does not exist:**

| Check                        | Status |
|------------------------------|--------|
| Target price input present   | Missing |
| Label clarity                | N/A    |
| Error feedback               | N/A    |
| Submit copy action-oriented  | N/A    |
| Mobile keyboard type         | N/A    |
| Loading state feedback       | N/A    |

This is a missing form, not a bad form. There is no input for `targetPrice` anywhere in the user-facing UI.

**Ship-ready spec (carried from weekly 2026-06-22):**

Add to `EventCard.tsx`, inside the logged-in add flow only:

```tsx
// State
const [targetPrice, setTargetPrice] = useState('');

// UI — show only when logged in, above the action row
{isLoggedIn && (
  <input
    type="number"
    inputMode="decimal"
    placeholder="Alert me below $…"
    value={targetPrice}
    onChange={(e) => setTargetPrice(e.target.value)}
    className="w-full mt-2 px-2 py-1 text-sm border border-gray-300 rounded"
  />
)}

// Pass to API call
await api.addToWatchlist({
  eventId: event.id,
  eventName: event.name,
  eventDate: event.date,
  venue: event.venue,
  city: event.city,
  targetPrice: targetPrice ? Number(targetPrice) : undefined,
});
```

No backend change. No migration. No new dependency. Unlocks the entire alert pipeline for all 149 existing watchlist items + all future adds.
