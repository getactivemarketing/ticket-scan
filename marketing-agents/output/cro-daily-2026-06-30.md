## Page-Level Review: Compare Page (`/compare`)

**Focus: Tuesday = Compare page**

### Finding 1 — Hard auth-wall blocks all organic and linked traffic (P0)

**Location:** `page.tsx:87-90`
```tsx
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```

The compare page has explicit SEO metadata in `layout.tsx` targeting "compare ticket prices", "Ticketmaster vs SeatGeek", "cheapest tickets" — keywords with real organic intent. It is linked from the footer nav, blog posts, and venue pages. Every visitor arriving from those sources hits `/login` before seeing a single price.

This is the same auth-redirect pattern already flagged as P0 on the event detail page. The compare page is arguably the highest-value proof page on the site: it shows real dollar savings between platforms. Locking it away from anonymous visitors destroys the conversion opportunity completely.

**Fix:** Remove the hard redirect. Replace with a soft gate on the search action:
- Allow anonymous visitors to load the page and see the search form + empty state
- On form submit, either (a) run the search and show results with a signup prompt beneath ("Sign up free to save your searches and get alerts"), or (b) show a brief preview then prompt login
- Option (a) is lower friction and likely higher converting

**Estimated effort:** Small — delete 4 lines of auth redirect, add a conditional CTA after results render.

**Priority:** P0 — this page is indexed by Google, linked everywhere, and currently delivers zero value to anonymous visitors.

### Finding 2 — Default city "Orlando" assumes every visitor is in Florida (P1)

**Location:** `page.tsx:74`
```tsx
const [city, setCity] = useState('Orlando');
```

Every visitor sees Orlando pre-filled in the City field on load. A user in Chicago, Los Angeles, or New York immediately perceives the tool as not for them before they've typed a single character. They must actively clear and retype before getting any value.

**Fix:** Default to an empty string or to a geographically neutral placeholder like `e.g., New York, Los Angeles`. If browser geolocation is available, auto-populate. Minimum viable fix is just `useState('')` with the existing placeholder text.

**Estimated effort:** Trivial — one-character change.

**Priority:** P1 — affects every non-Orlando visitor, zero implementation cost.

---

### Finding 3 — No watchlist/alert CTA after price comparison results (P1)

**Location:** `page.tsx:391-507` (matched events render loop)

After showing a matched event card with side-by-side prices and a "Save $X" badge, there is no next action for the user beyond clicking through to Ticketmaster or SeatGeek. There is no "Track this event" button, no "Set a price alert" hook, and no path deeper into the product.

The compare page generates the highest purchase intent of any page on the site. A user who sees "SeatGeek saves you $18 on this game" is primed to want an alert if the price drops further — but there's nowhere to go.

**Fix:** Add a "Track Price" button to each matched event card (authenticated only; prompt login for anon):
```tsx
{user && (
  <button
    onClick={() => api.addToWatchlist({ eventId, eventName, eventDate, venue, city })}
    className="text-sm text-brand underline hover:no-underline"
  >
    Track price →
  </button>
)}
```

**Estimated effort:** Small — add button to card header row, reuse existing `api.addToWatchlist()`.

**Priority:** P1 — the compare page currently has no retention hook at all.

### Finding 4 — "Compare Prices" submit button is right-aligned (P2)

**Location:** `page.tsx:316`
```tsx
<div className="flex justify-end">
  <button type="submit" ...>Compare Prices</button>
</div>
```

The form has 4 inputs in a grid, then the CTA floats to the right edge. Users scan left-to-right and expect the primary action button to anchor below the form content — either full-width or centered. Right-alignment buries the CTA visually and is particularly problematic on mobile where the thumb zone is center/bottom.

**Fix:** Change to `flex justify-center` or `w-full` on the button.

**Estimated effort:** Trivial.

**Priority:** P2 — minor friction on mobile, easy fix.

### Finding 5 — Empty state promises 60+ sources; reality is 2 (P2)

**Location:** `page.tsx:637-644`
```tsx
<span>🏪 StubHub</span>
<span>🎪 Vivid Seats</span>
<span>+ 60 more</span>
```

The pre-search empty state lists StubHub, Vivid Seats, and "60 more" as sources alongside Ticketmaster and SeatGeek. In practice the compare API only fetches from Ticketmaster and SeatGeek. The Pro Tip banner at the bottom clarifies that SeatGeek *aggregates* StubHub/Vivid Seats resale inventory — but most users won't read a disclaimer after already forming an expectation.

This is a credibility gap: if a user searches for a StubHub-specific deal and sees "Not available" on the StubHub column that doesn't exist, they'll feel misled.

**Fix:** Change the empty state source badges to accurately reflect what's fetched:
```tsx
<span>🎫 Ticketmaster</span>
<span>🎟️ SeatGeek (incl. StubHub, Vivid Seats + 60 resale sites)</span>
```

**Estimated effort:** Trivial — copy change only.

**Priority:** P2 — trust/credibility issue, trivial to fix.
