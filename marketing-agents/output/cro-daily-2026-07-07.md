## Page-Level Review: Compare Page (`/compare`) — Tuesday Focus

**Status: All P0/P1 findings from 2026-06-30 remain unshipped.** Code at `page.tsx:87-90` is unchanged. The hard auth redirect is still in place one week later.

Rather than re-listing the same findings, this report focuses on **what it costs to leave this unshipped one more week** and **one new finding** discovered in this pass.

---

### [CARRY-OVER P0] Login gate — unshipped 7+ days

`page.tsx:87-90` still redirects all anonymous visitors to `/login`.

The layout.tsx SEO metadata targets: `compare ticket prices`, `ticket price comparison`, `Ticketmaster vs SeatGeek`, `cheapest tickets` — these are high-purchase-intent queries. Every organic visitor arriving on this page hits `/login` before seeing a single result. Every blog post and footer link that sends traffic here is wasted.

**This is the single highest-leverage unshipped change in the codebase.** The fix is deleting 4 lines and adding a soft signup prompt after results render.

---

### [NEW — P1] No `returnUrl` on auth redirects — users lose their place

When the compare page (or event detail page) redirects an anonymous visitor to `/login` or `/register`, neither the login nor register page captures a `returnUrl`. After completing auth, the user is sent to `/dashboard` — not back to the compare search they just tried to run.

**User experience:** A visitor from Google searches for "NBA playoff ticket prices comparison", lands on `/compare`, gets redirected to `/login`, creates an account, lands on `/dashboard` with zero context for what to do next. The event they wanted to compare is gone.

**Fix:** Three small changes:
1. In `compare/page.tsx` (and `event/[id]/page.tsx`), push `/login?returnUrl=/compare` instead of just `/login`
2. In `register/page.tsx` and `login/page.tsx`, read `searchParams.get('returnUrl')` and redirect there after successful auth
3. Sanitize the returnUrl to only allow relative paths (prevents open redirect)

```tsx
// compare/page.tsx:88 — instead of:
router.push('/login');
// use:
router.push(`/login?returnUrl=${encodeURIComponent('/compare')}`);
```

```tsx
// register/page.tsx — after await register(email, password):
const returnUrl = searchParams.get('returnUrl');
router.push(returnUrl && returnUrl.startsWith('/') ? returnUrl : '/dashboard');
```

**Estimated effort:** Small — 3 files, ~10 lines total.

**Priority:** P1 — directly recovers users who are willing to sign up but get dropped after registration.

| Check                                    | Status  | Notes |
|------------------------------------------|---------|-------|
| Field count                              | ⚠️ 3   | Email + password + confirm password — confirm adds friction |
| `type="email"` on email field            | ✅      | Triggers email keyboard on mobile |
| `type="password"` on password fields     | ✅      | Correct |
| Labels with `htmlFor`                    | ✅      | All 3 fields have proper labels |
| `required` attributes                    | ✅      | All fields |
| Button copy                              | ✅      | "Create account" — clear |
| Loading state                            | ✅      | "Creating account..." — informative |
| Error feedback                           | ✅      | Red box, shown above form |
| Success redirect                         | ⚠️     | Sends to `/dashboard` regardless of entry point (see returnUrl issue above) |
| Social proof                             | ❌      | No user count, no trust signal, no benefit bullet |
| Value proposition                        | ⚠️     | "Start tracking ticket prices today" — functional but weak |
| Newsletter opt-in                        | ❌      | No checkbox — users hit the drip sequence without explicit consent |
| Password requirements shown proactively  | ❌      | "at least 8 characters" is only surfaced on error after submit |

**Recommendations (2 actionable):**

**1. Remove the confirm password field (P2)**

Modern auth forms (Stripe, Vercel, Linear) dropped confirm password years ago. If a user miskeys, password reset recovers them. The field adds a full interaction — type, tab, type again — with zero meaningful protection.

Delete `confirmPassword` state, the `<div>` block at lines 95–108, and the `if (password !== confirmPassword)` validation check.

**2. Add inline password requirement hint (P2)**

Currently the 8-character minimum only appears as an error after a failed submit. A small inline hint shown below the password input would prevent the failed-submit loop:

```tsx
<p className="text-xs text-gray-400 mt-1">At least 8 characters</p>
```

One line. Reduces form abandonment from failed validations.

**Larger gap (P1, separate ticket):** No `returnUrl` handling — covered above. Registration is the conversion endpoint for the compare and event page auth redirects; if users don't land back where they intended, the auth flow has a dead end.
