### FINDING 1 — P0: Page is hard auth-gated, bouncing all organic traffic

**Location:** `web/src/app/event/[id]/page.tsx:108-112`

```tsx
if (!authLoading && !user) {
  router.push('/login');
  return null;
}
```

Every anonymous visitor — including anyone who lands via search, share link, or direct URL — is immediately redirected to `/login` before seeing a single pixel of content. The page shows price history charts and buy recommendations: exactly the content that builds enough trust to prompt a signup. Instead, strangers get a login wall with zero context, and they bounce.

**Fix:** Show the price chart and BuyRecommendation to anonymous visitors. Only gate the "Add to Watchlist" button (which already has a sign-up prompt overlay built into EventCard). Replace the hard redirect with a conditional CTA:

```tsx
// Remove the router.push('/login') block entirely.
// In the watchlist/alert CTA section, show:
{!user && (
  <Link href="/register" className="...">
    Sign Up Free to Track This Event
  </Link>
)}
```

**Impact:** This is the highest-leverage unshipped fix on the site. The page can generate signups — but only if people see it.

---

### FINDING 2 — P0: Event detail page is orphaned — unreachable from search

**Location:** `web/src/components/EventCard.tsx:150-171` (no link to `/event/[id]`)

The event detail page is only linked from `watchlist/page.tsx:237`. There is no link to it from EventCard, the dashboard, or any search result. A user who finds an event they're interested in has no path to view its price history — the main value proposition of the product.

**Fix:** Add a "View Price History →" link to EventCard, below the Buy Tickets / watchlist buttons:

```tsx
<Link
  href={`/event/${event.id}`}
  className="text-sm text-brand hover:text-brand-dark font-medium"
>
  View price history →
</Link>
```

This single line connects the discovery flow (search → event card) to the retention/conversion flow (price chart → watchlist add → alert → return visit).

---

### FINDING 3 — P1: No "Buy Tickets" CTA on the event detail page

**Location:** `web/src/app/event/[id]/page.tsx` — no external buy link present

The page builds buying intent with a BuyRecommendation component that can display "Good Time to Buy" with high confidence — and then offers no action. The user has to navigate back to search, find the event again, and click "Buy Tickets" on the card. That's two unnecessary steps at peak buying intent.

**Fix:** Add a prominent "Buy Tickets" button in the page header next to the price trend, using the Ticketmaster URL stored in the price history or passed as a query param.

## 3. Form Friction Check — Watchlist Add (EventCard)

**Reviewed:** `web/src/components/EventCard.tsx:33-56`

The watchlist add "form" is a single-tap button with no target price input. The API supports `targetPrice` but the call never includes it:

```tsx
await api.addToWatchlist({
  eventId: event.id,
  eventName: event.name,
  eventDate: event.date,
  venue: event.venue,
  city: event.city,
  // targetPrice: ← missing
});
```

This means 100% of watchlist adds have no target price, which means 0 price alerts can ever fire. The alert system is completely inert for all new adds.

**Recommendation:** Before confirming the watchlist add, show a small inline input:

```
Set a target price (optional):  [$______]  [Track It →]
```

Implementation: toggle a "confirm" state in EventCard after the eye button is clicked. Show a small input + confirm button. Send `targetPrice: parseFloat(inputValue) || null` to the API.

- Fields: 1 (price input)
- Label: "Alert me when price drops below:" — clear and outcome-oriented
- Keyboard: `type="number"` triggers numeric keyboard on mobile
- Submit copy: "Track It" — action-oriented, not "Submit"
- Skip affordance: "No thanks, just track" for users who don't want an alert

**Effort:** ~45 minutes. This unlocks the entire alert/retention loop for every future watchlist add.
