### FINDING 1 — P0: Zero urgency signaling despite the Final being tomorrow

**Location:** `web/src/app/world-cup-2026/page.tsx:116-139` (hero section)

The hero badge reads "June 11 - July 19, 2026" — accurate but inert. A visitor landing today has no visual cue that this is the last 24 hours of the tournament. The "Key Tournament Dates" section correctly highlights the Final (July 19, MetLife) but it lives ~70% down the page behind venues and team sections.

Someone searching "World Cup Final tickets" today needs to understand in under 3 seconds that (a) the Final is tomorrow and (b) they can compare prices right now. The page currently reads as a general tournament hub, not a final-countdown urgency page.

**Fix:** Replace the static date badge with a countdown/urgency pill:

```tsx
// Replace:
<div className="inline-block bg-white/20 backdrop-blur-sm px-4 py-2 rounded-full text-sm font-medium mb-6">
  June 11 - July 19, 2026
</div>

// With:
<div className="inline-block bg-yellow-400 text-yellow-900 px-4 py-2 rounded-full text-sm font-bold mb-6 animate-pulse">
  ⚡ World Cup Final: Tomorrow — MetLife Stadium
</div>
```

Update the hero `<h1>` subtext (`page.tsx:123-124`) to lead with Final context:

```tsx
// Replace the current subtitle:
<p className="text-xl text-green-100 max-w-3xl mx-auto mb-8">
  The biggest World Cup ever is coming to North America...
</p>

// With:
<p className="text-xl text-green-100 max-w-3xl mx-auto mb-8">
  The World Cup Final is tomorrow at MetLife Stadium. Compare last-minute ticket prices across Ticketmaster, SeatGeek, and StubHub — prices spike the closer it gets.
</p>
```

**Impact:** Highest-leverage copy change of the entire campaign. Zero dev effort, ships in 5 minutes.

### FINDING 3 — P2: Bottom CTA offers register but compare page is login-gated

**Location:** `web/src/app/world-cup-2026/page.tsx:480-494` (bottom CTA section)

The bottom CTA section sends visitors to `/register` or `/dashboard?keyword=world+cup`. But the documented P0 issue (see memory: `compare-page-login-gated.md`) means `/compare` hard-redirects anon visitors to `/login`. Users who follow the "Compare Prices" CTA in the footer quick-links hit a login wall with no context.

If "Create Free Account" is the CTA, the page needs to briefly answer "why?" — what does registration unlock?

**Fix:** Update the bottom CTA supporting copy to set expectations:

```tsx
// Current:
<p className="text-green-100 mb-8 text-lg">
  Create a free account to track World Cup ticket prices and get alerts when deals drop.
</p>

// Updated:
<p className="text-green-100 mb-8 text-lg">
  Create a free account to unlock price comparisons, set drop alerts, and get notified the moment World Cup tickets hit your target price.
</p>
```

Also change the "Create Free Account" button label to "Compare Prices Free →" — outcome-oriented, not action-oriented. This tests whether visitors respond better to the benefit framing.

**Effort:** ~5 minutes.

## 3. Form Friction Check — Newsletter Signup (Footer Variant)

**Reviewed:** `web/src/components/NewsletterSignup.tsx:45-78`

### Audit

| Attribute | Current | Assessment |
|-----------|---------|------------|
| Field count | 1 (email) | ✅ Minimal |
| Heading | "Get Ticket Deals" | ✅ Outcome-oriented |
| Supporting copy | "Subscribe for exclusive deals and price drop alerts." | ✅ Clear value |
| Placeholder | "Enter your email" | Neutral — acceptable |
| Submit button copy | "Subscribe" | ⚠️ Weak — passive, describes the action not the benefit |
| Loading state | `'...'` | ❌ No feedback — looks broken on slow connections |
| Error state | Red text below form | ✅ Correct position and color |
| Success state | Replaces form with message | ✅ Prevents double-submit confusion |
| Mobile keyboard | `type="email"` | ✅ Triggers email keyboard correctly |
| Error message copy | Comes from API (`data.error`) | ⚠️ API error strings not user-tested |

### Issues

**Issue 1 — Submit button copy is passive** (`NewsletterSignup.tsx:69`)

"Subscribe" tells the user what the form does, not what they get. The `inline` variant already uses "Get Deals" which tests better for action orientation. The footer should match.

**Fix:**
```tsx
// Current:
{status === 'loading' ? '...' : 'Subscribe'}

// Updated:
{status === 'loading' ? 'Joining...' : 'Get Deals'}
```

**Issue 2 — Loading state gives no feedback** (`NewsletterSignup.tsx:69`)

`'...'` is invisible at glance-speed. On a mobile connection with 1-2s latency, users will re-tap thinking nothing happened, causing double-submit attempts.

**Fix:** Use descriptive loading text already used in the `card` variant (`'Subscribing...'`), or the updated `'Joining...'` above. This costs zero effort and eliminates a likely double-submit source.
