## Form Friction Check — NewsletterSignup card variant

The blog uses the card variant with one required email field, which is a low-friction form. `type="email"` and native `required` validation are correct, but several small issues reduce completion quality and observability:

- Add `autoComplete="email"` and `inputMode="email"` for password-manager and mobile-keyboard support.
- Change the submit copy from **“Subscribe”** to an outcome-led **“Get Ticket Deals”** or **“Get Buyer Tips”**, matching the actual archive/blog value proposition.
- Replace the loading copy **“Subscribing...”** with **“Joining...”** and expose it through `role="status"` / `aria-live="polite"`.
- Mark API errors with `role="alert"`, associate them with the input via `aria-describedby`, and preserve the entered email on retry.
- Push a `newsletter_subscribe` event only after a successful API response, including the `source` value. This is required to measure the blog conversion path.
- Consider adding one specific expectation under the field: **“One useful email a week. Unsubscribe anytime.”** Current “exclusive deals” language is broad and the page provides no frequency expectation.
