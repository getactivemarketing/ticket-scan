## Page-Level Conversion Review: Newsletter/Blog Path

### Finding 1 — Move the newsletter CTA earlier on the blog index (P1)

`web/src/app/blog/page.tsx` renders the newsletter card only after all featured and regular articles. The footer form is present sitewide, but it is below the page content. A motivated reader has to consume or scroll through the article directory before seeing the primary email ask.

**Recommendation:** add a compact, single-field newsletter band immediately below the blog hero or after the featured-article row. Keep the existing bottom card as a second ask only if analytics shows it is not redundant. Suggested copy: “Get the ticket intel before prices move” / “Weekly deal signals, price-drop alerts, and buying tips. No ticket-broker nonsense.”

### Finding 2 — Add an inline capture on individual posts, especially mobile (P1)

`web/src/app/blog/[slug]/page.tsx` places newsletter capture in the sidebar. The sidebar falls after the article on mobile, while the main article CTA asks users to create an account. This creates a late, split conversion path for readers who are not ready to register but are willing to subscribe.

**Recommendation:** place one inline `NewsletterSignup` after the introduction or first major section, with `source="blog-post-inline"`. Keep the account CTA at the end for higher-intent users. This should be one clear email ask, not a popup added on top of the existing footer form.

### Finding 3 — Page speed is not fully measured, but server response is healthy (P2)

Live `curl` checks on 2026-08-02 returned HTTP 200. Approximate total response time was 0.58s for `/blog` and 0.39s for `/`; this is server/network timing, not a Lighthouse or mobile Core Web Vitals result. No >3s server response issue was observed. Run a real mobile Lighthouse check before declaring the page fast.

## Form Friction Review: Newsletter Signup

Reviewed `web/src/components/NewsletterSignup.tsx` and `/api/newsletter/subscribe`.

| Check | Status | Notes |
|---|---|---|
| Field count | ✅ 1 | Email only; appropriate for a soft conversion. |
| Email input type | ✅ | `type="email"` supports the mobile email keyboard. |
| Required validation | ✅ | Empty submissions are blocked client-side. |
| Backend validation | ⚠️ | Checks only for an `@`; use stronger format validation or rely on a standard email validator. |

| Error feedback | ✅ | Error message is rendered below the form. Add `role="alert"` for assistive technology. |
| Success feedback | ✅ | Form is replaced by a success message. Add `role="status"` and confirm the promised content. |
| Attribution | ✅ | `source` is passed to the API (`blog-index`, `blog-post`, `site-footer`). |
| Trust copy | ✅ | “No spam, unsubscribe anytime” is present in the card variant; preserve it on all variants. |

### Form recommendation (P1)

Ship the following small changes together: explicit label/id, `aria-live` status messaging, footer button copy `Get Ticket Deals`, and a descriptive loading state. Keep the one-field form. Do not add ZIP code, name, or preference fields until the base form has measurable volume.
