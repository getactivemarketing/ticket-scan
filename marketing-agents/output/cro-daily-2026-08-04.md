## Page-Level Conversion Review: Compare

### What is working

- The value proposition is immediately clear in the page header: “Compare Ticket Prices” and “Find the best deals across multiple ticket sites.”
- The form has one obvious primary action, **Compare Prices**, with clear labels for city, event/artist/team, and date range.
- Results provide side-by-side Ticketmaster and SeatGeek prices, fee context, a `BEST` marker, savings callouts, and direct outbound buy links.
- Responsive classes collapse the four-field search grid to one column on small screens; controls use comfortable three-pixel vertical padding.
- Live route check returned HTTP 200 in 0.309s, but a real browser performance check remains outstanding.

### Recommendations

1. **P0 — Remove the hard auth wall for basic comparison.** Let anonymous users search and view a limited comparison preview. Require signup for saving an event, setting a target, and receiving alerts. This matches the user’s immediate intent and lets the product prove its value before asking for commitment.

2. **P0 — Preserve intent through auth.** If a gate remains temporarily, redirect to `/login?returnUrl=/compare` and preserve city, keyword, and date filters in validated short-lived state. After registration/login, return the user to the same query rather than the generic dashboard.

3. **P1 — Make the next conversion explicit after results.** Add a contextual CTA such as **Get price-drop alerts for this event** on each matched result, with event name, current low price, and target-price setup. The existing buy links monetize outbound intent, but there is no visible save/alert path on the comparison result itself.

4. **P1 — Instrument the actual compare funnel.** Fire `compare_viewed`, `compare_started`, `compare_completed`, `compare_zero_results`, and `outbound_ticket_click` events with route, query shape, auth state, device type, and result counts; exclude search text and other unnecessary personal data.

5. **P2 — Improve zero-result recovery.** The current message only suggests a different search or the All Events tab. Add a clear “broaden dates,” “remove date filter,” or popular-event fallback so a failed match does not end the session.

### Form recommendation — P0

Use contextual registration copy when the user arrives from a comparison or event action:

```text
Heading: Create your free price alert
Supporting copy: We’ll watch this event and email you when prices hit your target.
Primary button: Create account & set alert
Success: Account created. Set your target price to start tracking.
```

Preserve the event/query context through signup, land on a one-screen target-price step, and then confirm the watchlist item. Keep the current one-screen form for now; test removing confirm-password only after backend validation and recovery behavior are verified. Add `signup_started`, `signup_completed`, `watchlist_added`, `target_price_set`, and `onboarding_skipped` events.
