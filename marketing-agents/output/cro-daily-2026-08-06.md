## Form Friction Review — Price Alert Setup / Registration Handoff

### Finding

There is no price-alert setup form in `web/src/app/event/[id]/page.tsx` or `web/src/app/watchlist/page.tsx`. `target_price` is displayed when already present, but users have no visible control to create or edit it. This is a missing conversion step, not a form-abandonment problem.

The nearest existing form, registration, has three fields (email, password, confirm password), correct email/password input types, specific client-side password errors, and a loading state. Its error block lacks `role="alert"`, and registration always redirects to `/dashboard`, losing the event context.

### Recommended form spec — P0

```text
Heading: Set a price alert for [Event Name]
Supporting copy: Tell us your max price and we’ll email you when a ticket hits it.
Field: Target price (number, min 1, step 1, inputMode decimal)
Primary button: Set alert
Secondary action: Not now
Success: Alert set. We’ll email you when prices reach $X.
```

For anonymous users, preserve the event ID and target value through registration; then return to this form. Add inline validation (“Enter a price above $0”), a disabled/loading state, and an accessible live-region error. Track `alert_form_viewed`, `alert_started`, `target_price_set`, `alert_skipped`, and `alert_error` without sending raw email or unnecessary search text.
