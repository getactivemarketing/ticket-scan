### Homepage Conversion Review

The value proposition is understandable within five seconds: “Compare. Track. Save.” plus real-time prices and drop alerts. The hero is visually prominent, the CTA is above the fold, and the page includes a product preview, process explanation, testimonials, and repeated CTAs. Mobile layout uses stacked buttons and responsive grids, but a real-device tap/keyboard test is still needed.

#### Recommendations

1. **P1 — Change the primary hero CTA to comparison-first.** Use “Compare Ticket Prices” and route to `/compare` (or `/dashboard` if comparison requires authentication). Keep “Create a free account” as the secondary CTA near the watchlist/alert benefit. This aligns the first click with visitor intent and removes premature account friction.

2. **P1 — Instrument the homepage funnel.** Add typed GTM/dataLayer events for `hero_cta_click` with CTA/location, `compare_view`, `signup_start`, `signup_complete`, `watchlist_add`, and `newsletter_subscribe`; capture `utm_*`, landing page, and referrer. Define a daily report with visitors → search → compare → signup → watchlist denominators.

3. **P2 — Make proof auditable.** Replace the static `$127 Avg. Savings` and “Join thousands” claims with a dated methodology link or live aggregate; otherwise use defensible copy such as “Compare 5+ ticket sites” and “Track price changes over time.”

### Form Friction Check — Newsletter Signup

**Current state:** One required email field; `type="email"` is correctly set and the form has a submit handler. The homepage card uses “Subscribe”; the footer uses “Subscribe” and shows `...` while loading. There is no visible popup implementation in the reviewed source.

#### Form improvement specification

- **Priority P1:** Use action-oriented copy: “Send me ticket deals” for the card and “Get deals” for the footer. Keep the one-field form.
- **Priority P1:** Add a persistent visible label or an accessible name (`aria-label`) in addition to the placeholder; placeholders disappear as soon as the user types.
- **Priority P1:** Replace footer loading `...` with “Signing up…” and disable the field/button consistently. Add `aria-live="polite"` to success and error feedback.
- **Priority P1:** Make errors specific and recoverable: invalid email → “Enter a valid email address”; API failure → “Couldn’t subscribe right now. Try again.” Preserve the entered email on failure.
- **Priority P2:** Add concise expectation-setting near the CTA: “1–2 emails/week · no spam · unsubscribe anytime.” The card already has the latter two ideas; make cadence explicit.
- **Priority P2:** Emit `newsletter_form_view`, `newsletter_submit`, `newsletter_subscribe`, and `newsletter_error` events with `source` (`homepage`/`footer`) and error category.
