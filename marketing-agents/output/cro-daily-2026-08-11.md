### Page-Level Conversion Review — `/compare`

**What works**

- The authenticated page has a clear above-the-fold heading: “Compare Ticket Prices,” with a straightforward benefit statement.
- The primary action is visible in the search card and uses useful copy: “Compare Prices.”
- Search friction is modest: city, keyword, and optional from/to dates; inputs use appropriate text/date controls and labels.
- Results make the consumer value legible: matched listings are shown side by side, fees are surfaced, the lower source is marked “BEST,” and savings are called out.
- Responsive layout stacks the filters and provider cards on smaller screens. A real-device tap and keyboard test remains outstanding.

**Recommendations**

1. **P0 — Let visitors see comparison value before signup.** Remove the unconditional client-side redirect for `/compare`, or show a limited guest comparison with account creation requested only when saving a result or setting an alert. Preserve the query state through any login/register handoff.
2. **P1 — Make the promise more specific above the fold.** Change the supporting copy to “See the same event’s all-in prices side by side—fees included.” Add a compact trust note such as “Ticketmaster + SeatGeek; no ticket purchase required here.”
3. **P1 — Instrument qualified intent.** Emit `compare_view`, `compare_search_submit`, `compare_results_loaded`, `provider_click`, `signup_start`, and `signup_complete`, with auth state, result counts, city, and source. Track zero-result/error outcomes separately.

### Form Friction Check — Newsletter Signup

**Current state:** The shared component uses one required `type="email"` field, which is appropriately low friction. There is no visible label, no `aria-live` status region, no popup variant, and the footer loading state is only `...`. The component clears the email only after success, so failed submissions retain the value.

**Form improvement specification**

- **P1:** Add a visually hidden label and `aria-describedby` pointing to the expectation/privacy note; keep the single email field.
- **P1:** Use action-oriented copy: “Send me ticket deals” for the card and “Get deals” for the footer. Replace `...` with “Signing up…” or “Saving…”.
- **P1:** Add `aria-live="polite"` to success/error feedback and specific recoverable messaging for invalid email vs. API failure.
- **P2:** State cadence explicitly: “1–2 emails/week · no spam · unsubscribe anytime.”
- **P1:** Add popup only if product wants an interruption-based capture; start with exit-intent or delayed display, frequency-cap it, and measure exposure → start → success. Do not claim a popup conversion rate until those events exist.
- **P1:** Emit `newsletter_view`, `newsletter_start`, `newsletter_submit`, `newsletter_success`, and `newsletter_error` with the `source` value (`homepage`, `footer`, `blog`, or popup).
