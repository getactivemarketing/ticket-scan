## Page-Level Conversion Review — Venue Page

Focus page: [MSG venue guide](https://www.ticketscan.io/venues/msg)

### Findings and recommendations

1. **P0 — Make the price-alert value proposition concrete at the primary CTA.** The event CTA currently says “Track Price” and sends visitors directly to `/register`; the page does not explain that a target price is the next step. Change the CTA to “Track this event + set alert,” and add microcopy such as “Free account · choose your target price · get emailed when it drops.”

2. **P1 — Add an above-the-fold comparison action.** The venue hero contains venue facts and home-team badges, but no direct “Compare upcoming events” or event search action. Add a prominent CTA beneath the hero that anchors to Upcoming Events or routes to `/dashboard` with the venue preselected.

3. **P1 — Add trust proof beside the event CTA.** The page has useful seating guidance, but no evidence of freshness or savings near “Track Price.” Add “Prices checked hourly” only if technically true, plus the platforms compared and an “all-in fees” clarification. Avoid unsupported savings claims.

### Page checks

- Performance: **Pass** in a single production sample (0.33s total response, HTTP 200). This is not a full Core Web Vitals measurement.

## Form Friction Check — User Registration

### Current state

- Three fields: email, password, confirm password.
- Email uses `type="email"`, so mobile keyboard behavior is correct.
- Labels are explicit and fields are required.
- Client-side validation catches password mismatch and passwords shorter than 8 characters.
- Submit feedback exists: “Creating account...” plus disabled state.
- API errors are surfaced in a visible error panel.

### Recommendation

**P1 — Reduce perceived commitment and improve password recovery from errors.** Keep the three fields for now, but add password requirements directly under the password label before submission (minimum 8 characters), use `autoComplete="email"`, `autoComplete="new-password"`, and add a password visibility toggle. Change the CTA from “Create account” to **“Create account & track prices”** so the immediate benefit matches the venue CTA. Preserve server-side validation and never expose whether an email already exists.
