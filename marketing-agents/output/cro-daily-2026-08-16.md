### Page-Level Conversion Review — Newsletter/Blog Path

Observed implementation: `/blog` has a clear hero headline and supporting copy, article cards, and a newsletter card near the bottom. Individual posts have a strong registration CTA after the article, quick links in the sidebar, and a footer-style newsletter form in the sidebar. The live `/blog` page returned HTTP 200 with approximately 0.43s total response time from the check location; this is server response time, not a Core Web Vitals measurement.

1. **High priority — Add a primary CTA in the blog hero.** The hero currently explains the value but offers no next action above the fold. Add `Compare ticket prices free` linking to `/compare`, with `Get price-drop alerts` as the secondary CTA. This reduces the SEO-content-to-product handoff gap.
2. **High priority — Move newsletter capture into the article flow.** On post pages, the newsletter form is in the sidebar and may appear below the article on mobile. Add one inline capture block after the introduction or first major section, using the specific promise: `Get price drops and buying tips in your inbox.`
3. **Medium priority — Make proof concrete.** Add one verifiable data point near the CTA, such as the number of marketplaces compared or a recent observed price spread. Avoid unsupported user-count or savings claims.

Mobile note: the newsletter form uses a one-column layout on small screens, which is appropriate. Buttons and inputs have reasonable padding. The blog hero and article CTA should be checked on a real narrow viewport after adding the hero CTA; no automated mobile rendering or Core Web Vitals data is currently available.

### Form Friction Check — Newsletter Signup

- Fields: one email field; good. Do not add name, preferences, or password fields.
- Input: `type="email"` and `required` are correctly implemented. Add `autocomplete="email"`, `inputMode="email"`, and an explicit accessible label (the current UI relies on placeholder text).
- Submit copy: `Subscribe` / `Get Deals` is generic. Test `Get price alerts` or `Send me ticket deals`, matching the concrete value proposition.
- Loading state: the footer changes the button to `...`, which gives weak feedback. Use `Joining...` or `Saving...` while disabling the button.
- Error handling: the API error is shown, but the form has no `aria-live` status region and no field-level guidance for invalid or already-subscribed addresses.
- Trust copy: `No spam, unsubscribe anytime.` is useful and should remain directly adjacent to the submit action in every variant.
- Popup: no newsletter popup component was found, so popup conversion cannot be evaluated and there is no evidence that a popup is active.
