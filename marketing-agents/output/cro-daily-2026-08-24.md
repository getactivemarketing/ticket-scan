### Homepage Review

1. **P1 — Remove the duplicate footer from `page.tsx`.** Keep the shared root-layout footer. This reduces repeated navigation and newsletter CTAs and makes the conversion path intentional.
2. **P1 — Put the primary product CTA closer to the proof.** The hero CTA is visible above the fold and the value proposition is clear within five seconds, but “Get Started Free” sends a new visitor directly to registration before they can see a live comparison. Add a secondary “Compare prices” CTA to `/dashboard` or `/compare` and test it against registration-first traffic.
3. **P2 — Make proof more credible.** “50K+ Events Tracked,” “$127 Avg. Savings,” and “Join thousands” lack a timeframe or methodology. Add “last 30 days,” a sample size, or a link to the methodology; unsupported precision can reduce trust for a price-sensitive audience.

Mobile observations: the hero stacks cleanly and buttons are tappable-sized; the newsletter form stacks below the `sm` breakpoint. The duplicate footer and repeated newsletter forms are especially wasteful on mobile scroll depth.

### Newsletter Form Review

Current implementation: one email field, `type="email"`, `required`, async loading state, success state, and an API error state. An empty test submission correctly returned `{"success":false,"error":"Valid email address required"}` without creating a subscriber.

- **P1 — Add a visible label and privacy expectation.** The form relies on placeholder text (`Enter your email...`) and only the card variant says “No spam, unsubscribe anytime.” Use a persistent label or accessible visually-hidden label and consistent consent copy in every variant.
- **P1 — Improve failure recovery.** Preserve the entered email on API failure and use a clear retry CTA/state. The current catch path shows an error but gives no explicit recovery instruction beyond trying again.
- **P2 — Standardize CTA copy by intent.** Prefer “Get ticket deals” for the card/inline form and “Get deals” for the footer; reserve “Subscribe” for contexts where the newsletter itself is the product. Keep the loading state (“Joining…” or “Saving…”), not an ellipsis-only button in the footer.
- **P2 — Instrument source and states.** Emit `newsletter_view`, `newsletter_submit`, `newsletter_success`, and `newsletter_error` with `source` (`homepage`, `footer`, `site-footer`) so popup/footer/card performance can be compared.
