### Page-Level Review: Event Detail

Observed in source and live deployment:

- **Primary CTA above the fold: no.** The authenticated page opens with “Back to Watchlist”; there is no prominent “Compare prices,” “Buy tickets,” or “Set target price” action in the event-detail view.
- **Value proposition: partial.** The page can show trend, recommendation, estimated section pricing, and history, but only after authentication and successful API requests. The logged-out state explains none of that value.
- **Friction: high for acquisition.** Direct event links are converted into a generic login step. The event ID/name is not carried into the login/register copy.
- **Social proof: absent.** No watch count, price-check freshness, savings figure, or “last checked” reassurance is visible in the event-detail shell.
- **Performance: pass at network level.** Direct HTTP requests returned 200 in approximately 0.33s for the event route, 0.33s for register, and 0.43s for the homepage. This is not a substitute for a mobile browser/LCP measurement.
- **Mobile/accessibility note:** the page uses responsive containers and a skeleton loading state. The watchlist sign-up prompt has `role="dialog"`, but the source comment acknowledges no focus trap or focus restoration.

### Recommended Changes

1. **P0 — Instrument the funnel before optimizing it.** Add one shared client tracking helper and fire `search_initiated`, `compare_clicked`, `signup_completed`, `watchlist_added`, and `newsletter_subscribed` with event ID/source/page metadata. Verify in GTM Preview and GA4 DebugView.
2. **P1 — Make event detail useful before login.** Render a read-only event header (name, venue, date, starting price, and freshness) for logged-out visitors, then place “Compare prices” and “Track this event” CTAs beside the login/register prompt. Preserve the event ID through auth.
3. **P1 — Give authenticated users one next action.** Add a prominent “Compare prices” CTA and “Set a target price” control above the chart. After watchlist creation, ask for a target price in the same flow instead of requiring a second discovery step.

### Watchlist Add / Sign-Up Prompt — Form Friction Review

- **Fields:** 0 for logged-in users; this is good. Anonymous users get a two-action prompt with no fields until they choose sign-up.
- **Labels and copy:** “Track This Event” and “Create a free account to track prices and get alerts when they drop” are clear, but they promise price-drop alerts while the live alert/reporting path is currently not verifiable.
- **Submit/action copy:** “Sign Up Free” is clear and action-oriented. “Maybe Later” is a reasonable low-friction escape.
- **Mobile input:** not applicable before registration; the registration email field correctly uses `type="email"`.
- **Loading/error state:** logged-in add has a disabled loading state and `role="alert"` error. Anonymous prompt has no loading state because it only links to registration.
- **Accessibility:** the icon-only watchlist button has an accessible label, but visible “Track” text would improve discoverability. Add focus trapping/restoration to the dialog.

Form spec: change the post-sign-up onboarding to **“Track this event” → optional target price → “Save alert”**, with a skip link labelled **“Track without a target price.”** Only use “price alert” copy once the tracker and alert delivery are confirmed healthy.
