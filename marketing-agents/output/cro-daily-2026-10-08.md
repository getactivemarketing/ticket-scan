## Form Friction Check

### Focus form: Watchlist add / save-event flow

There is no standalone watchlist-add modal or supported price-alert setup in
the current usable flow. `EventCard` uses a one-click API call for logged-in
users and an overlay for logged-out users.

Observed friction:

- The authenticated control is icon-only (eye/check); it has an accessible
  label but weak visual discoverability and no visible confirmation copy beyond
  the icon state.
- The request saves the event but does not collect a target price. Do not add a
  price-alert step until alert delivery and current price data are working.
- The logged-out overlay says “Track This Event,” but the registration link
  drops the event id and return path.
- Duplicate or API failures surface a generic “Failed to add” message rather
  than explaining whether the event is already saved or what to do next.

Improvement specification:

- Use a visible, truthful action label: **“Save event”** or **“Add to
  watchlist.”**
- After success, show: **“Saved to your TicketScan watchlist. View saved
  events.”** Link directly to `/watchlist`.
- Pass a safe return path and event payload through registration; after signup,
  complete the save once and avoid asking the visitor to repeat the search.
- Map duplicate responses to **“Already saved — view watchlist”** and keep
  retryable network errors inline beside the control.
- Keep the existing email field type and required validation; add loading text
  that describes the action, such as **“Saving…”**, not an ellipsis-only state.
