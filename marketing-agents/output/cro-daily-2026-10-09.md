## Page-Level Conversion Review — Friday Focus

### Focus page: Madison Square Garden venue guide — `/venues/msg`

Madison Square Garden is the established high-intent venue proxy from prior CRO
reports and popular-events data; the admin API does not provide page-traffic
rankings, so it is not claimed to be the objectively highest-traffic venue.

Live request checks on October 9:

- `/venues/msg`: HTTP 200, ~0.34s
- `/register`: HTTP 200, ~0.40s
- `/compare`: HTTP 200, ~0.28s
- `/dashboard`: HTTP 200, ~0.31s

The venue page has strong venue-specific content: capacity, home-team context,
seating sections, event dates, seller links, and a city-events link. The event
rows place a seller action beside “Save Event,” which is a sensible high-intent
layout.

Prioritized recommendations:

1. **P0 — Rewrite stale save/registration language.** The template’s fallback
   description says TicketScan “tracks” onsales, while event-card and related
   surfaces still imply price tracking. Use supported language: “Save this event
   for onsale details” or “Keep event details handy.”
2. **P1 — Clarify the primary action.** Keep the external seller link as the
   primary purchase action and add a short disclosure that it opens the seller.
   Make “Save Event” visibly secondary and explain what saving preserves.
3. **P1 — Put the next onsale/presale fact near the first event list.** The page
   already has useful venue facts, but the first viewport is dominated by the
   hero and heading. A verified onsale date/time would give cold visitors an
   immediate reason to continue without relying on unsupported price claims.

Mobile/accessibility follow-up: validate that the seller and save actions are
comfortable 44px touch targets and remain distinct when event rows wrap.

## Form Friction Check — Friday Rotation

There is no separate supported price-alert setup form in the current frontend.
The closest live conversion form is registration (`/register`), which has
three fields: email, password, and password confirmation.

Observed issues and spec:

- Replace **“Start tracking ticket prices today”** with **“Save events and stay
  ahead of onsale dates.”**
- Add a visible password requirement hint before submit: minimum 8 characters.
- Add `autocomplete="email"` and `autocomplete="new-password"` to the
  appropriate fields; retain `type="email"` for the email keyboard on mobile.
- Keep the existing loading state, but make the post-submit destination clear:
  search an event, then save it for onsale information.
- Preserve event intent through registration (`next`/safe return path) so a
  visitor does not have to repeat the venue or event search.
- Keep target-price and price-alert copy out of this flow until current price
  data and delivery are verified.

The newsletter form is structurally low friction: one required email field,
correct email input type, and a loading state. Its copy should remain focused
on onsale/presale dates and venue tips.
