### Anomalies

- **P1 — measurement blind spot:** GTM is present, but the frontend does not
  emit the CRO event taxonomy. Visitors, search starts, result renders,
  seller clicks, compare runs, bounce, source, and device performance cannot
  be evaluated or compared day over day.
- **P1 — event-detail conversion break:** the live `/event/demo` request
  returned HTTP 200 in 0.33s, but the route is a client-authenticated
  watchlist lookup. `page.tsx` calls `getWatchlist()`, finds an event by ID,
  and otherwise shows “This event is no longer in your watchlist.” The page
  has no event search/fetch path, seller URL, or outbound seller CTA. The
  only useful event-detail path is therefore a saved-event path, not a
  public event-detail landing page.
- **P1 — status-conflicting copy:** registration still says “Start tracking
  ticket prices today,” and the empty watchlist still says “Get notified the
  moment it drops.” Price tracking and drop alerts are currently down; these
  claims should be removed or replaced with onsale/presale and saved-event
  language before traffic is sent to registration.
- **P2 — alert endpoint:** `/api/admin/alerts` remains unavailable in the
  analytics snapshot, so alert volume cannot be validated. This is not used
  as a live conversion metric.

### Event-Detail Page Review

| Check | Result | CRO implication |
|---|---|---|
| Primary CTA above the fold | Fail for the intended public use case | A public event visitor gets no event content or seller action; the route redirects unauthenticated users to login. |
| Value proposition in 5 seconds | Fail | The authenticated view shows event metadata and generic “Event details,” but no current seller link or next action. |
| Friction | High | Event data is fetched indirectly from the entire watchlist and requires authentication. |
| Social proof | Not present | No verified, non-price proof point is shown. Do not add unsupported user or savings claims. |
| Load speed | Pass for initial HTML | Live shell response was 0.33s; this does not validate authenticated client/API completion. |
| Mobile usability | Risk | The route has basic responsive spacing, but there is no mobile-specific seller CTA to test. |

#### Recommendations

1. **P0 — make event detail a real event route.** Accept an event ID from
   discovery, load the event record/details independently of the watchlist,
   render date/venue/city plus the available seller link, and keep the
   authenticated save action as a secondary CTA. Acceptance test: a logged-out
   user opening a valid event URL sees the event and can reach the seller in
   one tap; a logged-in user can save it without leaving the page.
2. **P1 — replace the dead-end detail copy.** Until the full route exists,
   change the saved-event detail panel to a clearly labeled “Open seller
   page” CTA backed by a persisted seller URL, or remove “View Details” from
   watchlist rows when no URL is available. Do not imply live TicketScan price
   intelligence.
3. **P1 — instrument the route and outbound action.** Add deduplicated
   `page_view`, `event_card_view`, `save_event_click`, `save_event_success`,
   and `seller_outbound_click` events with event ID, page, source page, and
   auth state; exclude PII and wait for seven days of integrity checks before
   publishing rates.

### Watchlist Add / Sign-up Form Review

The “form” is currently a save button plus an overlay, not a conventional
form. The authenticated path has zero fields; the unauthenticated path links
to registration.

| Check | Result | Recommendation |
|---|---|---|
| Number of fields | Pass | Keep saving field-free; defer account creation until intent is clear. |
| CTA clarity | Fail | The primary control is an eye-only icon. Add visible “Save event” text at desktop and mobile widths. |
| Sign-up message | Mixed | “Create a free account to save this event” is clear and status-safe. Keep it. |
| Error feedback | Partial | Inline `role="alert"` exists, but the generic “Failed to add” fallback gives no recovery guidance. Use “Couldn’t save this event. Check your connection and try again.” |
| Loading state | Partial | The button disables and shows `...`; use an explicit “Saving…” accessible label/status. |
| Mobile input behavior | N/A | No fields in this flow. Registration correctly uses `type="email"`; add `autocomplete="email"` and password autocomplete attributes. |
| Modal accessibility | Fail | The component comment confirms there is no focus trap or focus restoration. Move focus into the dialog on open and back to the trigger on close. |
| Product-status safety | Fail elsewhere | Remove price-alert language from registration/watchlist empty states; do not add a price-alert CTA. |

#### Form recommendation

**P0:** Change the icon-only save control to a visible, action-oriented
“Save event” button with a short status message after success: “Saved — find
it in your watchlist.” Preserve the eye icon as a supporting visual, not the
only affordance. Add focus management to the sign-up dialog.
