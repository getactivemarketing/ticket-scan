### Newsletter Form Review

Component: `web/src/components/NewsletterSignup.tsx`.

What works:

- One required field; no unnecessary data collection.
- `type="email"` enables the correct mobile keyboard.
- Loading, success, and error states exist.
- Source attribution is sent to the API without needing another user-facing field.

Recommendations:

- **P1 — add form semantics:** `name="email"`, `autoComplete="email"`, and an `aria-live="polite"` status region for success/error feedback.
- **P1 — make the loading state consistently explicit:** the footer currently changes the button to `...`; use “Subscribing…” or an accessible busy label in every variant.
- **P1 — use benefit-led but status-safe button copy:** keep “Subscribe” where space is tight; for the card/inline variants prefer “Send me ticket tips” or “Get onsale dates.” Avoid “Get Alerts” where it could be read as a price-drop promise.
- **P2 — preserve source in conversion telemetry:** emit a newsletter-success event only after a successful response, carrying `source` but never the email address.
