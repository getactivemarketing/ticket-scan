### Page-Level Conversion Review — Homepage

Evidence: live `/` response, `web/src/app/page.tsx`, `web/src/components/Navbar.tsx`, and `web/src/components/Footer.tsx`.

1. **P1 — make the first CTA promise match the current product.** The hero is clear within five seconds (“Events, venues and onsale dates”) and has a visible “Get Started Free” CTA, but the supporting text still says “Search events across the major ticket platforms.” Recommended status-safe variant: “Find events, check onsale and presale dates, and keep your ticket research in one place.” Keep the primary action as “Find Events” or “Get Started Free.”
2. **P1 — add an early discovery path for visitors who are not ready to register.** The homepage gives registration priority but does not offer a neutral “Search Events” CTA in the hero. Add a secondary link to `/dashboard` beside the account CTA; the dashboard can be used before signup and is the shortest path to product value.

Do not use price-alert or price-monitoring language.

### Newsletter Form Review

Component: `web/src/components/NewsletterSignup.tsx`, reviewed in the footer and homepage card variants.

What works:

- One required field; no unnecessary data collection.
- `type="email"` supports the correct mobile keyboard.
- Loading, success, and error states exist.
- The source label is sent to the API without exposing a second user-facing field.

Recommendations:

- **P1 — add semantics:** `name="email"`, `autoComplete="email"`, and an `aria-live="polite"` status region for success/error messages.
- **P1 — remove ambiguous alert wording.** The inline variant says “Get Alerts.” Use “Get ticket tips” or “Get onsale dates” so the CTA cannot be read as a price-drop promise. The footer heading “Get Onsale Alerts” should be changed to “Get Onsale Dates & Tips” if the team wants the most conservative interpretation.
- **P1 — make loading state consistent and accessible.** The footer button changes to `...`; use “Subscribing…” plus `aria-busy` or an equivalent busy state across all variants.
- **P2 — add conversion telemetry only after success.** Emit a `newsletter_success` event carrying the `source` value, never the email address. Add an error event with a normalized error class, not the raw address or response body.
- **P2 — set `autoComplete="email"` on every variant.** This is a small mobile completion improvement and is currently missing.
