## Form Friction Review — Watchlist Save / Sign-up Prompt

This is a save action plus an overlay, not a conventional form.

### What works

- Authenticated save requires no extra fields.
- The guest prompt explains that an account is needed and offers a single sign-up path plus “Maybe Later.”
- The component has a loading/disabled state and an error region on the authenticated API path.
- The email/password registration form uses native `type="email"`, required fields, and client-side password checks.

### Friction and recommendation

- **P0 — The sign-up link loses event intent.** `EventCard.tsx` links to bare `/register`; it does not pass the event ID or a return path. After registration, `register/page.tsx` always routes to `/dashboard`. Preserve the originating event and return the user to a concrete “Save this event” confirmation.
- **P1 — Rename “Track This Event” to “Save This Event.”** This is clearer, status-safe, and matches the actual action.
- **P1 — Make the button copy action-oriented.** Use **“Create account to save”** or **“Save this event”** rather than relying on a generic “Sign Up Free” link with no context.
- **P1 — Add accessible dialog behavior.** The overlay declares a dialog but does not move focus into it, trap focus, or restore focus on close. Add focus management before testing conversion; keyboard users should not tab behind the modal.
- **P2 — Add form semantics and measurement.** Add `name`, `autoComplete`, and explicit `signup_prompt_viewed`, `signup_prompt_click`, `signup_success`, `save_event_click`, and `save_event_success` events with source surface and event ID only. Exclude email and JWT values.
