### Page-Level Conversion Review — MetLife Stadium

Observed from source and deployed HTML:

- **Value proposition:** Clear within five seconds: “MetLife Stadium Tickets,” location, capacity, upcoming events, seating sections, and onsale-oriented metadata. The title is specific: “MetLife Stadium Tickets - Seating Guide and Onsale Dates.”
- **Primary CTA:** Above-the-fold hero has no action button. The first actionable area appears below the hero, where “Resale tickets” and “Save Event” sit beside each event.
- **CTA hierarchy:** Each event card has two peer actions. “Resale tickets” is the transactional outbound action; “Save Event” is the account-creation action. For anonymous users, Save Event routes to `/register`, adding a decision and context switch.
- **Trust/proof:** Venue capacity, home teams, seating sections, event dates, affiliate disclosure, FAQs, and a sitewide footer disclosure are present. No measurable user count, testimonial, or verified conversion proof is shown.
- **Performance:** Deployed HTTP checks returned 200. Total response time was approximately 0.43s for MetLife; this is a server/request check, not a Core Web Vitals measurement.
- **Mobile:** The event action row wraps with `flex-wrap`, and the hero/nav use responsive classes. The venue page remains information-dense; the two adjacent actions should be tested at 320–375px widths for wrapping and thumb reach.

#### Recommendations

1. **P1 — Add a single above-the-fold intent bridge.** Add a compact hero CTA such as “See upcoming events” anchored to the event list, with a secondary “Browse seating guide” anchor. This gives visitors an immediate next step without promising unavailable price features.
2. **P1 — Clarify event-card action order and copy.** Make “View resale tickets” the primary action and rename “Save Event” to “Save to watchlist” (or “Save this event”) with a short sign-in/create-account explanation. Test whether a single primary button plus a text save link reduces hesitation and increases completed registration.
3. **P2 — Add transparent availability framing.** Where price is `TBA`, use “Availability and checkout total shown by seller” beside the outbound CTA. This sets expectations without inventing TicketScan price data.

### Form Friction Review — Newsletter Signup (footer variant)

Current implementation (`web/src/components/NewsletterSignup.tsx`):

- One required email field; `type="email"` correctly enables the email keyboard.
- No visible label associated with the input; placeholder is the only field cue.
- Submit copy is generic “Subscribe”; loading feedback is “...” only.
- Success and error messages are rendered, but no conversion event is pushed.
- The footer heading says “Get Onsale Alerts,” while the inline variant says “Get Alerts.” The latter can be confused with unavailable price alerts.

#### Form improvement specification

- Add a visually-hidden `<label htmlFor>` and a stable input `id`; retain the placeholder as an example, not the label.
- Change ambiguous copy to **“Get onsale updates”** or **“Join the free onsale list”**. Use the same wording across footer, inline, and card variants.
- Replace the loading ellipsis with **“Joining…”** and keep the button disabled during submission.
- Add `aria-live="polite"` to success/error status text and preserve focus context after submission.
- Push a `newsletter_subscribe` event only after the API returns `success: true`, including `source` and page path; do not send the email address to analytics.
