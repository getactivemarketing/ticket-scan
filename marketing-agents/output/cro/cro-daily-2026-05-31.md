## Page-Level Review — Newsletter / Blog Conversion Path

I traced the full blog→newsletter path in code. **The path is broken by design: the only working newsletter form on the entire site lives on the homepage. Every newsletter CTA off the homepage is a dead-end redirect.** This fully explains Agent 7's 0-of-90 newsletter conversion (Day 119).

**Evidence (verified in source):**
- `NewsletterSignup` is imported/rendered **only** in `web/src/app/page.tsx` (homepage: line 285 card, line 314 footer-variant block). It appears on **no other page**.
- The global `web/src/components/Footer.tsx` — rendered on every page including all blog pages — has **no email capture at all**. (The component supports a `variant="footer"` form, but it is never mounted in the global footer.)
- `web/src/app/blog/page.tsx:170` — the "Get Ticket Tips in Your Inbox → Subscribe Now" CTA is `<Link href="/">`. It dumps the reader on the homepage instead of capturing email.
- `web/src/app/blog/[slug]/page.tsx:223` — sidebar "Get More Tips → Subscribe" is also `<Link href="/">`. Same dead-end.

**Friction cost:** a blog reader who wants to subscribe must click the CTA → land on the homepage → scroll to find the form → re-form their intent → type their email. Each hop sheds users; on mobile it's worse. We are routing warm, high-intent blog traffic into a cold homepage and losing it.

### Recommendations (priority order)

1. **🔴 P0 — Replace blog "Subscribe" redirects with an inline form.** Drop `<NewsletterSignup variant="inline" source="blog" />` directly into the blog-index CTA (`blog/page.tsx:163-175`) and the blog-post sidebar (`blog/[slug]/page.tsx:220-224`). Capture email *on the page the reader is already on*. Zero new infra — the component and `/api/newsletter/subscribe` endpoint already exist. **This is the single highest-leverage blog-path fix and directly attacks the Day-119 zero.**

2. **🔴 P0 — Add the newsletter form to the global Footer.** Mount `<NewsletterSignup variant="footer" source="footer" />` in `components/Footer.tsx` (it's built for exactly this and currently unused). This gives every page — venue, city, World Cup, blog, event — a persistent capture point instead of only the homepage. Single highest-leverage *site-wide* fix.

3. **🟡 P1 — Add a newsletter opt-in checkbox to registration.** `app/register/page.tsx` has no newsletter field, so 90 post-launch signups produced 0 subscribers. A pre-checked (or clearly-labeled) "Email me ticket deals & price-drop alerts" checkbox wired to `/api/newsletter/subscribe` converts the warmest audience we have. (Matches Agent 7's standing #2 fix.)

## Form Friction Check — Newsletter Signup (footer variant)

Reviewed `NewsletterSignup.tsx` `variant="footer"` (lines 45-77).

| Check | Status | Note |
|-------|--------|------|
| Field count | ✅ 1 (email only) | Optimal — no friction |
| `type="email"` | ✅ | Triggers email keyboard on mobile |
| Visible label | ⚠️ Placeholder-only | Relies on "Get Ticket Deals" heading; acceptable for a 1-field form |
| Submit copy | ⚠️ "Subscribe" | Generic. The `inline` variant uses **"Get Deals"** (benefit-oriented) — adopt that here |
| Loading state | ⚠️ "..." | Present but cryptic; "Sending…" reads clearer |
| Error feedback | ✅ | Red message rendered below form |
| Success state | ✅ | Replaces form with confirmation |
| Trust microcopy | ⚠️ Missing | `card` variant shows "No spam, unsubscribe anytime." — footer variant omits it; add it |

**Form recommendations:**
- **Change footer button copy "Subscribe" → "Get Deals"** (benefit framing, consistent with the inline variant). Low-effort, applies everywhere the form is mounted.
- **Add "No spam, unsubscribe anytime." microcopy** under the footer form to match the card variant and reduce hesitation.
- **Caveat:** none of these form tweaks matter until the form is actually *mounted* off the homepage (P0 #1 and #2 above). **Placement beats copy here — fix placement first.**
