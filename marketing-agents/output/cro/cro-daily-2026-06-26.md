## Page-Level Review — Venue Page Template (`/venues/[slug]`)

Analyzed the shared template in `web/src/app/venues/[slug]/page.tsx`. Findings apply to all 24 venue pages. Using MSG/Kia Center/Chase Center as representative examples since no traffic ranking is available.

### CTA Visibility Above the Fold

**Mobile (< 1024px):** The hero section shows venue name, city/capacity, and home team badges — no CTA visible above the fold. The first actionable element is the event cards in the main content column. The sidebar CTA card ("Track Ticket Prices → Start Free") is inside `lg:col-span-1` — **invisible on all mobile devices** until the user scrolls past all events and the About section. For a visitor arriving on mobile (estimated 50–60%+ of search traffic), there is **no conversion entry point above the fold**.

**Desktop (≥ 1024px):** The sidebar CTA is visible on first load, but it's an unauthenticated registration push with no prior value delivery. A visitor who just arrived sees "Start Free" before they've seen a single price comparison.

### Value Proposition Within 5 Seconds

The hero communicates what the VENUE is (`{venue.name} Tickets · {city}, {state}`), not what TicketScan does. No tagline or sub-heading explains: "we compare prices across Ticketmaster, SeatGeek, and more." A visitor arriving from Google search for "MSG tickets" sees a venue guide but no clear reason to register vs. clicking the "Buy Tickets" external link on the first event card.

### Friction Points

1. **"Track Price" → `/register` wall.** Every event card has a "Track Price" button that links to `/register` (line 261). Users must register before seeing a single price comparison. There is no try-before-register path. The compare page (`/compare`) is also login-gated (confirmed: `compare/page.tsx` line 87-90 redirects to `/login`). Net result: a user can "Buy Tickets" externally or be forced to register — there is no middle path.

2. **No price comparison on the venue page.** The page fetches events from the public API and shows a `minPrice`, but no multi-source comparison (e.g., "Ticketmaster: $85 · SeatGeek: $79 · Save $6"). This is TicketScan's core value prop and it's absent on venue pages.

3. **Empty state is silent.** When there are no events (`events.length === 0`), the empty state says "No upcoming events found" with a link to register (line 272-280). A newsletter capture ("Get notified when events are announced") would be more appropriate and higher-converting here.

### Social Proof

**None present.** No user count ("132 users tracking events here"), no reviews, no "X people watching this event." Social proof is completely absent on venue pages, which are entry points for cold organic traffic that needs trust signals before registering.

### Mobile Experience

- Tappable elements (event cards, "Track Price" button) are adequately sized
- The sidebar CTA is hidden on mobile — **primary conversion path absent on mobile**
- No sticky mobile CTA bar exists; once user scrolls past event cards, there is no re-entry point to convert

### Seating Section Guide

Shows relative multipliers (`~1.0x base`, `~1.5x base`) with no concrete price reference. This is opaque. A concrete heuristic ("Upper Bowl: typically $30–60 for most events") would be more useful and could include a "Set a price alert" CTA inline.

## Form Friction Check — Watchlist Add Flow (EventCard)

Today's rotation: watchlist add. Reviewed `web/src/components/EventCard.tsx`.

| Check | Status | Finding |
|-------|--------|---------|
| Entry point visibility | ✅ | Eye icon button is present on every event card |
| Field count | 🔴 **0 fields** | No target price input — the watchlist add is a single button click |
| Target price | 🔴 **Missing** | `api.addToWatchlist()` (line 43-49) sends no `targetPrice`. Alerts can never arm. |
| Feedback on add | ✅ | Button changes to green checkmark after add |
| Loading state | ✅ | Disabled during `adding` state |
| Error message | ✅ | Shown below button if API fails |
| Anon flow | ✅ | Shows sign-up overlay instead of silently failing |
| Upsell copy in anon overlay | ⚠️ | Says "Track prices and get alerts when they drop" — but alerts are currently broken |

**Root cause of 0 active alerts (confirmed):** `EventCard.tsx:43-49` sends `{ eventId, eventName, eventDate, venue, city }` — no `targetPrice`. The API's `POST /api/watchlist` accepts `target_price`, but the UI never sends it. 160 watchlist items exist and every one of them has `target_price = NULL`.

**Fix spec:**
Add a target price input to the watchlist add flow. Minimum viable version: an optional number input that appears after clicking the eye icon (before actually adding), with a "Set price alert" label and a "Skip / Add without alert" escape hatch.

```tsx
// Add state
const [showPriceInput, setShowPriceInput] = useState(false);
const [targetPrice, setTargetPrice] = useState('');

// Modify handleAddToWatchlist to show input first for logged-in users
// Then pass targetPrice to api.addToWatchlist({ ..., targetPrice: parseFloat(targetPrice) || undefined })
```

This is the **#1 funnel fix** — it enables the product's core alert value prop and turns 160 idle watchlist items into potential revenue-generating alerts.
