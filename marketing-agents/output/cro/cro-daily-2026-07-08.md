## Page-Level Review: Dashboard/Search (`/dashboard`) — Wednesday Focus

Source reviewed: `web/src/app/dashboard/page.tsx`, `web/src/components/EventCard.tsx`

### CTA visibility above the fold ✅ / ⚠️

The search form is immediately visible on load. The anon-user banner ("Track prices and get alerts when they drop!") appears above the form with a "Sign Up Free" CTA — this is correct placement. However, the banner disappears once results render (it's inside the `!user` conditional that's part of the pre-search layout). A user who searches first, *then* wants to track an event has to rely solely on the EventCard overlay, which requires a click to even see the prompt.

**Finding:** The auth nudge disappears after search results load. Anon users in the results state only encounter the signup prompt when they click the eye icon — which is an icon with no label, not a clear invitation.

### Value proposition within 5 seconds ⚠️

The pre-search state shows a logo, "Find your next event", and three static blog tiles. There is no stated value prop for why to search here vs. Google or Ticketmaster directly. The dashboard lacks a one-liner that answers: "Why TicketScan instead of Ticketmaster?" Something like: "Search Ticketmaster + SeatGeek in one shot — we flag when prices drop" would do it.

The auth banner has the value prop buried: "Track prices and get alerts when they drop" is the hook, but it appears only for anon users and competes visually with the gradient background.

### Friction points

**[P1 — NEW] Default city 'Orlando' on dashboard**

`page.tsx:28`: `useState('Orlando')`

The dashboard has the same pre-filled city bug flagged for the compare page. A visitor from any non-Florida city sees a stale default. It reads as a test fixture left in production. Fix: `useState('')` and update the placeholder to `"e.g., Orlando, Miami, New York"`.

Effort: trivial. Risk: zero.

**[P1 — CARRY-OVER] Watchlist adds with no target price — alerts never arm**

`EventCard.tsx:43-49`: `api.addToWatchlist(...)` sends no `targetPrice`.

The dashboard is the primary surface where users add to watchlist (168 adds total), yet there is no target price input anywhere in the flow. The product's core promise — "get alerted when prices drop to your target" — is structurally impossible. Every watchlist add is inert.

This was first flagged weeks ago and remains unshipped. The fix (a target price input on the EventCard or a post-add modal) is small; the impact on retention and activation is large.

**[P1 — NEW] Watchlist watch icon has no text label**

`EventCard.tsx:169`: The button renders `👁️` (anon) or `✓` (added).

There's no text. Screen readers get an empty button. Sighted users who don't recognize the icon won't click. Changing to `"Track Price"` (or `"Track"` if space is tight) would make the CTA explicit and likely double click-through on the watchlist CTA. After add, showing `"Tracking"` instead of `"✓"` reinforces the value.

Effort: trivial (3-character change per state).

**[P2] Search button right-aligned, not full-width on mobile**

`page.tsx:136`: `<div className="flex justify-end">` wraps the Submit button.

On mobile (single column layout), right-aligned is less ergonomic than full-width. The button is not large enough for comfortable thumb-tapping. Standard pattern: `w-full` on mobile, right-aligned on `sm:` breakpoint.

```tsx
// Change:
<div className="flex justify-end">
// To:
<div className="flex justify-end">
  <button ... className="w-full sm:w-auto bg-brand ...">
```

**[P2] No event detail link on EventCard**

EventCard renders two actions: "Buy Tickets" (external) and `👁️` (watchlist). There is no link to `/event/[id]` for users who want to see price history or the buy/wait recommendation before committing. The event detail page exists but is orphaned — not reachable from search results. Users who don't want to buy immediately and don't know about watchlist have nowhere to go.

Fix: Make the event name a link to `/event/${event.id}` (for logged-in users, or add anon preview as previously flagged).

**[P2] No "Compare Prices" path from search results**

After a search, users see EventCards with no way to compare prices across sources. The entire `/compare` flow is siloed — no entry point from the dashboard. A "Compare" link or button on EventCard would create a natural discovery path from the highest-traffic search surface into the core differentiator.

### Social proof ❌

The dashboard has zero social proof: no "146 users tracking prices", no "168 events tracked today", no testimonials. Adding a single stat ("Join 146 ticket trackers — get alerts when prices drop") to the anon banner would increase signup conversion without any design work.

### Mobile experience ⚠️

The 4-column grid (`lg:grid-cols-4`) on desktop collapses correctly to 1 column. The date picker is native — fine. The main mobile issue is the right-aligned search button (see above) and the small eye-icon target for the watchlist CTA (icon-only buttons are below the 44px tap target recommendation).

## Form Friction Review: Watchlist Add Flow (EventCard inline)

Today's form focus: the watchlist add interaction, which is the key in-dashboard conversion action.

| Check                                     | Status | Notes |
|-------------------------------------------|--------|-------|
| Field count                               | 0     | No fields — user just taps the icon. No input at all |
| Target price field                        | ❌    | Not present anywhere in flow |
| CTA clarity                               | ❌    | `👁️` icon with no label — not self-explanatory |
| Feedback after add                        | ⚠️    | Shows `✓` + green — but no explanation of what happens next |
| Error state                               | ✅    | Red error text shown below card |
| Loading state                             | ✅    | Shows `...` while adding |
| Anon gate                                 | ✅    | Overlay prompt shown — good pattern |
| Post-add next step                        | ❌    | No prompt to set target price or visit watchlist |
| Value reinforcement after conversion      | ❌    | No "We'll email you when prices drop" confirmation |

**Recommendation — P1: Add a target price prompt after watchlist add**

Currently: click `👁️` → API call → `✓`. Done.

Proposed: click `Track Price` → API call → success state shows "Added! Set a target price to get email alerts." with a small inline input or a link to the watchlist page.

This is the minimum change to unlock the core value proposition. Without a target price, 168 existing watchlist items generate 0 alerts. The fix doesn't require a new modal — a post-add inline prompt on the card is enough:

```tsx
// After setAdded(true):
// Show a small inline row:
{added && (
  <div className="mt-2 flex items-center gap-2 text-sm">
    <span className="text-green-700">Tracking!</span>
    <Link href="/watchlist" className="text-brand underline text-xs">Set target price →</Link>
  </div>
)}
```

This is not a full fix (the watchlist page also needs a target price edit input), but it creates a path for motivated users.

**Recommendation — P2: Rename icon button to text**

```tsx
// Change:
{added ? '✓' : adding ? '...' : '👁️'}
// To:
{added ? 'Tracking' : adding ? '...' : 'Track Price'}
```
