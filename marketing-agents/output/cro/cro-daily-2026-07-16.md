## Page-Level Review: Event Detail Page (`/event/[id]`) — Thursday Focus

Source reviewed: `web/src/app/event/[id]/page.tsx`, `web/src/components/BuyRecommendation.tsx`, `web/src/components/EventCard.tsx`

### CTA visibility above the fold ❌

There is **no purchase CTA on this page at all.** The event detail page shows a buy/wait/hold recommendation — the highest-intent moment in the entire product — and provides zero link to actually buy tickets. A user who sees "Good Time to Buy" has nowhere to act on it within the page. They must navigate away, find the event again on the dashboard, and click "Buy Tickets" on the EventCard.

This is a direct conversion leak at the moment of peak intent.

### Value proposition within 5 seconds ⚠️

For the rare user who reaches this page, the value is clear once data loads: price chart, trend indicator, BuyRecommendation. However, price history is empty platform-wide (`price_history` table returns 0 rows — see memory note). The overwhelming majority of users land on the "Price tracking just started" empty state. That state's copy ("First price check will happen within the next few hours") is potentially misleading given price tracking is not functioning at the platform level. The page reads as broken, not as a feature in progress.

### Friction points

**[P0 — NEW] No "Buy Tickets" link after recommendation**

`page.tsx:227-237` — `BuyRecommendation` renders but `BuyRecommendation.tsx` has no purchase link anywhere in it.

After displaying "Good Time to Buy" with current price, lowest recorded, and days until event, the user has zero way to act. There is no "Buy on Ticketmaster →" or "Buy on SeatGeek →" button. The event URL exists in Ticketmaster API responses; it needs to be threaded through to this page and surfaced as a CTA next to the recommendation.

Minimum viable fix: add an optional `eventUrl` prop to `BuyRecommendation` and render a "Buy Now →" button when the action is `buy_now`.

**[P1 — NEW] Login redirect loses event context (no returnUrl)**

`page.tsx:110` — `router.push('/login')` sends the user to `/login` with no `?returnUrl` parameter.

If a direct link to `/event/abc123` is shared (via blog, social, or email alert), unauthenticated users get redirected to `/login`. After logging in, they land on the homepage, not the event. Their context is lost. The fix is one line:

```tsx
// Change:
router.push('/login');
// To:
router.push(`/login?returnUrl=/event/${eventId}`);
```

Then `login/page.tsx` needs to read `returnUrl` and redirect after successful auth (standard pattern, small effort).

**[P1 — CARRY-OVER] Page completely orphaned — no entry point from EventCard or search**

`EventCard.tsx:121-124` — The event name renders as a plain `<h3>` with no link. The only route into `/event/[id]` is from `/watchlist`. Users on the dashboard who search for events, see results, and want to investigate price history or buy recommendations have no path to this page.

This was flagged on 07-08 and remains unshipped. Given that this page is where the BuyRecommendation lives, it's also where the purchase link would land. The event detail page can't convert what it can't attract.

Fix: wrap event name in `EventCard.tsx:121-124` with `<Link href={`/event/${event.id}`}>` for logged-in users.

**[P1] Back navigation hardcoded to /watchlist**

`page.tsx:188-196` — `href="/watchlist"` is hardcoded.

If this page gains additional entry points (from search results, blog, shared links), the back button will always dump the user into their watchlist, not where they came from. Replace with `onClick={() => router.back()}` or a smarter referrer check. At minimum, the back label "Back to Watchlist" is only accurate when the user arrived from /watchlist.

**[P2] Empty state copy is misleading**

`page.tsx:343-352` — "First price check will happen within the next few hours" is shown for all events with 0 price history.

Given that price tracking is not functioning at the platform level (0 rows in price_history, confirmed), this message is inaccurate. Users who see it will check back and see the same message repeatedly, eroding trust. The copy should be honest about the delay or replaced with a "Notify me when data is available" micro-CTA.

**[P2] No target price editor on event detail page**

`BuyRecommendation.tsx:120-124` — Target price is displayed read-only (`Your target price: $X`).

The event detail page is the natural place to adjust a target price after seeing current market data. There's no edit affordance. A user seeing "Current: $145 / Your target: $200" has no way to update the target without leaving to the watchlist page. An inline edit input here would keep the user in context.

### Social proof ❌

No social proof on the event detail page. A "You're one of N people tracking this event" line next to the event header would create urgency and validate the user's interest.

### Mobile experience ⚠️

The stats grid in `BuyRecommendation.tsx:89` uses `grid-cols-2 sm:grid-cols-4` — correct responsive collapse. The price history table (`page.tsx:277-334`) has `overflow-x-auto` which handles overflow, but 5 columns on mobile is still dense. The back link and header are well-sized. Main mobile issue: "Buy Tickets" doesn't exist anywhere, so mobile has the same conversion gap as desktop.

## Form Friction Review: BuyRecommendation Component

Today's form/component focus: `BuyRecommendation.tsx` — the primary decision surface on the event detail page.

| Check                                     | Status | Notes |
|-------------------------------------------|--------|-------|
| Primary CTA present                       | ❌    | No purchase link anywhere in component |
| Action clarity                            | ✅    | "Good Time to Buy" / "Consider Waiting" / "Monitor Prices" — clear labels |
| Confidence signal                         | ✅    | High/Medium/Low badge present |
| Reason text                               | ✅    | Reason string shown below title |
| Stats shown                               | ✅    | Current, Lowest, Highest, Days Until Event grid |
| Savings potential shown                   | ❌    | No "X% below average" or "You could save $Y vs. highest" |
| Source breakdown                          | ❌    | No "Ticketmaster: $145 / SeatGeek: $138" comparison |
| Target price editable                     | ❌    | Read-only display only |
| CTA after buy_now recommendation          | ❌    | Missing entirely |

**Recommendation — P0: Add purchase CTA to BuyRecommendation when action is `buy_now`**

The component needs an `eventUrl?: string` prop. When passed and action is `buy_now`:

```tsx
{action === 'buy_now' && eventUrl && (
  <a
    href={eventUrl}
    target="_blank"
    rel="noopener noreferrer"
    className="mt-4 inline-block bg-green-600 hover:bg-green-700 text-white px-6 py-3 rounded-lg font-bold transition-colors"
  >
    Buy Tickets Now →
  </a>
)}
```

The event page already fetches recommendation via `api.getBuyRecommendation(eventId)` — the API response can include `eventUrl`. Alternatively, store `event.url` when the event is added to watchlist (it's available at add time in EventCard).

**Recommendation — P2: Add savings line to stats grid**

After the 4-stat grid, one line:

```tsx
{stats && stats.highestRecorded > stats.currentPrice && (
  <p className="mt-2 text-sm text-green-700">
    You're seeing prices {Math.round((1 - stats.currentPrice / stats.highestRecorded) * 100)}% below peak.
  </p>
)}
```

This converts abstract price numbers into an actionable framing ("23% below peak") that mirrors how deal-seekers think.
