### Page-Level Conversion Review: Newsletter/Blog Path

**Pages reviewed:** `/blog` and `/blog/best-time-to-buy-concert-tickets` (valid production smoke check). Production responses were HTTP 200 at approximately 0.44s and 0.35s respectively; this is server response time, not a Core Web Vitals measurement.

1. **P1 — Move or duplicate the blog-index newsletter CTA above the article list.** The blog hero states the content value proposition, but the first newsletter form appears after all featured and regular articles (`web/src/app/blog/page.tsx:179-182`). Many users will never reach it. Add a compact inline capture directly below the hero, preserving the existing end-of-page card as a secondary CTA.
2. **P1 — Make the primary next step on each article explicit and intent-matched.** The article CTA currently sends users to `/register` with “Create Free Account” (`web/src/app/blog/[slug]/page.tsx:191-196`), while the sidebar newsletter form is below/alongside long-form content (`:199-226`). Add a two-option block: “Compare prices free” → `/dashboard` and “Get deal alerts by email” → newsletter form, with source attribution.
3. **P2 — Add proof without inventing claims.** The blog and newsletter components contain no testimonials, subscriber count, recent savings example, or data freshness signal. Add a verified proof line such as the number of marketplaces compared only if the backend integration is live, plus a small “No spam. Unsubscribe anytime.” reassurance in the article form variant.

**Checklist:**

- Primary CTA above the fold: **Fail on blog index**; the article hero has no CTA until after content.
- Value proposition within five seconds: **Pass**, but it is generic and does not state the newsletter benefit or cadence.
- Friction: **Low field count** (email only); CTA placement and unclear newsletter-vs-alert promise are the main friction points.
- Social proof: **Missing**.
- Performance: **No server-response issue observed**; measure LCP/INP/CLS in real-user analytics.
- Mobile: **Generally sound**—responsive layouts use stacked forms and the email input is correctly typed; article sidebar CTA should be duplicated inline for mobile rather than relying on the sidebar’s position.
