### Page-Level Conversion Review: `/dashboard`

**Priority 1 — Add a comparison action to search results.** The page has a clear above-the-fold “Search Events” form and a non-authenticated signup banner, but `EventCard` only offers “Buy Tickets” plus an unlabeled eye-icon watchlist control. A successful search can therefore end without discovering `/compare`. Add an explicit “Compare prices” CTA to each result and preserve the event/query context.

**Priority 1 — Make the first search lower-friction.** The form exposes four fields (city, event/artist/team, from date, to date) and defaults to Orlando. Keep dates optional, but provide a popular-search example or suggested event and change the primary copy to “Find Cheapest Tickets” / “Compare Prices” so the immediate value is clearer than the generic “Search Events.”

**Priority 2 — Improve activation handoff.** The logged-out banner says “Create a free account,” but the post-registration destination is the generic dashboard. Send new users to a short checklist: choose an event → add to watchlist → set a price ceiling. The current product promise is price tracking, so the first session should complete that loop.

**Checklist:**

- Value proposition within five seconds: **Partial**, “Find your next event” is clear, but comparison/savings value is not prominent on the search surface.
- Friction: **Needs work**, four inputs and no suggested search; compare is not discoverable from results.
- Social proof: **Partial**, the signup banner explains the benefit but has no verified usage or savings proof.
- Performance: **No server-response issue observed** — production returned HTTP 200 in ~0.29s for `/dashboard`; this is not a Core Web Vitals measurement.
