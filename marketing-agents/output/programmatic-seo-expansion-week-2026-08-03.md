# Programmatic SEO Expansion Plan — 2026-08-03

## Decision

Do not launch a large batch of thin combinations yet. First strengthen the data contract and templates, then launch the three page types below in order. Every new page must have a unique primary entity, current event inventory or a durable first-party data point, a clear update date, and at least three meaningful internal links.

| Rank | Page type | Search potential | Difficulty | Template feasibility | Data requirement | Recommendation |
|---|---|---:|---:|---:|---|---|
| 1 | `/artist/[slug]` and `/team/[slug]` | High | High | High | Entity identity, aliases, upcoming events, normalized venue/city, price history | Pilot with 20–30 entities already present in API results; merge artist/team templates behind a shared entity model. |
| 2 | `/best-time-to-buy/[category]` | Medium-high | Medium | High | Historical price snapshots by category, days-to-event, sample size, methodology | Launch 5 categories first: concerts, NFL, NBA, MLB, theater. Publish confidence/sample-size notes, not unsupported universal claims. |
| 3 | `/compare-guides/[platform-a]-vs-[platform-b]` | Medium-high | Medium-high | High | Fee policy, inventory type, buyer protection, like-for-like examples, current update date | Build editorial comparison hubs for Ticketmaster, SeatGeek, StubHub, and Vivid Seats. These are more defensible than autogenerated event pages. |
| 4 | `/tickets/[city]/[venue-or-category]` | Medium | Medium | Medium | Venue-city mapping, event API results, unique local copy | Launch only for cities with multiple venues and enough inventory; avoid creating 24 × 25 combinations by default. |
| 5 | `/compare/[event-slug]` | High when inventory exists | High | Medium | Stable event IDs, live multi-source listings, canonical event name/date, availability | Use only for high-volume, stable events. Add expiry/noindex handling when the event passes or inventory disappears. |
| 6 | `/tickets/[seasonal-intent]` such as NFL playoffs or festivals 2026 | Medium | Medium | High | Category taxonomy, current season dates, live inventory, freshness workflow | Good editorial/programmatic hybrid. Create only when the season is active and seed with substantial original guidance. |

## Template specifications

### Entity page: artist/team

- Title: `[Entity] Tickets: Compare Prices, Track Drops & Upcoming Events`.
- H1: `[Entity] Tickets`.
- Above fold: next events, lowest observed price, source coverage, last checked time, and “track price” CTA.
- Sections: upcoming events, price history, best time-to-buy summary, venues/cities, FAQs, related entities.
- Structured data: `Person` or `SportsTeam`, `Event`/`ItemList` only for real future events, `BreadcrumbList`.
- Guardrails: no page for an alias without a distinct entity; no fabricated popularity or price claims; expire pages with no event and no editorial demand.

### Best-time-to-buy guide

- Title: `Best Time to Buy [Category] Tickets — Data-Backed Guide`.
- H1 answers the query in one sentence, followed by “how we calculated it.”
- Include median/percentile movement by days-to-event, sample size, observation window, source coverage, exceptions, and a CTA to set an alert.
- Never state a single universal buying day without confidence intervals or a qualification.

### City + venue/category

- Use a real hierarchical route only when the page adds local information: transit/venue context, competing venues, event inventory, and local price observations.
- Canonicalize only one URL per intent. Do not let query parameters or alternate slug spellings create indexable duplicates.
- Link parent city, venue, category, and at least two related pages.

### Event comparison

- Require stable event ID and date; render identical seat/section comparison where possible.
- Show price timestamp, fees/all-in status, source, availability, and a clear disclaimer that external checkout can change.
- Return 404 or `noindex` after a documented retention window; remove expired pages from sitemap.

## Recommended launch sequence

1. Post-event World Cup cleanup and evergreen hub repair.
2. Data-backed `/best-time-to-buy/` pilot.
3. Artist/team entity model and 20-page pilot.
4. Compare-platform editorial hub.
5. Only then test high-volume event comparison pages.

## Acceptance criteria

- No generated page has fewer than 500 useful words unless the live data itself is the primary value and the page still has unique analysis.
- Every page has a canonical, indexability state, last-updated date, source/methodology note, and parent/child links.
- Automated checks fail builds when a sitemap URL is missing a generated route or when an expired event remains indexable.
- Monitor indexed pages, impressions, CTR, conversions, and “no events” rate by template for 28 days before scaling.
