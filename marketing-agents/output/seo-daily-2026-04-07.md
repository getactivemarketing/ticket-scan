## Schema Markup Validation

### 1. `/venues/[slug]/page.tsx` — FIXED ✅
**Issue:** Page emitted `@type: "EventVenue"`, which is **not a valid schema.org type**. Google ignores invalid types, so venue rich-result eligibility was effectively zero across all 24 venue pages.

**Fix applied:** Switched to `StadiumOrArena` (for arena/stadium types) or `PerformingArtsTheater` (theaters), based on `venue.type`. Added `description` and canonical `url` fields.

**File:** `web/src/app/venues/[slug]/page.tsx:97-112`

**Follow-up:** Validate one URL post-deploy via Google Rich Results Test:
- https://www.ticketscan.io/venues/kia-center
- https://www.ticketscan.io/venues/madison-square-garden

**Still missing (next iteration):**
- `geo` (lat/lng) — requires lat/lng fields in `web/src/data/venues.ts`
- `streetAddress` and `postalCode`
- `event[]` array of upcoming events (would need to inline events fetched in `getVenueEvents`)

### 2. `/faq/page.tsx` — OK ✅

### 3. `/world-cup-2026/**` — MAJOR GAP ⚠️
**Issue:** Neither `/world-cup-2026/page.tsx` nor `/world-cup-2026/[stadium]/page.tsx` emit ANY structured data. 17 high-intent landing pages have zero schema → losing eligibility for `SportsEvent` rich results during the highest-traffic search window of 2026.

**Recommended schema:** `SportsEvent` per match (or per stadium, listing matches as sub-events) with:
- `name`, `startDate`, `endDate`
- `location` → `Place` with stadium address
- `competitor` → home/away teams
- `offers` → priceRange + url to TicketScan compare page
- `eventStatus: EventScheduled`
- `eventAttendanceMode: OfflineEventAttendanceMode`
