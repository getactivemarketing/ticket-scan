## Schema Markup Validation (Today's Rotation: World Cup Stadium + Venue Pages)

### World Cup Stadium Pages (`/world-cup-2026/[stadium]`)
**Schema type:** `StadiumOrArena` + nested `SportsEvent`
**Issues found:**
1. **AggregateOffer missing `lowPrice`/`highPrice`** — Google requires these for price-related rich results. Currently only has `priceCurrency` and `availability`. **FIX APPLIED** ✅
2. **Missing `image` property** — StadiumOrArena schema should include an image for richer search appearance. No images in data model currently — deferred to content team.
3. `SportsEvent` has tournament-level dates (June 11 – July 19) rather than per-match dates. Acceptable for tournament pages but could be more granular.

### Venue Pages (`/venues/[slug]`)
**Schema type:** `StadiumOrArena` or `PerformingArtsTheater`
**Issues found:**
1. **Missing `image` property** — Same as WC pages, no image URLs in venue data.
2. **No event listings in schema** — Events are fetched dynamically but not included in JSON-LD. Could add `event` array when events are available.
3. Schema otherwise valid: has name, description, URL, PostalAddress, capacity.

### World Cup Main Page (`/world-cup-2026`)
**Status:** Client component (`'use client'`) — inherits metadata from `layout.tsx` which has proper title, description, keywords, and OpenGraph tags.
**Gap:** No page-level JSON-LD schema (e.g., `SportsEvent` for the tournament itself). Not critical since metadata is inherited, but would improve rich results eligibility. **Logged for future fix.**
