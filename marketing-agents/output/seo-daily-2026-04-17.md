## Technical Fix Applied

**Fix:** Resolved broken `/logo.png` reference in root `Organization` JSON-LD (carryover blocker from yesterday).

**Root cause:** `web/src/app/layout.tsx:76` emits `"logo": "https://ticketscan.io/logo.png"` in every page's Organization schema, but `web/public/` had no `logo.png` — only SVG icons. Schema.org logo validation would fail, and Google's knowledge-panel eligibility logic silently excludes Organizations whose `logo` URL 404s.

**Implementation:**
- Copied the existing 512×512 `ticketscan_appicon_512_v2.png` (the app icon from `logos /`) to `web/public/logo.png`
- File: 220 KB, PNG, 512×512, RGBA — well above Google's 112×112 minimum for Organization logo
- No code changes needed; the schema already points at the correct URL

**Why 512×512:** Google's Organization logo guidelines require the image to fit in a 600×60 box after scaling. 512×512 is the recommended square size for downstream flexibility (favicons, OG defaults, knowledge-panel display).

**Verification:**
- `npm run build` → 115/115 routes, no errors
- Built HTML confirmed: `grep '"logo":"https://ticketscan.io/logo.png"'` hits every page (homepage + all static routes)
- `file web/public/logo.png` → valid PNG, 512×512

**Files changed:** `web/public/logo.png` (new binary asset only; no source code changes)

**Deployment note:** This ships automatically with the next Vercel deploy since it lives in `public/`. No schema file changes needed.
