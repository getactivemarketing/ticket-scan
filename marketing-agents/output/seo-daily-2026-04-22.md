## Technical Fix Applied

**Fix:** Refactored `/tickets/[slug]` JSON-LD to emit a unified `@graph` of `ItemList` + `BreadcrumbList` on **both** city and category branches. This directly addresses yesterday's "HIGH" action item, which called out that category pages were shipping a bare `ItemList` container with no items — rendering the rich result ineligible for all 13 category pages (including high-value `/tickets/nba`, `/tickets/nfl`, `/tickets/concerts`).

**What changed in `web/src/app/tickets/[slug]/page.tsx` (lines 150–188, now ~42 lines of JSON-LD):**

1. **Hoisted `itemListElement` out of the ternary** — the same `events.slice(0, 5).map(...)` array is now used for both city and category pages. The mapping emits `@type: Event` with `name`, `startDate`, `location: Place` (with nested `PostalAddress.addressLocality`), and `offers: AggregateOffer` (with `lowPrice` + `priceCurrency`) for every event that has a minPrice.

2. **Added `@id` to `ItemList`** — `https://ticketscan.io/tickets/{slug}#itemlist` — anchors the entity for cross-schema reference and Google's entity graph.

3. **Added `numberOfItems`** — Schema.org recommends this on `ItemList`; clarifies the list is finite and indicates size to indexers.

4. **Added `BreadcrumbList`** — Home → Events/Tickets → [Slug Name]. Differentiates breadcrumb second-tier text per branch:
   - City pages: "Home → Events → Orlando"
   - Category pages: "Home → Tickets → NBA Tickets"

5. **Unified shape** — both branches now return an `@graph` with two entities (`ItemList` and `BreadcrumbList`) under a single `@context`. Parallel to the `/blog/[slug]` `@graph` structure shipped 2026-04-18.

Spot-checked **StubHub's `/tickets/nba` analog** and **SeatGeek's `/nba-tickets` page** as today's rotation matches the fix:

- **StubHub:** Emits `ItemList` only on their venue listing pages, not on sport-category pages. Their `/nba-tickets` category page carries `WebPage` + `BreadcrumbList` + a separate `FAQPage` but no `ItemList`. Our new approach is strictly more specific: a populated `ItemList` with `Event` items is directly eligible for Google's Event carousel rich result, which StubHub is forfeiting.
- **SeatGeek:** Emits `ItemList` on category pages (✓) and includes `BreadcrumbList` (✓). Their `itemListElement` entries carry `Event` with `offers.priceSpecification` (section-level pricing) rather than `AggregateOffer.lowPrice`. **Takeaway:** Once our public API exposes section-level pricing on the events list endpoint (already exists on `/api/events/compare`'s tier breakdowns), we should upgrade `offers` from `AggregateOffer` → per-section `PriceSpecification` array.
