### `/admin` — **noindex check → BEFORE TODAY'S FIX WAS FAILING**

**Before today's fix (prior built HTML):**
```
<meta name="robots" content="index, follow"/>
```

This is a **real production-leak risk**: `/admin` is disallowed in `robots.txt`, but robots.txt blocks *crawling*, not *indexing*. If Google discovers the URL via an external link (or via a sitemap inclusion anywhere), it can still index the URL as a bare "URL not crawled because of robots.txt" entry. The admin dashboard is client-rendered behind a login, so even an index-only URL leak is mostly cosmetic — but it's a signal of a misconfigured site to crawlers, and it pollutes search results for the ticketscan.io domain.

**After today's fix (current built HTML):**
```
<meta name="robots" content="noindex, nofollow, nocache"/>
```

**Same issue confirmed on `/watchlist` and `/favorites`:** both have `<meta name="robots" content="index, follow"/>` in the built HTML despite being auth-walled. These should also carry `noindex` — see "Action Items" (HIGH).

**Rich-result eligibility:** N/A (and that's the point).

## Technical Fix Applied

**Fix:** Added `web/src/app/admin/layout.tsx` — a 15-line wrapper layout that sets `robots: { index: false, follow: false, nocache: true, googleBot: { ... } }` on the `/admin` route. Mirrors the layout-override pattern already used on `/compare/layout.tsx` (2026-04-19) and `/dashboard/layout.tsx` (2026-04-21).

**Why a layout rather than page metadata:** `web/src/app/admin/page.tsx` is a `'use client'` component, and Next.js disallows `metadata` exports from client components. The thin server-component layout wrapper is the canonical Next 16 fix. Already the pattern of record in this codebase for every client-rendered page that needs server metadata.

**Verification (built HTML before vs. after):**

| File | Before | After |
|------|--------|-------|

## Competitor Insight

Spot-checked how StubHub and SeatGeek handle their own admin-adjacent / auth-walled URLs (since today's rotation flagged the issue on `/admin`):

- **StubHub:** `/my-tickets`, `/orders`, and `/account/*` all return `X-Robots-Tag: noindex` at the HTTP header level in addition to `<meta name="robots" content="noindex">`. This is a belt-and-suspenders pattern — the HTTP header catches cases where meta isn't rendered (e.g., API responses, redirects). **Takeaway (LOW):** Could add `x-robots-tag: noindex` to the Vercel headers config for `/admin`, `/watchlist`, `/favorites` as a second layer. Not urgent, but a nice defense-in-depth touch.

- **SeatGeek:** `/my-events`, `/account` — same pattern. They also put `/admin/*` under an entirely different subdomain (`admin.seatgeek.com`) which is a stronger isolation pattern we can't easily adopt post-hoc without redirects.

- **Both competitors:** Keep FAQ and Help Center pages explicitly `index, follow` with `FAQPage` schema. Our `/faq` is already correctly indexed (rotation pass from earlier this week confirmed) but still lacks `BreadcrumbList` — noted below.
