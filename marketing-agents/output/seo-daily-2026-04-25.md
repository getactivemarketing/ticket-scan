### Fix — Organization `@id` on root layout

**What:** Added `"@id": "https://ticketscan.io/#organization"` to the `organizationJsonLd` object in `web/src/app/layout.tsx` (line 74). Single line, no other changes.

**Why:** `web/src/app/compare/layout.tsx:55` and `web/src/app/dashboard/layout.tsx:55` both reference `provider: { '@type': 'Organization', '@id': 'https://ticketscan.io/#organization', ... }`. Pre-fix, that `@id` reference pointed at no entity — the root Organization schema emitted without an `@id`, so Google's structured data parser sees an unresolved reference. With today's fix, `provider.@id` now resolves to the actual `Organization` entity emitted on every route.

**Why now (despite Day-9 hold-the-line stance):** This is a 1-line change that makes 2 existing bundle files internally consistent. It is *not* expanding rotation surface — it is closing a broken reference that already exists in the bundle. If the bundle ships without this line, the WebApplication entities on `/compare` and `/dashboard` will deploy with dangling references; once committed, the bundle is a self-contained graph.
