## Competitor Insight

Spot-checked SeatGeek's `/compare` competitive equivalent (`/promocode-and-coupons` deep-funnel page) and StubHub's `/help/sell` deep-funnel page — both emit a single consolidated `@graph` on every route via what looks like a global layout component. Specifically:

- **SeatGeek's deep-funnel routes** carry `Organization` + `WebSite` + `BreadcrumbList` in one `@graph`, identical across `/`, `/promocode-and-coupons`, `/sell`, etc. Per-page entities (Article, Event, FAQPage) get appended to this global graph rather than emitted as a separate JSON-LD block.
- **StubHub's deep-funnel routes** do the same thing: `Organization` + `WebSite` (with `publisher` reference back to Organization) on every page.

**Takeaway:** Both competitors confirm the architecture pattern that yesterday's Organization `@id` fix and today's WebSite-relocation flag are converging toward: **canonical Organization + WebSite entities emitted from the root layout, page-level entities reference them via `@id`.** Once today's WebSite-relocation flag is implemented (next commit, NOT today), our schema graph will match the SeatGeek/StubHub structural pattern — no more, no less. There is no further competitor-research surface left to mine on this question. Today's competitor check confirms the destination; the bundle just has to ship to reach it.
