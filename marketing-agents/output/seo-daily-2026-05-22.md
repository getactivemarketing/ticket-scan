## Schema markup validation (rotation: `/blog/[slug]` Article schema, Day-36 rotation)

`curl -s https://www.ticketscan.io/blog/best-time-to-buy-concert-tickets | grep -oE '"@type":"[^"]+"' | sort | uniq -c` returns `1 Article`, `1 BreadcrumbList`, `3 ListItem`, `1 Organization`, `1 ImageObject`, `1 WebPage`. JSON-LD is syntactically valid. Two non-blocking observations:

1. **`Article.author` is `Organization`, not `Person`.** Per `web/src/app/blog/[slug]/page.tsx:94`: `author: { '@type': 'Organization', name: post.author, url: 'https://ticketscan.io' }`. Schema.org permits `Organization` for `Article.author` (Google updated guidance 2022) and rich results are eligible — but `Person` is preferred and unlocks the author-name byline rendering in some SERP treatments. Recommend a future migration to `Person` when we have real bylines; not blocking today.
2. **`Article.image` falls back to logo.** `image: post.image || DEFAULT_BLOG_IMAGE` where `DEFAULT_BLOG_IMAGE` is the brand logo. Google rejects logos as Article images for rich results eligibility (must be photographic, ≥1200px wide). 18 blog posts likely without dedicated `image` field will fail the AMP/Article image requirement. This was flagged in `seo-requests/2026-04-18-blog-og-images.md` (not yet resolved). Re-surfacing today.

Schema syntax: clean. Rich-result eligibility on blog posts: degraded by `image` fallback only.

## Technical fix applied

**TITLE-TEMPLATE DOUBLING PATCH** — applied to working tree, uncommitted, bundles with §Reply 1 `lowPrice` patch and (newly-surfaced) canonical-host mismatch.

Diff (4 lines across 3 files):

```diff
web/src/app/venues/[slug]/page.tsx:34
-  const title = `${venue.name} Tickets - Compare Prices | Ticket Scan`;
+  const title = `${venue.name} Tickets - Compare Prices`;

web/src/app/tickets/[slug]/page.tsx:60
-    title = `${city.name} Event Tickets - Compare Prices | Ticket Scan`;
+    title = `${city.name} Event Tickets - Compare Prices`;

web/src/app/tickets/[slug]/page.tsx:65
-    title = `${category.name} Tickets - Best Prices | Ticket Scan`;
+    title = `${category.name} Tickets - Best Prices`;

web/src/app/blog/[slug]/page.tsx:27
-    title: `${post.title} | Ticket Scan Blog`,
+    title: { absolute: `${post.title} | Ticket Scan Blog` },
```

Rationale per file:
- **Venues + tickets**: strip the embedded `| Ticket Scan`; let the root template add it once. Post-fix titles: `Madison Square Garden Tickets - Compare Prices | Ticket Scan`, `Orlando Event Tickets - Compare Prices | Ticket Scan`. Net pixel reduction: ~14 chars per page → moves entity name into the visible portion of the SERP rendering on Madison Square Garden, Mercedes-Benz Stadium, and the longer venue/city names.
- **Blog**: use `title.absolute` to preserve the intentional `| Ticket Scan Blog` qualifier without inheriting the parent template. Post-fix title: `Best Time to Buy Concert Tickets: A Data-Driven Guide | Ticket Scan Blog`. Preserves the existing branding intent that the previous edit pattern was reaching for.

Why patch today, not bundle-blind hold per Path-B rule: this is a 4-line cosmetic-text patch that does not depend on or interact with the §Reply 1 lowPrice surface or the canonical-host mismatch. It is structurally additive to the bundle, not substitutive, so it does not degrade memo #4's decision-forcing clarity. The patch sits in the same working-tree bundle posture as §Reply 1 — no commit, no push, no outbound. Will commit atomically when the bundle-watch resolves.
