## Errors found

### CORRECTION — Title-template "doubling" defect from 5/22 report does NOT reproduce on live production

Yesterday's report claimed 72 production pages serve doubled `| Ticket Scan` suffixes in `<title>`, citing curl evidence. **Re-verified today, the doubling does not exist:**

| URL | Live `<title>` (curl, 2026-05-23 10:06 UTC) |
|---|---|
| `/venues/msg` | `Madison Square Garden Tickets - Compare Prices \| Ticket Scan` |
| `/tickets/orlando` | `Orlando Event Tickets - Compare Prices \| Ticket Scan` |
| `/blog/best-time-to-buy-concert-tickets` | `Best Time to Buy Concert Tickets: A Data-Driven Guide \| Ticket Scan Blog` |

Each title has exactly ONE suffix. The committed HEAD code in `web/src/app/venues/[slug]/page.tsx:34` does pass a string `${venue.name} Tickets - Compare Prices | Ticket Scan` to the metadata API, and `web/src/app/layout.tsx:35` does set `template: "%s | Ticket Scan"`. Per my reading of the Next.js metadata API spec, those two should compose to produce a doubled suffix. They empirically do not. Most likely explanations: (a) Next.js 16 applies template-suffix detection/dedup that I was unaware of, (b) some build-time Vercel optimization, or (c) the spec behavior differs from what I expected. I haven't found a definitive doc for which.

**Implication for the working-tree patch in 5/22 bundle:** The 4-line edit to `venues/[slug]/page.tsx`, `tickets/[slug]/page.tsx`, and `blog/[slug]/page.tsx` (strips embedded suffix or wraps in `title.absolute`) is fixing a defect that does not appear in production output. Post-patch behavior: identical-looking titles (the layout template would add the suffix that was just removed). Net effect: cosmetic refactor at best, possible regression risk on the `blog/[slug]` page where `title.absolute` would prevent ANY future parent-template application. **Recommendation: pull this patch out of the working-tree bundle.** It was a fix-for-a-fake-defect based on yesterday's analytical error. The `blog/[slug]` Article-schema improvements and OG-image fallback (also in that same working-tree change) are legitimate and should stay — only the title-string edits revert.
