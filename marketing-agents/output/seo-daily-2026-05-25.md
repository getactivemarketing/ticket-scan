The deployed Vercel build is **not the same code as `origin/main`**. Verified by:

1. `git show HEAD:web/src/app/blog/[slug]/page.tsx` — lines 79–88 show the pre-patch flat `articleJsonLd` object (no `@graph`, no `image`, no `BreadcrumbList`, no `keywords`, no `articleSection`).
2. Live HTML from `https://www.ticketscan.io/blog/world-cup-2026-final-ticket-10990-dynamic-pricing?_cb=$(epoch)` shows post-patch JSON-LD structure — full `@graph`, `BreadcrumbList`, `image: https://ticketscan.io/logo.png`, `keywords`, `articleSection`, `publisher.logo.@type: ImageObject`.
3. Cache check: `x-vercel-cache: HIT` with `age: 46s` on cache-busted URL — Vercel built fresh HTML for the random query-string URL and the build emitted the patched JSON-LD. Same result on 2nd post (`best-time-to-buy-concert-tickets`) and 3rd post (`avoid-ticket-scams`).
4. Local `git ls-files --error-unmatch` confirms the file is tracked. `git hash-object` on working tree = `274227f5` (post-patch). HEAD blob differs.
5. `git rev-parse HEAD origin/main` returns identical SHA `50dbcd3` — local main is up to date with origin/main.

**Conclusion:** Either (a) the patches were applied to the deployed build via Vercel CLI / preview promotion without a git commit, or (b) Vercel is configured to pull from a non-main source (branch, fork, or non-repo path). Either path is a process defect — production state cannot be derived from the canonical git history. This breaks the assumption underlying every "bundle is frozen" framing in escalations #1–#4.

**Equally important:** the divergence is **partial**. The `lowPrice` patch in `world-cup-2026/[stadium]/page.tsx` is **not** live — `curl -s https://www.ticketscan.io/world-cup-2026/att-stadium?_cb=...` still returns `"lowPrice":15000`, identical to 5/24. Same fetch shows `mercedes-benz-stadium = 10000`, `lumen-field = 8000`, `levis-stadium = 6000` — unchanged from 5/10 baseline. So whoever deployed the blog patches did so selectively, not by promoting the full working tree.

**Action required:** Architect (or whoever owns the deploy pipeline) needs to (1) confirm what production is actually built from, (2) commit the live-but-uncommitted blog patches to main to restore source-of-truth, (3) explain why `lowPrice` wasn't included in the same selective deploy.
