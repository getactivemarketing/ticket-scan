## 2. Technical Fix Applied

**Bug:** Capital One Arena venue page generated a broken city link.

**Root cause:** `web/src/app/venues/[slug]/page.tsx` was deriving the city slug from `venue.city.toLowerCase().replace(...)`. For "Washington" that produces `washington`, but the city page in `cities.ts` is keyed `washington-dc`. The breadcrumb in the JSON-LD and two in-page anchor links all pointed to a 404.

**Impact:**
- Broken internal link from a Domain-Authority-bearing venue page to a city hub page — hurts crawl depth and link equity flow.
- JSON-LD `BreadcrumbList` containing a 404 URL is an invalid structured-data signal (Google's Rich Results Test would mark it as a warning/error).
- Same wrong URL was duplicated in the hero breadcrumb and "More in Washington" sidebar link.

**Fix:**
1. Added optional `citySlug` field to the `Venue` interface in `web/src/data/venues.ts:13` so venue → city mappings can override the default kebab-case slug rule.
2. Set `citySlug: 'washington-dc'` on `capital-one-arena`.
3. Updated `web/src/app/venues/[slug]/page.tsx` to use `venue.citySlug || venue.city.toLowerCase().replace(/\s+/g, '-')` in three places: JSON-LD breadcrumb, hero breadcrumb anchor, sidebar "All {City} Events" anchor.

`npx tsc --noEmit` passes. Other 23 venues unchanged (their city values still slug correctly).

## 3. Opportunities Logged

### High value, low effort
- **Event schema on venue pages.** The page already fetches up to 10 upcoming events. Emitting one `Event` node per event (name, startDate, location, offers with priceCurrency + lowPrice) makes each venue page eligible for event rich results in SERPs — a big visibility win for queries like "Lakers tickets" or "Beyoncé Crypto.com Arena". Sent to Content Agent backlog.

### Medium value
- **Blog `Article` author should be `Person`, not `Organization`.** Better E-E-A-T signal for AI Overviews and Discover. Requires adding a writer profile (name, optional bio link). Defer until we have named author bylines.

### Latent fragility (no current break)
- Venue page used `replace(' ', '-')` (single-space only) in body links, while the JSON-LD used `replace(/\s+/g, '-')` (all whitespace). Today's fix routes both through the same `citySlug` variable, so any future multi-space city will not silently produce two different URLs. Pattern worth re-using on the World Cup stadium page (`replace(' ', '+')` for the dashboard keyword query has the same single-space-only flaw, but no current stadium city has more than one space so it's not breaking anything yet).
