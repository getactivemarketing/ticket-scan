## Schema markup validation (rotation: `/event/[id]` event-detail page — Day-43 rotation)

**Audit target:** `web/src/app/event/[id]/page.tsx` (first rotation through this template).

**Findings:**
- **Rendering:** `'use client'` (line 1) — fully client-rendered. No SSR'd structured data; any schema would not be in the initial HTML for crawlers.
- **Schema present:** **None.** No `application/ld+json`, no `@type`, no metadata export.
- **Indexability:** `robots.ts:9–14` disallows `/event/` (alongside `/watchlist`, `/api/`, `/admin`). The page is intentionally excluded from crawl.

**Verdict: correct as-is, no fix owed.** This is a dynamic, auth-aware detail page (price history, buy recommendation, watchlist actions) — appropriately noindex and appropriately schema-free. The interesting observation: `/event/[id]` is the page type that most *naturally* maps to Google's single-Event rich result (one event + price + offer), yet it's deliberately not the SEO surface. The Event-rich-result opportunity is correctly delegated to the **SSR** `/venues/[slug]` and `/tickets/[slug]` pages — which is exactly why closing the per-event-schema gap on those two templates (below) is the right lever, not trying to index `/event/[id]`.

## Technical fix applied

**File:** `web/src/app/tickets/[slug]/page.tsx`

1. Extended the `Event` interface with `url?`, `image?`, `state?` (optional — defensive against events missing them).
2. Enriched the ItemList per-event `Event` node:
   - `eventStatus: 'https://schema.org/EventScheduled'` (constant)
   - `eventAttendanceMode: 'https://schema.org/OfflineEventAttendanceMode'` (constant)
   - `image` / `url` spread in only when present (from API)
   - `location.address.addressRegion` from `event.state`
   - `offers.availability: 'https://schema.org/InStock'` and `offers.url` (deep link) when `minPrice` exists

All additions use conditional spreads so no `undefined`/empty fields are ever emitted (avoids structured-data warnings). Schema continues to derive from the **deduped** `events` array, keeping JSON-LD in sync with visible content.

**Verification:** `./node_modules/.bin/tsc --noEmit` from `web/` → exit 0, no errors.
