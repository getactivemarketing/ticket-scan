## 1. Index & Crawl Health — live verification

Live HTTP checks (today):

| URL | Status | Note |
|---|---|---|
| `https://ticketscan.io/` (apex) | **307 → www** | Apex redirects to www for *every* path |

| `https://www.ticketscan.io/sitemap.xml` | **200** | Served; but **emitted apex URLs** (now fixed in source) |

| `https://www.ticketscan.io/llms.txt` | **404** | Not present (low priority, logged §3) |

**The issue:** production resolves to **www** (apex 307-redirects to www), but the
codebase declared the **apex** as canonical in every signal that matters:

- `app/layout.tsx:41` — `metadataBase: new URL("https://ticketscan.io")` (resolves all canonical/OG URLs)
- `app/sitemap.ts:8` — `BASE_URL = 'https://ticketscan.io'` → **every sitemap entry was an apex URL that 307-redirects**
- `app/robots.ts:18` — `sitemap: 'https://ticketscan.io/sitemap.xml'`
- OG `url`, Organization `@id`/`url`/`logo`, and all `BreadcrumbList`/`ItemList` `@id`s

Submitting a sitemap composed entirely of redirecting URLs, and pointing
canonical/OG tags at a host that 307s, is a documented crawl-clarity and
indexing-signal problem. Google follows the redirect and indexes www, but the
mixed signals waste crawl budget and muddy canonicalization.

## 2. Technical Fix Applied This Run — canonical host → www

**Change:** swapped `https://ticketscan.io` → `https://www.ticketscan.io` across
**74 occurrences in 14 files** (mechanical string replace; social handles like
`@ticketscan_io`, `x.com/ticketscan_io`, `tiktok.com/@ticketscan_io` do **not**
contain the apex URL and were untouched — verified).

Critical files now correct:
- `app/layout.tsx:41` → `metadataBase: new URL("https://www.ticketscan.io")`
- `app/sitemap.ts:8` → `BASE_URL = 'https://www.ticketscan.io'`
- `app/robots.ts:18` → `sitemap: 'https://www.ticketscan.io/sitemap.xml'`

**Why www (not apex):** two independent sources of truth already agree on www —
(1) production serves www at 200 and 307-redirects apex→www, and (2) the only
pre-existing absolute links in the repo were human-written blog CTAs already
using `https://www.ticketscan.io/...` (`data/blog.ts:85,87`). Aligning to www
matches reality, is git-revertible, and changes **no** page a user sees.

**Verification:** apex refs in `web/src` now **0** (was 74); www refs **76**; no
malformed hosts (`grep "www.www"` → none); infra-file diffs are host-only.

> **Reversibility / the lever for the team:** if the team would rather make the
> **apex** canonical, the correct alternative is to flip the Vercel domain config
> to redirect **www → apex** (and revert this commit). Both achieve consistency;
> I chose the direction that matches the currently-live 200 host and needs no
> dashboard change. Flag if you prefer apex.
