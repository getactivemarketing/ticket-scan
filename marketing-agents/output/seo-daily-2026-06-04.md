## 2. Technical fixes applied this run

### Fix A — sitemap `lastmod` churn (`web/src/app/sitemap.ts`)
- **Before:** `const lastModified = new Date();` applied to every static, venue,
  city, category, and WC entry — so ~100 URLs reported `lastmod = today` on
  *every* crawl, which trains search engines to discount our `<lastmod>` signal.
  (Blog posts already used real `publishedAt/updatedAt` dates — left untouched.)
- **After:** replaced with a single stable `CONTENT_LAST_MODIFIED = new Date('2026-06-01')`
  constant + a comment to bump it when the venue/city/category/WC data sets are
  materially revised. The data files carry **no per-entity date field** (verified
  via grep), so a content-revision constant is the honest representation —
  per-URL real dates aren't available without adding date fields to the data.

### Fix B — breadcrumb pointing at a 404 (`web/src/app/tickets/[slug]/page.tsx`)
- **Before:** `BreadcrumbList` position-2 item = `https://www.ticketscan.io/tickets`
  for both city and category pages (lines ~209–211, 229). Live check confirms
  `/tickets` → **404**. A breadcrumb item referencing a non-existent URL is a
  structured-data quality defect on all ~37 ticket pages.
- **After:** collapsed to a valid 2-level crumb (`Home → {pageTitle}`), so the
  breadcrumb references only resolving URLs. Comment left to re-add the middle
  crumb once a real `/tickets` hub ships. Removed now-unused `breadcrumbSecondary`.
- **Note:** the **venue** page breadcrumb was checked and is fine — its
  position-2 points to `/tickets/{citySlug}` (a real 200 page), not the bare hub.
  (This corrects a slightly muddled claim in the 2026-06-02 report, which lumped
  both templates together.)

**Verification:** `npx tsc --noEmit` → **exit 0**. JSON-LD/metadata only; no
runtime logic touched. Not committed (git discipline — push only when asked).
