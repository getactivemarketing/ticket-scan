## 2. Technical fix applied this run

### Fix — missing `WebSite` node / dangling `#website` references (`web/src/app/layout.tsx`)
- **Found:** the root layout's JSON-LD defined only an `Organization` node
  (`#organization`, layout.tsx:71–84). There was **no `WebSite` node anywhere**.
  Meanwhile three pages reference one:
  - `src/app/page.tsx` (homepage)
  - `src/app/dashboard/layout.tsx` → `isPartOf: { @id: …/#website }`
  - `src/app/compare/layout.tsx` → `isPartOf: { @id: …/#website }`

  (Verified via `grep '#website' web/src` → 4 files: the 3 consumers + now the
  definition.) Each `isPartOf` pointed at a node that didn't exist — a
  structured-data quality defect (dangling `@id` cross-reference).
- **Fix:** converted `organizationJsonLd` into an `@graph` holding both the
  existing `Organization` node **and** a new `WebSite` node
  (`@id: …/#website`, with `url`, `name`, `description`, `publisher → #organization`,
  `inLanguage: en-US`). All three `isPartOf` references now resolve.
- **Deliberately omitted:** no `SearchAction` / Sitelinks Searchbox. Site search
  is **client-side only** — there is no `?q=` deep-link URL to target (verified:
  grep for `searchParams`/`?q=` in `dashboard/page.tsx` → no matches). Declaring a
  non-functional search target would be worse than declaring none.
- **Verification:** `npx tsc --noEmit` → **exit 0**. JSON-LD only; no runtime
  logic touched. Not committed (git discipline — push only when asked).
