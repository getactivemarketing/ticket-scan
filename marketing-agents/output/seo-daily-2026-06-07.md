## 2. Technical fix applied this run

### Fix — duplicate `WebSite` `#website` node on the homepage (`web/src/app/page.tsx:37`)

- **Found:** the homepage's `@graph` (`page.tsx:40–51`) defined a `WebSite` node
  with `@id: …/#website` — **the same `@id`** as the canonical `WebSite` node added
  to the root layout on 06-05 (`layout.tsx:91–99`). The root-layout JSON-LD renders
  on **every** page, so on the homepage two nodes claimed the same `@id`, and they
  **disagreed**:
  | field | homepage node (removed) | layout node (canonical, kept) |
  |---|---|---|
  | `name` | `TicketScan` | `Ticket Scan` |
  | `description` | "…multiple platforms…" | "…Ticketmaster, SeatGeek…" |
  | `SearchAction` | yes → `/dashboard?q={search_term_string}` | none |

  Two nodes sharing an `@id` is a structured-data conflict — Google merges or picks
  one unpredictably, and the conflicting `name`/`description` is exactly the kind of
  ambiguity that suppresses entity confidence.

- **`SearchAction` verified non-functional (the deeper issue).** The homepage node
  declared a Sitelinks Searchbox targeting `/dashboard?q={search_term_string}`. But
  `dashboard/page.tsx` is `'use client'` and initializes `keyword` to `''`, updated
  **only** from the form — it has **no `useSearchParams`, no `?q=` read** (verified:
  `grep 'searchParams\|?q=\|get(.q.)' dashboard/page.tsx` → **0 matches**). Landing
  on `/dashboard?q=lakers` runs no search. Declaring a search target the page ignores
  is worse than declaring none. (This confirms the 06-05 reasoning — site search is
  client-side only — and shows the homepage node had been silently contradicting it.)

- **Fix:** removed the duplicate `WebSite` node from the homepage `@graph`, leaving
  only the homepage's genuinely-unique `FAQPage` node. The homepage **still has a
  `WebSite` node** — the single canonical one inherited from the root layout. Net
  effect: exactly **one** `#website` definition site-wide, referenced via `isPartOf`
  by `dashboard/layout.tsx:59` and `compare/layout.tsx:59` (both verified as
  references, not redefinitions). Added a source comment explaining why the homepage
  must not redeclare it and why no `SearchAction` is declared.

- **Verification:**
  - `grep -rn '#website' web/src` → 1 definition (layout) + 2 `isPartOf` refs
    (dashboard, compare) + the new explanatory comment. No second definition.
  - `npx tsc --noEmit` → **exit 0**. JSON-LD only; no runtime logic touched.
  - Not committed (git discipline — push only when asked).

> **Correction to the 06-05 report (for the record):** 06-05 stated "no `WebSite`
> node existed anywhere." That was incomplete — the *homepage* already had one. The
> root-layout node was still correct to add (dashboard/compare `isPartOf` only
