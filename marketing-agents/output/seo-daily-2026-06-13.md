## 3. Task 3 — technical fix applied: venue pages now surface their events in schema

**File:** `web/src/app/venues/[slug]/page.tsx` (`:100–172`). **Typecheck:** `npx tsc --noEmit` → **exit 0**.

**What & why:** The venue page already fetches up to 10 upcoming events (with `minPrice`/`maxPrice`) from `/api/public/events` and renders them in the "Upcoming Events" section, but the JSON-LD `@graph` only ever contained the `Place` + `BreadcrumbList` — the event data was fetched and thrown away for SEO. I ported the **exact proven pattern** already live on `/tickets/[slug]`:
- A conditional `ItemList` (`#events`) node, added to the graph **only when `events.length > 0`** (mirrors the rendered section — no empty list).
- Each `Event` carries `name`, `startDate`, `eventStatus`, `eventAttendanceMode`, and `location` **referenced by `@id`** to the existing `#place` node (no address duplication).
- `offers` is a **null-safe** `AggregateOffer` — emitted only when `event.minPrice` exists (`highPrice` only when `maxPrice` exists). Honors the price-data reality (many events return null prices); never fabricates a figure.

**Why this is the right "highest-priority" fix today (not a no-op, not scope creep):**
- Venue detail pages are **already live** (`/venues/msg` → 200), so this ships on the *same* deploy as the blocked bundle — it does not depend on the index hubs and adds no new deploy gate.
- Pure **reuse** of an already-validated pattern + already-fetched data → low risk, typecheck-clean.
- Closes the long-carried open item *"Port tickets/[slug] ItemList/Event schema into venues/[slug]"* and is a concrete step toward SeatGeek's "venue page exposes its events + from-$X" parity.

**Deliberately left out of scope:** the venue **`<title>`/meta** "Tickets from $X" port (open item) — `generateMetadata` does not currently fetch events, so doing it cleanly is a larger change; kept separate to keep this fix tight and reviewable.
