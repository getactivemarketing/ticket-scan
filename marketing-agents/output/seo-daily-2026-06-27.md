- `maximumAttendeeCapacity` present. ✓
- Status: **PASS** — no schema errors.

**`/world-cup-2026/[stadium]` (StadiumOrArena + SportsEvent)** — PASS WITH ISSUES

- Two separate `<script type="application/ld+json">` blocks: one for `StadiumOrArena` with nested `SportsEvent`, one for `BreadcrumbList`. Technically valid but inconsistent with the `@graph` pattern used on venue pages.
- `priceCurrency` correctly localized (USD for USA, CAD for Canada, MXN for Mexico). ✓
- `lowPrice` is null-safe (omitted if no price pattern found). ✓
- `BreadcrumbList` breadcrumb is separate script block — works but could be unified.

**Issues on WC stadium pages:**

**Issue A (Medium):** `SportsEvent` node has no `image` property. Google's Event rich results documentation lists `image` as a required field for eligibility. All 16 stadium pages are affected. Without `image`, these pages are structurally valid but ineligible for the Event rich result feature in SERPs.

```typescript
// Add to stadiumJsonLd.event once stadium OG images are generated:
image: `https://www.ticketscan.io/og/world-cup-2026-${stadium}.jpg`,
// or use the generic fallback:
image: 'https://www.ticketscan.io/og/world-cup-2026.jpg',
```

**Issue B (Low):** `SportsEvent.location` is declared as `{ '@type': 'Place', name: venue.name }` — a new inline node rather than a cross-reference to the outer `StadiumOrArena`. More correct pattern:

```typescript
location: { '@id': `https://www.ticketscan.io/world-cup-2026/${stadium}#place` }
// (requires adding @id to the StadiumOrArena node first)
```

This inconsistency does not currently cause errors but misses the graph-linking benefit proven on venue pages.

## 3. Technical Fix Applied

### Fix 1: Remove login-gated pages from sitemap — FIXED
**File:** `web/src/app/sitemap.ts` lines 31–41 (removed)

**Problem:** `/dashboard` (priority 0.9) and `/compare` (priority 0.8) were included in `sitemap.xml` despite both redirecting anon visitors to `/login`. Googlebot fetched these high-priority URLs, encountered redirects, and could not index the content — wasting crawl budget on pages that return no indexable response.

**Fix:** Removed both entries from `staticPages`. Sitemap now drops from 109 → 99 entries, all of which are publicly accessible.

**Impact:** Crawl budget now fully allocated to 99 indexable pages. Google will no longer re-queue `/dashboard` and `/compare` on every crawl cycle.

**Note:** Un-gating `/compare` for anonymous visitors (known CRO P0) remains the ideal long-term fix. It would allow both pages to return to the sitemap with real indexable content — and convert organic visitors without requiring a login wall.
