## Technical Fix Applied Today

### Fix: BreadcrumbList on `/tickets/[slug]` — add `/tickets` hub as middle crumb
**File:** `web/src/app/tickets/[slug]/page.tsx`

**What changed:**

JSON-LD BreadcrumbList — before (2 items):
```json
[
  { "position": 1, "name": "Home", "item": "https://www.ticketscan.io" },
  { "position": 2, "name": "Orlando Events", "item": "https://www.ticketscan.io/tickets/orlando-events" }
]
```

JSON-LD BreadcrumbList — after (3 items):
```json
[
  { "position": 1, "name": "Home", "item": "https://www.ticketscan.io" },
  { "position": 2, "name": "Tickets", "item": "https://www.ticketscan.io/tickets" },
  { "position": 3, "name": "Orlando Events", "item": "https://www.ticketscan.io/tickets/orlando-events" }
]
```

Visual nav breadcrumb updated to match: `Home / Tickets / [City or Category]`

Stale code comment (referencing the `/tickets` hub as "not yet existing / 404") removed.

**Why this matters:**
- Google uses BreadcrumbList to understand site hierarchy and display breadcrumb paths in SERPs. A 2-item chain (Home → City) signals a flat site, making it harder for Googlebot to understand that `/tickets/[slug]` pages belong to a coherent `/tickets` section.
- The `/tickets` hub was confirmed live HTTP 200 in late June. Keeping the stale comment and truncated breadcrumb was sending wrong hierarchy signals to Google for all 37 city/category pages.
- With the 3-item chain, these 37 pages now correctly advertise their place in the sitemap hierarchy, which can improve SERP breadcrumb display and internal PageRank flow through the `/tickets` hub.

**Scope:** Affects all 37 `/tickets/[slug]` pages (24 city + 13 category).
